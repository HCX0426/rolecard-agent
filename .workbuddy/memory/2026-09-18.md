## 里程碑 C·§6.2 run_command 命令执行 + 审批交付

- **能力**：角色可在任务目录内执行 shell 命令（`core/tools/run.py` 的 `run_command`，
  内核工具 domain=None、`idempotent=False` 执行器绝不重试）。
- **审批状态机**（`core/approvals.py`）：`command_approval` 表 + `ApprovalService`。
  pending → approved（后台执行中）→ done（结果回填）；rejected 终态。**批准一次跑 N 遍
  被结构性禁止**：某命令一旦 done，工具同一命令只回放历史结果。
- **关键坑（Windows）**：`subprocess.run(timeout=)` 超时时只 kill 父进程 —— cmd/shell 派生
  的子进程会继续跑满整个命令（实测等满 30s）。改用 `Popen + communicate(timeout)` +
  `taskkill /F /T /PID`（树杀）/ POSIX `killpg`；超时后 returncode 是 1，需置 None 否则
  模型误读为"失败退出码"。
- **后台执行**：approve 这个 HTTP 请求必须快（前端 30s 超时）→ `run_approval_execution`
  在模块级 `_APPROVAL_EXECUTOR` 执行并回填；`scripts/run_api.py` 的退出路径
  `_shutdown_approval_executor()` 关闭（与 `_CHAT_POOL` 同生命周期）。
- **边界特意收敛**：cwd 必须落在任务目录内（`_resolve_within` 同 fs 工具）；输出 64KB 截断；
  `.venv-tasks/<目录名>` 的 Scripts/bin 自动前置进命令 PATH（独立 venv 支持）；审计
  detail 只有 command/exit_code/output_bytes/duration_ms —— **结构上没有 output 字段**。
- 配置：`RUN_TOOLS_ENABLED` 总闸 + `RUN_APPROVAL`（manual 默认 / auto 绿色通道），
  env 双源 + 「运行环境」页热切（FieldSpec 已加 choices 下拉）。
- API：`GET /api/approvals?status=`（含 pending 计数）+ `POST /api/approvals/{id}/decide`；
  审批写 operator 审计、执行写 agent 审计。前端：侧栏「命令审批」+ 红点（10s 静默轮询）
  + 抽屉（仿 ReachoutPanel，w-80 右侧面板）。
- 测试：test_approvals / test_run_command / test_approvals_api / ApprovalPanel.test.tsx；
  **覆盖率 88.01%（≥85）、ruff 0、mypy 0、consistency 24 全过、smoke 14/14、前端 68 过**。
