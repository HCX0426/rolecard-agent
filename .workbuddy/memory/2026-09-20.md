## 坑：同文件批量 Edit 静默丢改（本轮踩到，记下来防复发）

- 一次性对**同一文件**发多个 `Edit` 调用，部分 edit 返回 success 但实际未生效（多行 edit 与部分单行 edit 都中招，
  规律不固定：import 行、带属性前缀的 `<div`（`mt-3` / `key=`）最易丢）。暴露方式是 grep 发现 `<Card` 数少于预期、
  tsc 报 `Cannot find name 'Card'`。
- 对策：卡片 opening 这类机械替换改用**确定性 Python 脚本**（`scripts/_migrate_cards.py` 一次性）而非批量 Edit；
  闭合标签用深度匹配脚本 `_fix_card_close.py`（已修成幂等：显式处理 `</Card>`，可重复跑）。两者跑完即删。
- 教训：同文件多 edit 不可信，改完必须用 Python 统计 `<Card`/`<div` 开闭数 + tsc 复核，别只看 tool 回显。
- 附加：深度匹配脚本 v1 不处理 `</Card>`，在"半转换"文件上重跑会把 depth 算偏（pending_left=6 depth=7）；
  v2 加了 `close_card` 分支后幂等。

## 对标 AstrBot + 桌宠方向讨论（本轮，用户提问）

- 用户问 rolecard-agent 与 **AstrBot**（确认是 AstrBotDevs/AstrBot，非 ASR bot / TEAM SPY 转发 bot）的区别，并质疑"项目是否只适合学习"。
- 关键澄清：**本项目已有 Electron 桌宠壳（`shell/`，`docs/开发流程.md` "桌宠壳怎么跑"）+ 前端 `pages/PetPage.tsx` + 本地 Ollama 起停（D③-b），架构审计 §10 的 D②「桌宠全系列」已落地**。用户对自己项目已有桌宠形态不清楚。
- AstrBot 生态桌宠方案有三：① `Astrbot-desktop-assistant`（悬浮球 + Q版"桃桃"桌宠 + Live2D 看板娘，桌面感知/主动对话，最贴近桌宠）；② `astrbot-live2d-desktop`（独立 Live2D 桌面端）；③ `astrbot_plugin_live2d_pet`（Live2D 桌宠插件，依赖 Live2DViewerEX）。
- 对比结论：本项目 vs AstrBot 在桌宠维度是**同类雏形**而非"有无"差距——本项目的"脑"（角色卡内核+域插件+RAG）自己写了，缺的是成熟"皮"（live2d 动画/悬浮球/桌面感知生态）；AstrBot 反之。许可证：AstrBot AGPL-3.0（营利性网络服务须开源），本项目 MIT。
- AstrBot 开箱即用（IM 18+、插件 1000+、一键部署），但作为"可定制 Agent 内核"灵活度不如本项目。
