## 用户气泡单行修复（截图复现 → 探针定位 → 扁平化重构）

- 现象："我对话发了我1111111111111111111" 在气泡里断成两行（明明有空间）。
- 定位（playwright 探 computed style）：用户气泡被**双层 max-w-[80%] 包装**（外层编辑
  包装 + 内层铅笔横排）有效宽度 64%，且铅笔 opacity-0 恒占 28px——气泡被压到 233px
  < 236px 单行宽。方法：probe 脚本输出整条祖先链的 display/width/white-space。
- 修复：分支扁平化——铅笔 absolute -left-9 悬浮（不占布局），气泡直接做 flex 项；
  编辑态包装 w-full max-w-[80%]。实测单行 ✓。

  （已修+测试锁）。**教训：JSX 重构后先跑 frontend 测试再截图；嵌套百分比包装是宽度

## 气泡宽度最终形态：w-fit 自适应 + 80% 上限

- 用户反馈 w-full 矫枉过正（气泡恒 80% 定宽）。最终：包装层 `max-w-[80%]`（编辑态才
  w-full）+ 气泡 `w-fit` —— 短消息贴内容、超上限才换行（WorkBuddy 式）。截图验证：
  长数字串单行不断、短消息"我是没"小气泡、Markdown 列表渲染 ✓。
- **气泡宽度三层教训**：双层 max-w 百分比嵌套挤压 → w-full 定宽矫枉过正 → 正解 =
  单层上限 + w-fit 内容自适应。flex 项默认 shrink 行为 + 隐形占位元素（opacity-0）
  是宽度问题的两大嫌疑。
