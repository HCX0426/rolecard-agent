## 一、现状审计（为什么要做）

- **Tailwind CSS v4**（`@import "tailwindcss"`，无 config 文件）—— 深色模式必须用 v4 的
  `@custom-variant dark (&:where(.dark, .dark *))` 写法，不能用 v3 的 `darkMode: "class"`。
- **样式重复规模**（跨 6 个页面 + 组件）：`bg-white` ×38、`border-slate-200` ×64、
  `text-slate-400` ×56、`rounded-lg` ×49、`px-4 py-2.5` ×16 —— 同一套"卡片/按钮/标签"的
  类名在每页手写一遍，改一次主题要动 6 个文件。
- **无响应式**：App 外壳 `w-52` 导航 + ChatPage `w-64` 会话栏都是固定宽，窄屏直接挤爆。
- **无深色模式**：所有表面都是硬编码浅色。
- **单 bundle**：206KB JS 全量加载，6 个页面没有分包。
- **唯一组件**：`components/Toast.tsx` —— 组件库从它开始。

## 二、目标架构

```
src/
  api.ts                  # 唯一数据出口（不动）
  main.tsx
  index.css               # Tailwind v4 + 语义化组件类 + dark variant
  components/
    Toast.tsx             # （已有）toast
    ui/
      Button.tsx          # variant: primary/outline/ghost/danger · size: sm/md
      Card.tsx            # 面板：可选标题 + 右侧动作区
      Tag.tsx             # tone: green/amber/red/blue/slate
      Switch.tsx          # role="switch" 开关（插件启停用）
      index.ts            # barrel
  pages/                  # 业务编排（逐步迁移到 ui/ 组件）
    ChatPage / DataPage / KnowledgePage / RolesPage / PluginsPage / SettingsPage
```

**原则**：`components/ui/` 只做展示、零业务；页面负责编排。迁移是**渐进**的 —— 新代码必须用
ui/，旧代码按页面逐步换（本轮完成 DataPage 全量 + PluginsPage 开关，其余页面类名经深色脚本
统一处理，不阻塞）。

## 三、深色模式（Tailwind v4 写法）

1. `index.css` 声明 class 策略：`@custom-variant dark (&:where(.dark, .dark *));`
2. `useTheme`：`localStorage("theme")` + `document.documentElement.classList.toggle("dark")`，
   初始跟随 `prefers-color-scheme`。开关放侧栏底部（太阳/月亮 SVG）。
3. **落地方式是脚本而非逐行手改**：跨 `src/**/*.tsx` 把高频浅色类批量追加 `dark:` 变体
   （映射表固定：`bg-white→dark:bg-slate-800`、`border-slate-200→dark:border-slate-700`、
   `text-slate-900→dark:text-slate-100`、`text-slate-400→dark:text-slate-500`、
   各语义色软底 `bg-blue-50→dark:bg-blue-900/30` 等）。脚本用 **二进制写、保 LF**（踩过
   `write_text` 在 Windows 转 CRLF 的坑）。
4. `index.css` 的 body 同步：`dark:bg-slate-900 dark:text-slate-100`。

> 为什么不用 CSS 变量重写全部颜色：v4 的 `dark:` 变体 + 批量脚本改动小、可回滚、
> 不引入第二套颜色事实来源；语义化组件类只沉淀**最高频**的几个，避免过度抽象。

## 四、响应式（移动优先的降级）

| 位置 | 桌面（≥768px） | 移动（<768px） |
| --- | --- | --- |
| App 导航 `w-52` | 常驻左栏 | **off-canvas 抽屉**（`max-md:fixed` + 汉堡按钮 + 遮罩） |
| ChatPage 会话栏 `w-64` | 常驻左栏 | **off-canvas 抽屉**（页头「会话」按钮唤出） |
| 页面留白 | `p-6` | `p-4 md:p-6` |
| 表格 | 正常 | 外层 `overflow-x-auto`（DataPage / 审计） |

两个抽屉共用同一模式：`max-md:fixed max-md:inset-y-0 max-md:z-40` + `translate-x` 切换 + 遮罩，
选中后自动关闭。

## 五、性能优化

- **路由级代码分割**：6 个页面全部 `React.lazy` + `<Suspense>`（当前 206KB 单包 → 分包，
  首屏只加载对话页）。
- 其余保持既有做法：`useMemo`（后端分组）、checkpoint 回放作为唯一真相、api.ts 单出口。
