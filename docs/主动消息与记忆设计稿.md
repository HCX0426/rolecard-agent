## 0. 现在有什么（避免重复造）

| 能力 | 现状 | 缺口 |
|---|---|---|
| 主动消息列表 | 收件箱一行一条（`GET /api/reachouts`），红点=未读数；桌宠气泡只显示最新一条、其余折成 `+N` | **列表不分天**：一天开口 5 次就是 5 行，历史一多就糊成流水账 |

## 1. 收件箱按「角色 × 时间桶」折叠 + 角标

**决策点 A：合并窗口放 1/3/7 天三档，不做连续滑块。**

- 分组键 = `(role_id, 本地日期桶)`；桶宽由新配置 `REACHOUT_MERGE_DAYS`（默认 1）决定。
- 一行显示成：`角色名 · 今天/日期区间` + **该角色在该桶内最新一条的摘要** + 右上角**未读数角标**；
  展开后是该桶内的逐条（时间 + 内容），点任意一条都进同一个主动会话，并把**整摞**标已读
  （复用已有的 `read-by-role`，不新增端点）。
- 桌宠气泡不变（已经只显示最新 + `+N`）。

**实现位置刻意选在前端**：分组纯展示，`created_at` 已经在响应里 → **后端零改动**，只多一个配置项。
理由：把折叠做进后端会立刻产生"第二份分组逻辑"（前端展示与接口聚合各算一遍），
而这条规则唯一的服务对象就是界面。

- `REACHOUT_MERGE_DAYS` 进 `RUNTIME_FIELDS`：五处契约同步（Settings / from_env / FieldSpec /
  运行环境分组 / `.env.example`），可写入口单一放在「记忆与任务目录」帖（与主动开口总闸同帖），
  运行环境页只读展示 —— 沿用批次 5 已经定的那套口径。
- 顺手把 `REACHOUT_INTERVAL_MINUTES` 也纳入运行环境页（现在只能改 env，排查时不能把间隔调小复现）。

## 2. 主动消息「提取精华」进记忆

**决策点 B：触发选「会话结束 + 每 N 轮兜底」，不做 per-message；并给一个手动按钮。**

市面做法高度一致（SillyTavern 每 N 条滚动摘要、ChatGPT/Claude 后台 reflection、星野「事件簿」事件级摘要）。
per-message 提取被明确回避：一次提取=一次模型调用，本地 8GB 卡上按消息数放大就是不可用的成本。

- 触发：① 会话内累计满 N 轮（默认 12）；② 手动「提取精华」（对话页一个按钮，走同一条路）；
  ③ **不**做定时全库夜间整理（见 §4）。
- 产物是**条目**而不是整段重写：每条一句话事实，带来源（`proactive` / `chat` / `manual`）。
- 提取用的模型走该角色当前后端；失败只留日志，绝不影响对话与开口。
- 成本可见化：提取那一次调用的 token 数写进审计，让"记忆变聪明花多少钱"是可查的。

## 2.5 主动开口时到底注入了什么（2026-09-20 实测，这一节是回答"注入的内容合适吗"）

`generate_reachout_text`（`core/reachout.py:282-321`）的 prompt 只有两条消息：

| 进了 prompt 的 | 没进的 |
|---|---|
| 人设（实测 elysia 359 字）+ 范例 3 条 + `memory_for_turn` 取到的记忆 + 三种口吻之一的任务指令；然后单轮 `invoke` → guard → 截 2000 字 | **任何"最近性"**：不看该角色的主动会话历史，也不看它自己上次主动说过什么；不看时间之外的上下文 |

实测出的三个问题（都有数据支撑，不是推测）：

1. **记忆槽是空的**：`role_memory` 只有 `general_assistant`（长度 0），elysia 没有行；全局 `memory:facts` 那行压根不存在。
   于是任务指令"结合关于用户的长期记忆"指向一个空串 —— 模型只能凭人设编，这正与
   「人设只解读不捏造」那条不变式对冲。（这条不是 bug 而是数据现状，但指令该诚实：
   **记忆为空时不再说"结合长期记忆"**，改成"凭你对他的了解自然说一句"。）
2. **重复开口**：今天 09:00 / 10:00 / 11:00 / 12:00 四条几乎同义（花海、阳光、亮晶晶）。原因不是模型差，
   是上下文里没有"我刚说过这些"。
   → **E1 注入该角色最近 K 条主动消息原文**（默认 5，一行 SQL），并明写"这些你最近说过，
   别重复同样的话和同样的由头"。零额外调用，多 200–400 token。
3. **recall 档有口无食**：`trigger_recall` 只回答"这角色有没有专属记忆"，命中就要求模型
   "提起一件之前聊过或答应的事" —— 但**没把是哪件事给它**，结构上就在邀请它编一个具体细节。
   对比 `file_event` 档就做对了：给文件名清单 + 明写"不得编造文件内容"。
   → **E2 recall 改成带素材**：从条目化后的 active 记忆里挑一条当由头，明写"只说这一条，
   不要补别的细节"；**挑不出素材就不要走 recall 档**（现在是"有 blob 就走"）。
   这也是 §2/§3 那条"记忆条目化"真正的落点 —— 条目不是为了好看，是为了能被引用与被去重。

> 顺带要改的文档口径：架构总览 §3 写着"角色也记得自己主动说过什么" —— 那一句只对
> **下一次对话**成立（消息落进了主动会话），对**下一次主动开口**不成立。两条路不对称，
> 做完 E1 才真正两边都成立。

## 3. 记忆的退役机制（你点名要的那块）

**决策点 C：失效不删 + 近因加权 + 条数上限，参数一律不暴露到界面。**

调研结论很一致：**没有一家在 UI 上暴露衰减参数**，但都暴露"逐条查看/编辑/删除/钉住"
（ChatGPT、Claude、星野事件簿都是这个形态）；工程侧的成熟做法是**标记失效而非物理删除**
（Zep/Graphiti 的 `valid_at/invalid_at`、Mem0 的 decay + `expiration_date`），因为可撤销、可调试。

落到我们这里，最小形态是给 `role_memory` 换成一张条目表（保留 blob 作为"渲染视图"，注入规则不变）：

| 列 | 作用 |
|---|---|
| `text` | 一条事实（一句话） |
| `source` | `proactive` / `chat` / `manual` / `seed` |
| `pinned` | 钉住 = 不参与淘汰，也不被覆盖 |
| `hit_count` / `last_hit_at` | 被注入过就记一次（近因与频次的依据，一行 SQL 的乘子） |
| `invalidated_at` / `superseded_by` | 失效不删；被更新的事实指向新版 |
| `created_at` | 排序与桶计算 |

- **淘汰前先整理**（用户 2026-09-20 指出"超上限不该直接删，先看能不能合并"，是对的）：
  触到 active 上限时**先跑一次整理（consolidation）**，而不是立刻失效最弱的那条：
  1. 让模型对这摞条目做一次 `MERGE / KEEP / INVALID` 判定（同义的多条合成一条、被新事实
     取代的转 `invalidated_at` 并写 `superseded_by`）；
  2. **整理后仍超限**才按 近因×频次 从最弱的开始转 `invalidated_at`；
  3. 整理只在超过阈值时跑（不是每次写入），且**可手动触发**（记忆卡上一个「整理记忆」按钮）——
     它是一次模型调用，让用户决定什么时候花这个钱；
  4. 整理是**幂等且可回滚**的：只写 `invalidated_at` / `superseded_by`，不物理删任何行，
     所以"整理坏了"最坏是回滚一个标记，而不是丢记忆。
- **注入**：只取 active，按 近因×频次 排序，装进 `MAX_MEMORY_CHARS` 能容的部分。
- **合并写入**：提取新条目时先做 `ADD / UPDATE / NOOP` 三态判定（Mem0 的形状）——
  UPDATE 就是写 `superseded_by`，而不是让两句矛盾的话一起留在库里。
- **隐私出口**：导出/分享角色卡时 **真删**记忆行（只带 pinned+active 且需显式勾选）。
  这条是我们与托管产品的关键差异：他们没有"把另一个人的隐私焊进文件里"的问题，我们有。
- 用户控制：记忆卡从 textarea 换成**逐条列表**（编辑/删除/钉住/「提取精华」/「整理记忆」），
  仍保留"原文视图"折叠展开，便于你直接看注入进去长什么样。

## 4. 明确不做

- 知识图谱 / 实体关系抽取（Graphiti 那套）——单用户本地场景收益不抵复杂度。
- 夜间全库反思重写（Letta sleep-time agent）——一次全库重写就是几百次调用，本地卡上不成立。
- user / agent / run 三层作用域（Mem0）——我们的 per-role 硬隔离已经天然是那个形状。
- LRU 容量淘汰 —— 条数上限比 LRU 可解释，也更好演示。
- "用户没回则抑制下一封"——我们的未读堆积上限已经在做同一件事，不叠加第二套。

> 严格行协议（提取 `ADD/UPDATE/NOOP`、整理 `MERGE/INVALID`），要点与偏离：
> 1. **`UPDATE` 不就地改文本**：新增一条 + 把旧那条 `invalidate_item(superseded_by=新)` ——
>    "它什么时候开始搞错"的那条版本链是审计唯一的证据，也是"整理坏了能回滚"的前提；
> 2. **看不懂的行忽略并计数**（`skipped`），绝不猜它想说什么；**pinned 条目碰不得**：模型对
>    它输出任何一条指令，那条指令整条作废（宁可不合并，也不把用户钉住的事进一次模型改写）；
> 3. 自动兜底的节奏按**游标**而不是墙钟：`session_thread.distilled_at_seq` 存"上次提取时的
>    消息条数"，攒够 `MEMORY_EXTRACT_TURNS` 轮（= 2N 条）才再提一次；`0` = 只留手动按钮。
>    它跑在 **SSE 响应已经流完之后的后台线程**里，失败只写 trace —— 提取可以坏，对话不能变慢；
> 4. **提取用的模型走这一会话自己在用的那个**（会话覆盖 > 角色覆盖 > 默认）：换到一个更弱的
>    模型上去抽事实，症状是"记忆悄悄变笨了"，而没人会怀疑到提取这一步；
> 5. 成本可见化：模型报了 usage 就把 token 数带进审计与界面提示，**没报就是空**（不编一个数）；
>    审计只记结构与条数，**绝不记提取出来的内容**（那条由单测钉住：审计里搜不到记忆文本）；
> 6. 一处与稿子 §3 不同的界面决定：**「提取精华」放在对话页头部**，不放记忆卡 —— 它的输入是
>    *这段对话*；记忆卡上那个按钮做的是另一件事（输入是已有条目）。两个按钮各自只需要自己那份
>    输入，不互相冒充。写进的是**该会话所属角色**的桶（对话是跟它说的，回忆以后也只在该角色的
>    注入里出现）。
> 7. 整理一次最多看 60 条（按注入序），超出留下次 —— 一次调用要装进小上下文模型的窗口。
> 8. 一处与 §3 决策点 C 的**有意例外**：那句"参数一律不暴露到界面"说的是**衰减与上限**
>    （近因半衰期、每桶条数）—— 那些调好了不该让人碰，调错才会让记忆变笨。但**提取节奏**不是
>    同一类：它决定"什么时候多发一次模型调用"，是本地卡上一个会自己发生的开销。市面也一致
>    （SillyTavern 的 summarize 就是"每 N 条"一个输入框）。所以记忆卡上给了一个下拉
>    （关闭 / 6 / 12 / 24 轮），"关闭"只关总闸、**保留节奏值**，重新打开还是原来那一档。

## 6. 事件簿：把"和这个角色有关的事"按时间摊开（2026-09-21 提案，**待拍板**）

**动机**：§2/§3 做完之后，系统里第一次同时躺着三类带时间的东西 —— 它主动找过你什么
（`agent_reachout`）、它哪天记下/更正了关于你的哪条事实（`role_memory_item`）、你们什么时候
开过哪些会话（`session_thread`）。它们各自都有界面（收件箱 / 记忆卡 / 会话列表），但**没有一处
能按时间把三条并起来看**，而"我记得它知道我搬过家"这种感受恰恰是时间线给的。星野的「事件簿」
是同一个诉求，只是它是托管产品、事件由平台生成。

**核心约束：不新建事件表。** 时间线是这三张已有表的**只读派生视图** —— 新增一张 `event` 表
就是制造第二份事实，而"两处真相"是本轮审计反复在删的东西（backends 投影、`role_memory` blob、
`content`/`items` 同源都属这一族）。

### 6.1 读侧合同

`GET /api/roles/{role_id}/timeline?limit=50&before=<游标>&kinds=reachout,memory,thread`
→ `{ items: [{ kind, at, text, from_text?, thread_id? }], next_cursor }`

| 事件种类 | 来源行 | 显示成 |
|---|---|---|
| `reachout` | `agent_reachout` 一条 | 它主动说：<原文>（可点 → 跳进那条主动会话，复用收件箱的 `onOpenThread`） |
| `memory` | `role_memory_item.created_at` | 记下：<事实> |
| `memory_correct` | 同表的 `invalidated_at` + `superseded_by` | 更正：<新事实>，下面一行划掉旧的那条 |
| `thread` | `session_thread.created_at` / `updated_at` | 开始聊 / 最近聊：<标题>（锚点，**不**逐条列消息） |

- **排序**：`at` 倒序；同一时刻按 `kind` 稳定序，避免翻页时同秒事件跳位。
- **游标**：`(at, kind, 主键)` 三元组编码成一个不透明串（与 `/api/audit` 的 `before_id` 同一目的：
  不靠 `OFFSET` 深分页）。
- **时间口径**：三张表都是 `CURRENT_TIMESTAMP`（UTC），分桶文案直接复用收件箱那套"今天/昨天/日期"
  —— 那里已经踩过一次时区，不重新踩。
- **分级**：`/api/roles` 前缀已在 `USER_ROUTES`，纯读、不写审计（读了什么不该进操作流水）。

```
┌ 爱莉希雅 · 事件簿                        只看 ▾ ┐
│ 今天                                             │
│  ● 20:14 主动  刚路过琴房，想起你说周三要练琴。 → │
│  ● 18:02 记忆  更正：用户下周搬到杭州居住         │
│              ┄ 用户住在上海（已作废）             │
│ 昨天                                             │
│  ● 21:31 对话  开始聊：腰疼怎么缓解           →   │
│  ● 09:12 记忆  记下：用户每周三晚上练琴           │
│                                    加载更多 ↓     │
└──────────────────────────────────────────────────┘
```

- 左侧一条细竖线 + 圆点，种类用**小徽章**上色（主动=蓝 / 记忆=绿 / 更正=琥珀 / 对话=灰）；
  徽章是说明不是控件 —— 不做点击筛选（筛选只有一个下拉，见下）。
- 「更正」那条把旧文本划掉显示：这是 §3「失效不删」第一次**被用户看见**的地方 —— 之前它只是
  数据库里一列 `invalidated_at`，价值只在回滚与调试里。
- 顶部一个下拉筛选（全部 / 只看它主动说的 / 只看它记下的）：**一个控件而不是四个开关**，
  因为"对话"锚点单独看没有意义。
- 空态写清路径：「还没有关于它的事 —— 聊几句，或在角色卡上让它主动找你」。
- **只读**：编辑/钉住/删除的唯一写点仍在记忆卡（§3 那条"一个设置只有一个写点"）。

### 6.3 明确不做

- **逐条聊天消息进轴**：按角色扫 checkpoint 既贵（每会话一次全量反序列化）又是把"对话全文"
  复制进另一个视图 —— 那里已经有对话页了。
- **把 `audit_log` 的计数混进来**（"提取了 2 条、整理 1 次"）：没有内容的计数在"我和它的故事"
  里是噪音；那些数字属于记忆卡的成本可见化，不属于这条轴。
- **导出/分享时间线**：§3 那条隐私出口已经定了规矩（导出角色卡只带 pinned+active 且要显式勾选），
  时间线把 per-role 记忆与主动消息原文摊在一起，导出它等于绕开那条规矩。

### 6.4 代价（诚实）

- 记忆条目的 `created_at` 是**被记下的时间**，不是事情发生的时间。所以轴上的措辞只能是
  "它哪天记下/更正了什么" —— 写成"你搬来杭州"就是骗人。这条约束决定了上面那张表的动词。
- 三类源没有共同主键，跨源游标必须自己编码；分页边界（同秒多条）要一条用例钉住。
- 工作量：后端一个只读聚合端点 + 一个抽屉组件 + 两端用例。不动任何写路径。

## 7. 桌宠悬停对话：不进控制台就能回话（2026-09-21 提案，**待拍板**）

**诉求**（用户原话）：鼠标悬停时把历史消息和输入框弹在桌宠旁边，"这样不用进界面都能对话"。
现在的形状是：桌宠 219×259、只有一张色片 + 一条会淡出的气泡，点气泡 = 让壳把**控制台**拉到前台
—— 想回一句话得开一扇大窗，这跟"抬眼就能看到"的驻留件定位是拧着的。

### 7.1 参考项目对照（2026-09-21 查的，四条直接影响判断）

| 项目 | 它怎么做 | 我们取什么 |
|---|---|---|
| **Cherry Studio**（Electron，开源）划词助手 / 浮动窗 | 一条浮动条 + 点按钮开各自的结果面板；设置项是**自动关闭 / 自动置顶 / 透明度 / 紧凑模式 / 记住大小**；它是**独立工具**，不跟主聊天共享上下文；"点了下面屏幕区域就自动隐藏" | 那套**设置词汇**照搬（用户认得）；"独立工具"正是"和控制台互不干扰"的现成先例 |
| **Open-LLM-VTuber**（Electron + Live2D）桌宠模式 | 透明 + 全局置顶 + **鼠标穿透**；但**输入与历史在网页 UI 那一侧**，overlay 只画角色和气泡 | 反面参照：它没有"悬停就能打字"，我们要的正是这一步 |
| Electron 悬浮球实现（掘金 7460779695833333811） | 展开/收起**在同一扇窗里用 CSS 做**（不调 `setBounds`、不开第二扇窗）；并明确说 `-webkit-app-region: drag` 与点击事件冲突，所以他们改成 JS 手动拖 + IPC 定位 | 我们**已经有能用的 `app-region: drag`**（桌宠气泡的 `pet-nodrag` 证明可共存）⇒ 不为它推翻现有拖拽 |
| AI 桌宠实战（CSDN 95244841） | 点出这个坑：**"透明区域虽然看起来透明，但鼠标交互范围仍然是一整块矩形，容易挡住用户点击其他程序"**，作者的做法是**把窗口尺寸贴合成角色大小** | 我们现在 219×259 就是贴合的形状 ⇒ **收起态不挡桌面**这条必须保住 |

⇒ 结论：**收起态维持小窗，悬停时向壳要一次 `setBounds` 长大**。比"常驻大窗 +
`setIgnoreMouseEvents(forward)`"少动一处系统级行为 —— 穿透开关是全局的，哪条路径忘了关回来，
桌宠就再也点不动；而改窗口状态的路径我们已经有三处（托盘显隐、位置记忆、单实例）。

### 7.2 四条要拍板的判断

1. **一扇窗长出来，不加第三扇窗。** 悬停时 219×259 → 约 380×520，面板画在同一份 `frontend/dist`
   里。再加一扇 popover 窗意味着：跟随定位、拖拽同步、失焦隐藏、托盘/退出/单实例每条路径都要
   多管一扇 —— 而"不为壳重写 UI、不在壳里存第二份界面"是里程碑 D 的立身之本。
   **代价要说清**：只在展开期间，那块矩形挡住它下方的桌面点击，鼠标离开即恢复。
2. **桌宠的会话是它自己的一条，与控制台的"新建对话"互不干扰**（用户 2026-09-21 明确要的）——
   这一条**推翻**本稿最初"复用该角色主动会话"的提案。三选一见 §7.2.1。
3. **流式复用 `streamChat`；收起不打断正在跑的那一轮。** 面板用对话页同一套 SSE 归约
   （`lib/stream.ts`），不写第二份。鼠标离开自动收起时**不 abort** —— "我话刚问完它还没答，
   挪开鼠标就没了"是不可接受的；只有面板里那个「停止」按钮才 abort。
4. **给三个开关**（词汇照 Cherry Studio）：自动置顶 / 透明度 / **显示消息内容**（默认开）。
   最后一条的理由不是省屏幕：桌宠常驻置顶、透明、不跟主窗一起收起，别人站在你屏幕后面就能
   读到你们聊了什么。关掉后展开只给"有 N 条新消息" + 输入框。

#### 7.2.1 会话归属：三选一

| | 线程 | 得到 | 失去 |
|---|---|---|---|
| (a) 复用主动会话 | `s_proactive_<role>` | 你回的就是它主动说的那句，上下文天然连续；不新增概念 | 桌宠的闲聊混进"它主动找你"那条历史，也混进控制台的会话列表 |
| **(b) 桌宠专属一条**（推荐） | `s_pet_<role>`（幂等 ensure，固定一条） | 与控制台**互不干扰**：桌宠永不新建会话、不占会话列表的新位置；想接着聊可以在控制台打开同一条 | 角色下次**主动开口**读的是它自己的主动会话，看不到这条 ⇒ 两边历史分叉 |
| (c) 每次展开新建一条 | 随机 id | 像 Spotlight，零负担 | 历史碎成几十条，第二天找不着 —— 与"记忆"这条主线相反 |

推荐 **(b)**，代价就是"历史分叉"：要不分叉，得让主动开口的生成侧也读桌宠那条（那是
`memory_for_turn` 之外的另一处注入口径，得单独拍）。
**后端要补一个幂等端点**：`POST /api/session/pet {role_id}` → 确保那条会话存在并返回 `thread_id`
（照 `bootstrap.deliver_proactive` 里那段 `ON CONFLICT DO NOTHING` 写，**不跑图、不写消息**）。

### 7.3 界面

```
      ┌ 爱莉希雅 ▾ ─────── 在控制台打开 ✕ ┐
      │ 它：刚路过琴房，想起你说周三练琴   │  ← 最近 6 条，面板内滚动
      │ 你：周三晚上，可能吧               │
      │ 它：那我把琴房那段记下来？         │
      │ ──────────────────────────────────  │
      │ [ 说点什么…                  ] 发送 │  ← Enter 发 / Shift+Enter 换行
      └─────────────────────────────────────┘
                        ██
                      ( 莉 )      ← 色片：悬停展开，拖它=挪桌宠
```

- 面板出现在色片**上方偏右**；越界时翻到左侧或下方（与窗口位置记忆那套"夹回当前工作区"同一逻辑）。
- 鼠标离开色片与面板 → **400ms 后**收起：留一段"游过去"的宽限，否则输入框永远点不到。
- 顶部角色名带 ▾：多角色可切换，默认 = 最近主动找过你的那个（就是现在气泡里那条的角色）。
- **只在输入框被点时**才抢键盘焦点（桌宠平时 `showInactive`，不该抢你正在打字的窗口）。

### 7.4 先要实测的三件（都在这台机器上，不靠猜）

1. `showInactive` 的无边框窗点进去能不能拿到键盘焦点（Chromium 一般会；不行就展开时 `win.focus()` 一次）。
2. 展开区挡住桌面点击的实际范围与收起判据是否可靠（`mouseleave` + 宽限）。
3. 拖拽用的 `-webkit-app-region: drag` 与"输入框可选字/可粘贴"共存（气泡的 `pet-nodrag` 已经证明标记法可行，
   但输入框是原生焦点控件，得真点一次）。

### 7.5 分期与代价

① 后端 ensure 端点（不依赖拍板，可先做）→ ② 展开/收起 + 只读历史 → ③ 输入框 + 流式 + 托盘总闸。
不动任何写路径、不动控制台；新增的是桌宠页一个面板、壳一处 resize IPC、托盘一项，两端各带用例。
