- ⚠️ 连带的产品后果：**181 MB 安装包（`67b7e33` 那次构建）里那份 dist 也是旧的** —— 源码与

`current_role_id_ctx` / `role_knowledge_scopes_ctx` / `turn_image_ctx` 是 §5 那条"欠设计·暂缓"的
三元组。真去合成一个的代价比想象大：三者读侧在不同模块（`memory.py` 读角色、`nodes.py` 读作用域
与图片），合并必须先搬进一个两边都能 import 的叶子模块（否则 memory→nodes 成环），而且**测试会退化**
—— 现在每条用例只 `set` 自己那一维，合并后要为改一维构造整个快照。**真正的风险从来不是"有三个"，
而是"改了两个、忘第三个"**（不会有编译错误，症状只是某条工具静默降级），而三者的写入点本来就集中在
`execute_tools` 开头一段。所以做的是机制而不是重构：`test_one_turn_writes_all_three_injected_scopes_together`
钉住"同一轮把三维一起注入、且在工具自己的线程里看得见、换一轮一个都不许留"。
**验过它能红**：临时注掉 `turn_image_ctx.set(...)` 后该用例失败（拿到 `None`），随后恢复。

### 10.15 P0-3 第二步：审批的一次性决定令牌（2026-09-20）
P0-3 里"任何人可自批"其实是两个不同的洞，分开堵才有意义：**"猜一个自增 id 就批准"**今天就能堵，
不需要 authz 模型；**"别人的凭证能批你的命令"**才需要角色（第三步）。这里做的是前者。

机制：`submit` 时生成 `decide_token`（`secrets.token_urlsafe(24)`），随 pending 行从读侧下发，
`decide(id, decision, *, token)` 用 `hmac.compare_digest` 比对，**决定后清空**，并带 30 分钟 TTL。

- **为什么 403 不是 401**：缺口不是"没登录"（单机形态本来就不登录，用户明确"一个人用不配登录"），
  而是"没持有这条待批下发的凭据"。身份可以匿名，凭据不行。
- **真实收益说清楚（也包括它防不住什么）**：挡得住本机任意进程/脚本盲 POST 审批端点，
  **尤其挡得住浏览器里一段跨源 JS**（同源策略让它读不到 `/api/approvals` 的响应，于是拿不到令牌）
  —— 这是一条不依赖任何配置的安全增益。它**防不住**"已经能全量读你 8000 的本地恶意程序"：
  同一信任域内读到就等于拿到，那种情况该由"不给自己没在跑的进程开公网"和回环边界负责，
  不是靠一个字段能救的。这条边界写在这里，是为了不让后来人误以为令牌=鉴权。
- **为什么要 TTL**：没有上限等于一次读取买断一条命令的批准权（面板开着过夜，期间任何一次带
  该令牌的 POST 都能批）。30 分钟的语义是"回来还能批，隔天得重新看一眼"。
- **老库的 pending 行**（迁移前插的，没有令牌）：一律拒并提示"请让角色重新提交这条命令" ——
  默认落在安全那一侧，绝不"缺令牌就放行"。
- **形态 B 的接缝已经留好**：同一个字段将来只发给已认证的 operator（读侧按角色下发），
  契约不用再改一次。第三步（角色）与路由分级见 §1「还剩什么」1。

### 10.16 P0-3 第三步：路由分级（2026-09-20）
"哪些端点能影响主机"以前**没有答案**：`local_service.py` 里那个 `require_loopback` 是一个路由文件
自带的局部约定，既不是共享词汇，也没人保证新端点会表态。现在是一张清单 + 默认最严：
**想让一条端点更宽松必须写一行，忘了表态的后果是被当成操作员端点**（而不是反过来）。

四点值得记：
- **清单的价值一半在运行时、一半在"没人能悄悄加端点"**。所以配了枚举用例：断言清单里每一条都
  真匹配到某条路由 —— 前缀写错字/端点改名的后果是"降级悄悄失效、行为变严"，那种红比绿重要。
- **枚举路由必须递归**：这个版本 FastAPI 把 `include_router` 存成惰性的 `_IncludedRouter`，
  `app.routes` 里根本没有 `APIRoute` —— 不展开就"看到 19 条而实际 75 条"，清单检查会**假绿**。
  这是 §10.11 那条"只会数出现次数的检查比没有更危险"的镜像版本：检查本身也可能长得像做了。
- **`AUTH_MODE=off` 不启用分级**（不是忘了）：那档的语义就是"我本机单人用"，而非回环绑定早已被
  启动护栏拒绝，在这里再拦一次等于用一条永远为真的条件伪装成检查。真正的收益在 `on`/`auto`：
  豁免路径不再能顺带放过管理端点。TestClient 默认对端是 `"testclient"`（非回环），所以用例里
  **对端必须显式注入**，否则测的是一厢情愿。
- **文档路由不跟着静态资源一起豁免**：`/openapi.json` 把整个攻击面连参数模型一起打印出来，
  它不在 `/api/` 下，按"非 /api = 静态"的规则会被白送，所以显式排除。

### 10.17 未表态即拒的形状选择：默认最严而不是"每条都得填"
另一种写法是给装饰器加必填 `access=...` 参数（新端点不填就起不来）。没选它是因为它把决定推给
了"写端点的人记得写"，而清单 + 枚举用例把决定推给了"读清单的人看得见"。前者漏一次就静默放行，
后者漏一次是红。**同一层还顺手给下一步（凭证分族）留了唯一挂点** —— 那一步只需要改 `classify`
的消费方，不需要再翻 75 条端点。

### 11.1 模型页「本地推理服务」启停卡 —— 三档齐全

动机是真实痛点：8 GB 显存上默认模型被启动预热以 `keep_alive=-1` 钉死（实测 `expires_at` 是 2318
年），**它自己永远不会让出显存**；要玩游戏/跑别的模型就得手动卸。

| 档 | 语义 | 落点 | 状态 |
|---|---|---|---|
| 卸载模型 | 释放显存，服务进程留着（回来第一条消息自动重载） | `POST /api/local-service/unload`（原语 `core/probes.ollama_keep`） | ✅ `165a3ab`，默认按钮 |
| 停止服务 | 杀掉 `ollama serve` 进程 | **壳侧** `stopOllama()` | ✅ `e6e03c0`，**只停本壳 spawn 的那个** |
| 启动服务 | 拉起本地服务 | **壳侧** `startOllama()` | ✅ `e6e03c0`，自动发现 + 端口已有别人实例时给可读理由 |

**安全边界（写死，不留配置）**：这组端点能影响本机，而 P0-3 的 operator 鉴权尚未闭环 ⇒
**只接受回环来源**（不看 `X-Forwarded-For`，复用 `api/auth.client_ip` 的 TCP 对端口径），且不随
`AUTH_MODE` 放开。等 authz 建起来再纳入同一套角色判定。

三处偏离与收获：
- **合并了原先那半张卡**：「预热/常驻」原先在 `routers/settings.py`，与新的卸载端点分家 = 两处各写
  一遍"什么在显存里"。合并后旧端点删除，`num_ctx` 透传断言搬到 `test_local_service_api.py`。
  顺带补了一个洞：`keepalive` 原先挂在设置路由上、**没有回环门禁**，而它会驱动进程去加载 5.8 GB
  ⇒ 公网部署时等于任何人可远程撑满显存。
- **`OLLAMA_BIN` 不进 Python `Settings`**（与初版设计相反）。原设计假定"后端起进程"；归属定成壳之后，
  "可执行文件在哪"的唯一回答者就是 spawn 它的人。若后端也存一份，就成了"两处各自决定同一个事实"。
  壳侧用 `ROLECARD_OLLAMA_BIN`，自动发现顺序 = 显式 env → `%LOCALAPPDATA%\Programs\Ollama` →
  `Program Files(x86)/Ollama` → PATH。**本机就是装在 `D:\code\Ollama` 的便携实例、不在 PATH**，
  所以这条兜底不是假想需求。
- **"停止"不给外部实例按钮**（不是给了再拒绝）：那是用户自己的服务，一个桌宠没资格代管它的退出。
  分工照实切开：**"在不在跑"只有 `/api/local-service` 说**，壳只说"是不是我们起的 + pid"；B/S 下没有
  壳可问，卡片就换成一句说明而不是一个点不动的灰按钮。
- 状态行**没有"占用/总量"**：总量要读 `nvidia-smi`，本机（WDDM/混合显卡）那个数不可信，而且多一个
  进程外呼就是多一种失败模式。卡片只显示 Ollama 自己报的驻留字节数。

实测（2026-09-20，**真 Ollama 真起真停**）：为了不碰用户那个正在跑的实例，把壳指到空端口
（`ROLECARD_OLLAMA_URL=http://127.0.0.1:11534` + 子进程 `OLLAMA_HOST=127.0.0.1:11534`）后
`start()` → pid 27788、`/api/version` 答 `0.34.0`、`owner()` 如实 `managed:true`；`stop()` →
端口 4 秒内释放、`managed` 回落 false，而 11434 上那个全程 200 没被碰。同一轮还做实了两条拒绝路径：
指向**别人的**实例时 `start()` 给回"已经有一个 Ollama 在跑（不是本应用起的），不再起一个"且
`managed` 保持 false，`stop()` 给回"本应用没有起过 Ollama，所以不停任何进程"。
⚠️ **自动发现在这台机器上是真的兜不住**：`resolveBinary()` 不设 env 时返回 `null` —— 本机 Ollama
是装在 `D:\code\Ollama` 的便携版、不在 PATH，而那三个官方默认落点都不是它。这不是缺陷（便携安装
按定义就是用户自己放的位置），但要知道：**这类机器必须设 `ROLECARD_OLLAMA_BIN`**，界面上那句
"没找到 ollama 可执行文件……或给壳设 ROLECARD_OLLAMA_BIN 指到它"就是唯一出口，别指望猜路径。
起停管道更早还用过"会立刻退出的假二进制"验过 `managed` 随子进程退出如实回落。

### 11.2 运行形态与分发（含一次自我更正与一次选型翻转）

**先说钉住的那条承诺：不装 Ollama 也必须是完整可用的一等形态**（`952594f`，
`tests/integration/test_cloud_only_shape.py` 负责——它跨装配根/预热/地址解析/主动投递四个模块，
拆进各模块单测就没人对"这一形态"负责）。受影响只有三处且都不影响可用性：视觉探针（云端只信声明的
能力位）、本地服务卡（老实显示"未运行"）、隐私边界从"全本地"变成"文本走第三方"。

| 形态 | 后端在哪 | 绑定 | 安全前提 |
|---|---|---|---|
| **A 单机自用**（当前目标） | 用户自己机器（sidecar 随包） | 127.0.0.1 | 回环即边界，`AUTH_MODE=off` 可用 |
| **B 共享服务**（v2.4 那条线，暂不做） | 某台服务器 | 0.0.0.0 / 反代 | **必须** `AUTH_MODE=on` + 多用户 + 限流 + 审批鉴权（P0-3 未闭环前不能开） |

"模型走本地还是走云端 API"是**另一根独立的轴**，四种组合都合法——之前把两根轴混在"离线/在线"这一个
词里，会生出"给离线模式做一套代码"这类伪需求。

**自我更正（记下来是因为它差点误导了选型）**：拿"安装包 6 MB vs 100 MB"比较壳时，比的是**只装壳**。
一旦按形态 A 把 Python 后端打进包，两边总包体积基本相同，Tauri 的体积杀手锏在自包含分发里不成立。

**于是壳选型翻转：Tauri → Electron**（`b798f80`，用户拍定"换吧，早换早好"）。理由按分量排：
① D② 剩下的活全是**原生能力胶水**（托盘/自启/热键/通知/单实例/位置记忆），Electron 里每项都是同一
份 TS，Tauri 里每项都是 Rust 侧改动 + 插件 + capability 配置 + 一次 cargo 编译；② 与门禁贴合：
Electron 跑在现成 npm + tsc + vitest 上，壳代码能进同一套门禁，`cargo build` 几分钟且 `gate.py` 覆盖
不到；③ 体积优势被后端抹平，而装机成本从 1.5 GB 工具链变成零编译器、`npm i` 即可。
**反过来该选 Tauri 的唯一情形**：若最终不做自包含包，而是"壳只 6–10 MB、用户连部署的服务"（形态 B），
小体积/小更新/系统 WebView 又都回来了——所以这个选择的真正前提是分发形态，而形态已定为 A。

**从 Tauri 实测带走、换壳也不变的三条通用事实**：
1. **透明窗必须截屏幕区域验**：按窗口截图（WGC 类机制）不合成下层窗口，永远看不出来——这条验证死
   胡同走过一次。WebView2 与 Chromium 的 per-pixel alpha 都能真透明。
2. **不能让窗口直接指向后端地址**：后端没起来时内核浏览器会显示**它自己的**错误页（实测"嗯…无法访问
   此页面"），那块白底 + 浏览器文案比桌宠还显眼，我们写的可读提示根本没机会渲染。正确做法是每扇窗
   先落**壳自带的本地着陆页**，探活成功再跳。
3. **进程归属不能只挂在"正常退出"上**：硬杀/崩溃时后端会变孤儿，占着端口（本地模型场景还占着 6 GB
   显存）。等价做法是**后端自己盯着父进程**（`ROLECARD_PARENT_PID` + 看门狗，父没了就自杀，`1c275eb`）
   ——这样这条保证与壳用什么语言无关。**该做在后端，不该做在壳里。**

### 11.3 D②-3 原生桥（`3aacdb3` + `42dfb6e`）

**桥面刻意做小，且规则先于功能**：`preload/bridge.ts` 现在九个方法，一律**零参数或只收会话 id**；
**没有通用 IPC 转发器**——有了 `invoke(channel, ...args)` 那种口子，上面这些限制就只是一句空话。
起停本机进程的三个方法（`ollamaOwner`/`startOllama`/`stopOllama`）连参数都不收：起停一个本机进程能
碰到的东西比打开一个会话多得多，参数一旦是路径/命令，桥就成了任意执行入口。

**"关窗口"的语义定在壳里**：控制台 `close` → `preventDefault` + `hide`（桌宠与后端继续活着），唯一
退出入口是托盘「退出」，它走 `before-quit` 回收**自己 spawn 的**那个后端。
`window-all-closed → quit` 保留为兜底，不是用户路径。
**通知的判定在前端、弹在壳**（与 §7 那条更正是一对）；首次快照只立基线，避免开机/重连把积压当新
消息轰炸。

实测清单（起真窗，非 mock）：桌宠拖到新位置后 `window-state.json` 记下 `(706,210)`；把该文件手工写
成越界坐标再启动 → 主窗从 `(-5000,-5000)` 夹回 `(0,0)`，且 `move` 事件把夹完的位置写回（一次启动同时
验"还原/夹取/保存"三段）；点控制台 ✕ → 窗口从列表消失而进程仍活；再跑一个实例 → 主实例把控制台带回
前台，第二个实例自己退出且**没碰**端口上那个不属于它的后端。

### 11.4 D②-4 sidecar 自包含打包（`67b7e33` + `c15e0ef`，产物实机跑通）

**做法**：`packaging/rolecard-backend.spec`（PyInstaller **onedir**）+ `scripts/build_sidecar.py` +
`shell/electron-builder.yml`（`extraResources` 把后端塞进 `resources/rolecard-backend/`）。
选 onedir 不选 onefile：onefile 每次启动都要自解压几百 MB，冷启动几秒起，而且"解压再执行"正是杀毒
软件最爱报的行为。

**实测体积（本机）**：随包后端 **219 MB**（含 chromadb/onnxruntime/tokenizers；**不含 Paddle** ——
本地 OCR 按设计不进包，打包态的表现是"本地 OCR 不可用"，云端 OCR 不受影响）；解包版 **592 MB**；
**NSIS 安装包 181 MB**。⇒ 当初"200–500 MB"的预估落在下沿，形态 A 的代价主要是**首次下载**，不是运行时。

**踩到的一次假成功（形状值得记住）**：第一次构建 **exit 0**、exe 也起来了，但 uvicorn 报
`Could not import module "rolecard_agent.api.main"` —— 本项目是 src-layout 且不 `pip install -e`，
`collect_submodules("rolecard_agent")` 在打包进程里**安静地返回空**。修法是 spec 里显式
`sys.path.insert(0, "<repo>/src")`。**"构建成功"不等于"产物能跑"**：打包链路的验收判据必须是跑那个
exe，不是看 PyInstaller 的退出码。

**打包态的路径策略**（`core/paths.py` 新增 `bundle_root()` / `user_data_root()` / `dotenv_path()` /
`path_from_config()`）：随包只读资源在 `_MEIPASS`（含 `frontend/dist`），用户数据在
`%LOCALAPPDATA%\rolecard-agent`，`.env` 在安装目录之外。理由都是硬的：安装目录可能不可写，而且升级
是整目录替换。开发态一字未变——`tests/unit/test_paths.py` 钉住两种形态，其中一条专门钉"相对路径按
仓库根解析"（换基准会让用户"没改过配置"却凭空丢库）。

**进程归属两层各自实测**：① 绕开壳单独测随包 exe：真父进程 `os._exit` 后 ≤10 秒后端自己走，日志出现
`[parent-watch] 父进程 NNN 已退出` ⇒ **我们那层在冻结态有效**；② 强杀打包壳主进程（`/F` 不带 `/T`）：
后端 4 秒内消失、端口释放，但 `backend.log` 里**没有**那一行 ⇒ 先动手的仍是 Electron 的子进程管理（且
壳一死，管道里未落盘的日志一起丢）。父链在打包态**没有多出一层**（后端的父进程就是壳主进程，
`ROLECARD_PARENT_PID` 指对了）。合起来的诚实说法：**Electron 那层通常先兜住，我们那层是被单独证明过的
第二道**——换壳、或壳被整树 `taskkill /T /F` 时只剩它，所以不能删。

**安装包托管给 B/S 用户下载**（`SHELL_RELEASE_DIR` + `GET /api/shell-release` + `/download`，界面在
设置→「关于与系统状态」底部一张卡）：判据是**目录里到底有没有 `rolecard-agent-*.exe`**，不是配置开没
开——部署方忘了拷产物时，界面连入口都不渲染，不留一个点了没反应的死按钮。下载走 `FileResponse` 而不
是再 mount 一个静态目录（SPA 挂在 `/`，多挂一个就要和它抢匹配顺序）；文件名只由服务端列目录得到
⇒ 没有路径拼接，也就没有穿越。

### 11.5 D②-6 收尾三件：原生目录对话框 / 开机自启 / 全局热键（`1cda1f8`）

- **原生目录对话框**：桥加 `pickDirectory()`，**零参数**——路径是用户在系统对话框里挑的，页面从头
  到尾不给路径，所以这条不构成"网页能指定任意路径"的新口子。`NativeDirPickerButton` 在**没有壳时整个
  不出现**（B/S 继续用内置的目录树抽屉），挑完只填进草稿，仍要按「保存」才生效：**授权范围不该被一次
  点击顺手改掉**。`TaskDirectoryProvider` 那层抽象**没有补**，理由见 §7。
- **开机自启**：托盘多一条「开机自启」勾选，**只在打包态出现**（dev 下 `setLoginItemSettings` 写进登录项
  的是 `node_modules/electron/dist/electron.exe` —— 一条指向依赖目录、卸载也带不走的假启动项）。同理不给
  一个"看得见但永远无效"的条目。自启带起来的这次启动带 `--autostart`，控制台**不显示**、只放桌宠——开机
  自启的语义是"宠物在桌面上待着"，不是"再弹一扇窗盖住用户正在做的事"。
- **全局热键** `Ctrl+Alt+R` 唤起/收起控制台。注册失败（键被别的程序占了）只 warn，不影响启动；退出时
  `unregisterAll`。**刻意不做**"热键让角色开口"那类触发：那是能改变主机状态的动作，而 operator 鉴权
  （P0-3）还没有——**一条全局热键等于给"任何拿到这台电脑的人"一个免登录的入口**。

**安装/卸载实跑（本机 per-user）**：`rolecard-agent-0.1.0-x64.exe /S` 装进
`%LOCALAPPDATA%\Programs\rolecard-agent` 并建了开始菜单快捷方式；装完直接跑，**起的确实是包内那个后端**
（进程可执行路径 = `…\resources\rolecard-backend\rolecard-backend.exe`），控制台 200、托盘与热键都没
告警。带 `--autostart` 再起一次：窗口列表里**只有桌宠、没有控制台**。静默卸载把文件与快捷方式都清掉了，
只剩一个空目录（NSIS 常态）。
**卸载故意不删用户数据**（`%LOCALAPPDATA%\rolecard-agent` 里是 sqlite/chroma/uploads，`%APPDATA%` 里是壳
的窗口状态与日志）：卸载一个应用不该顺手销毁别人的对话、知识库和医疗记录，要清理由用户自己来。

**热键实跑（2026-09-20 补做）**：开发态起壳（日志先说"127.0.0.1:8000 上已有后端（不是本壳起的）
→ 直接连它，退出时不动它"），用合成输入发 `Ctrl+Alt+R` 走两个方向——控制台**可见但未聚焦**时按 →
唤起（进前台）；**已聚焦**时按 → 收起（窗口从列表消失，桌宠与进程仍活）。`toggleConsole()` 那句
`isVisible() && isFocused() ? hide() : showConsole()` 就是这两个分支，实测与代码一致；日志里
没有注册失败的 warn。
