## 6. 测试性能（实测）

- 全套 641 collected，墙钟 **199s**（Ollama 在跑）。**最慢 `test_records_api::test_extract_rejects_a_second_call_while_one_is_running` 独占 46~66%**（实测 130/93/92s）——其 `client` fixture 未注入 model → 走**真实 qwen3-vl:8b**，断言接受 200/502 故恒绿。
- **隐蔽外呼**：`main.py:308/337 _auto_pin_default_model` 每次 lifespan 真 POST `/api/generate`（timeout 120）；测试补的是 `routers.settings.ollama_keep`，**没补 main** → 20 处 `TestClient` + 冒烟都把 8B 钉进显存争 GPU。
- **冒烟**：13 项离线 ~98s（其中 `_settings` 仍打真 Ollama，与"离线"自述不符）+ 1 项真机 UI ~630s（真 Chrome + 真对话，固定 sleep + 90/180s 等待）。**缺陷**：`console_ui_smoke` 的 `@check` 在模块顶层 → 装饰即执行，实际**最先**跑（与"放最后"相反）。✅（顺序反常已实测）
- 金字塔：unit 475(74%) / API 166(26%) / 冒烟 14 / 前端 vitest 72 —— 比例健康，问题是**顶层冒烟含真模型，比底层贵两个数量级**。

**提速方案**：① 该 fixture 注入 `ScriptedChat`/`model_factory` → 全套降到 ~35-45s（快 4-5×）；真模型路径另立 `@pytest.mark.live`。② lifespan 预热加开关 `create_app(pin_on_startup=False)`。③ 注册 markers，`--fast` 用 `-m "not live"`。④ ui_smoke 用 `waitForSelector` 换掉固定 sleep、超时下调。⑤ 校正 `gate.py`/`开发流程.md` 的计时口径（现称 fast≈51.7s，失真）。

## 7. C/S 就绪度 & 剩余里程碑兼容

  ⚠️ 本条原先还写着「`ReachoutScheduler` 全 DI，加 `notifier: Callable` 即原生通知接缝」—— **那句是 aspirational，不是现状**（没有那个参数），2026-09-20 决定**也不去加**：通知的判定（"这条是新未读 → 该弹"）需要知道"用户已经看过哪些"，那份状态只有前端有；后端加一个 `notifier` 回调，调用方是零（B/S 在轮询、壳也在轮询同一个 `/api/reachouts`），那就是 P1-5 删掉的那五个假接缝的再生。判定放桌宠页（可测），壳只负责"弹"（glue）。

### 11.1 模型页「本地推理服务」启停卡（用户 2026-09-19 提出，设计已拍定）

动机是真实痛点：8 GB 显存上默认模型 `qwen3-vl:8b` 被启动预热以 `keep_alive=-1` 钉死
（实测 `expires_at` 是 2318 年），**它自己永远不会让出显存**；要玩游戏/跑别的模型就得手动卸。
今天这一幕（"Ollama 停一下，我要玩游戏"）就是要做成界面的那个动作。

设计（**三档齐全**，用户已确认）：

| 档 | 语义 | 实现 | 风险与防护 |
|---|---|---|---|
| 卸载模型 | 释放显存，服务进程留着（回来第一条消息自动重载） | `POST /api/generate {"model":…,"keep_alive":0}`，原语已在 `core/probes.ollama_keep` | 无。这是默认按钮 |
| 停止服务 | 杀掉 `ollama serve` 进程 | 只允许停**由本应用启动**的进程（记录 spawn 的 PID + 校验端口归属）；别人手动起的实例只显示不操作 | 误杀是主要风险；停止后正在跑的对话/抽取要收到可读失败而不是挂住 |
| 启动服务 | 拉起本地服务 | 需要可执行文件路径 → 新配置项 `OLLAMA_BIN`（**必须走 `Settings` + `from_env` + `.env.example` 契约**，不许在代码里 `os.environ` 直读，见 P1-4 的教训）。本机 Ollama 是便携安装、不在 PATH，自动发现要有失败兜底 | 起进程 = 本机执行，见下面的安全边界 |

状态行要显示：在跑/没跑、哪个模型驻留、占用/总量、是谁起的（本应用 / 外部）。
UI 位置：设置 → 模型页顶部一行卡片（不新开页签）；`前端设计.md` 能力矩阵加一行"可见/可控"。

⚠️ **安全边界（写死，不留配置）**：这是一组"能起停本机进程"的端点，而 §1 的 P0-3 尚未闭环
（`AUTH_MODE` 默认 off + 审批可自批 = 公网即自批 RCE 链）。所以这些端点从第一天起
**只接受回环来源调用**（不看 `X-Forwarded-For`，复用 `api/auth.client_ip` 的 TCP 对端口径），
且不随 `AUTH_MODE` 放开。等 P0-3 的 operator 鉴权建起来，再把它纳入同一套角色判定。

依赖顺序：与 `core/turn.py`（§7 D 的最后一条返工点）**无冲突** —— 那是在动对话链路的编排，
这是新增一组管理端点。先做哪个都不挡另一个。

**落地（2026-09-19，第一档 + 状态）**：`api/routers/local_service.py` 三个端点
`GET /api/local-service`、`POST /api/local-service/pin`、`POST /api/local-service/unload`，
界面在设置 → 模型顶部一张卡（`components/LocalServiceCard.tsx`）。三处值得记的偏离与收获：

- **原来那半张卡被合并了**：「预热/常驻」原先是 `routers/settings.py` 的
  `GET /api/settings/models/resident` + `POST /api/settings/models/keepalive`，与新的卸载端点
  分家 = 两处各写一遍"什么在显存里"（P1-5 收口的正是这类"两处各自实现且不同步"）。
  合并到一处后旧的两个端点**删除**，
  `num_ctx` 透传的断言搬到 `test_local_service_api.py`，`PATCH .../context` 的读回另补一条。
- **合并顺带补了一个洞**：`keepalive` 原先挂在设置路由上、**没有回环门禁**，而它会驱动进程去
  加载 5.8 GB —— 公网部署时等于任何人可远程撑满显存。现在 `pin` 与 `unload` 吃同一道门禁。
- **状态行没有"占用/总量"**：总量要读 `nvidia-smi`，本机（WDDM/混合显卡）那个数不可信，
  而且多一个进程外呼就是多一种失败模式。卡片只显示 Ollama 自己报的驻留字节数，够用。

`停止服务 / 启动服务` 两档**仍未做**，等 D② 的桌面壳：`OLLAMA_BIN` 与 PID 归属校验都属于壳侧
的进程管理，先在 HTTP 层做一遍到壳里还要挪一次。

**落地（2026-09-20，D③-b 补齐后两档，三档齐全）**：起停做在**壳**里（`shell/main/ollama.ts`），
桥暴露 `ollamaOwner` / `startOllama` / `stopOllama` **三个零参数方法**，界面仍是那张卡加两个按钮。
两处对设计的偏离，都是当时没想清楚的地方：

- **`OLLAMA_BIN` 不进 Python `Settings`**（与上表那条相反）。原设计假定"后端起进程"，所以要求
  它走 `Settings` + `.env.example` 契约；实际归属定成壳之后，"可执行文件在哪"这件事的唯一回答者
  就是 spawn 它的那个人。若后端也存一份，就成了"两处各自决定同一个事实"——正是 §11.1 上面刚合并
  掉的那个 bug 形状。壳侧用 `ROLECARD_OLLAMA_BIN`（与 `ROLECARD_PET` 同一族壳 env 契约），
  自动发现顺序 = 显式 env → `%LOCALAPPDATA%\Programs\Ollama` → `Program Files(x86)/Ollama` → PATH。
  **本机就是装在 `D:\code\Ollama` 的便携实例、不在 PATH**，所以这条兜底不是假想需求。
- **"停止"只停本壳 spawn 的那个**，别人起的（含开机自启）只显示状态、**不给按钮** ——
  不是给了再拒绝。理由：那是用户自己的服务，一个桌宠没资格代管它的退出。

分工也照实切开：**"在不在跑"只有 `/api/local-service` 说**，壳只说"是不是我们起的 + pid"。
两边各答一件事，才不会互相打脸（B/S 下没有壳可问，卡片就换成一句说明而不是一个点不动的灰按钮）。

实测：端口上已有别人的 Ollama 时 `start()` 给回可读理由、不重复起；`stop()` 在我们没起过时拒绝；
起停管道用"会立刻退出的假二进制"验过 `managed` 随子进程退出如实回落。真 Ollama 全程没被碰。
⚠️ 仍未实机验证的只剩一条：**真的把本壳起的 Ollama 拉起来一次**（需要先把用户那个停掉，
不在别人正在用的机器上做）。

### 11.2 运行形态与分发（2026-09-20 定，含一处自我更正与一次壳选型翻转）

用户问的两件事把形态问题逼了出来："总不能后端还放我这吧"、"别人填其他厂的 API key 能不能用"。

**先说承诺并钉住的那条**：**不装 Ollama 也必须是完整可用的一等形态**。核实结果是对话/抽取
（模型页任意 OpenAI 兼容行 + key）、检索嵌入（服务页端点序，`hash` 兜底）、OCR（云端行需
操作员显式建凭据行）都不依赖本地推理；受影响的只有三处，且都不影响可用性：视觉能力探针
（`vision_model_ready` 问的是 Ollama，云端只信声明的能力位）、模型页那张本地服务卡（会老实
显示"未运行"）、以及隐私边界从"全本地"变成"文本走第三方"。这条整体成立由
`tests/integration/test_cloud_only_shape.py` 负责（跨装配根/预热/地址解析/主动投递四个模块，
拆进各模块单测就没人对"这一形态"负责）。

**两个运行形态，按"这台机器是不是别人也会连"分，不按有没有网分**：

| 形态 | 后端在哪 | 绑定 | 安全前提 |
|---|---|---|---|
| **A 单机自用**（桌宠/桌面 App，**当前目标**） | 用户自己机器（sidecar 随包） | 127.0.0.1 | 回环即边界，`AUTH_MODE=off` 可用；主机影响类端点的回环限制天然满足 |
| **B 共享服务**（v2.4 那条线，暂不做） | 某台服务器 | 0.0.0.0 / 反代 | **必须** `AUTH_MODE=on` + 多用户身份 + 速率限制 + 审批鉴权（P0-3 未闭环前不能开） |

"模型走本地还是走云端 API"是**另一根独立的轴**，四种组合都合法 —— 之前把两根轴混在
"离线/在线"这一个词里，会生出"给离线模式做一套代码"这类伪需求。

**自我更正（记下来是因为它差点误导了选型）**：我拿"安装包 6 MB vs 100 MB"比较壳时，比的
是**只装壳**。一旦按形态 A 把 Python 后端打进包（PyInstaller/Nuitka → 200–500 MB），
两边总包体积基本相同，Tauri 的体积杀手锏在自包含分发里不成立。

**于是壳选型翻转：Tauri → Electron**（用户 2026-09-20 拍定"换吧，早换早好"）。理由按分量排：

1. **D② 剩下的活全是原生能力胶水**（托盘/自启/全局热键/系统通知/单实例/窗口位置记忆）。
   Electron 里每一项都是同一份 TS；Tauri 里每一项都是 Rust 侧改动 + 一个插件 + capability
   配置 + 一次 cargo 编译。
2. **与本项目门禁贴合**：Electron 跑在现成的 npm + tsc + vitest 上，壳代码能进同一套门禁；
   `cargo build` 几分钟，gate.py 覆盖不到，只能靠手工验（这一轮就是这么过的）。
3. **体积优势被后端抹平**（见上），而"你这台机器"的装机成本从 1.5 GB 工具链 + 两颗坑
   变成零编译器、`npm i` 即可。
4. 保留的优势承认更小：Tauri 省 100–200 MB 常驻内存（只在本地模型场景有意义）、更新包小
   （但整包大头是后端，本来就得重发）。

**反过来该选 Tauri 的唯一情形**：如果最终不做自包含包，而是"壳只 6–10 MB、用户连你部署的
服务"（形态 B），小体积/小更新/系统 WebView 又都回来了。所以这个选择的真正前提是分发形态，
而形态已定为 A。

**从 Tauri 实测里带走的三条结论**（换壳不改变它们，是桌宠这类窗口的通用事实）：

1. **透明窗必须截屏幕区域验**，按窗口截图（WGC/类似机制）不合成下层窗口，永远看不出来 ——
   这条验证死胡同走过一次。WebView2 与 Chromium 的 per-pixel alpha 都能真透明。
2. **不能让窗口直接指向后端地址**：后端没起来时内核浏览器会显示它自己的错误页（实测
   "嗯…无法访问此页面"），那块白底 + 浏览器文案比桌宠还显眼，我们写的可读提示根本没机会
   渲染。正确做法是每扇窗先落**壳自带的本地着陆页**，探活成功再跳。
3. **进程归属不能只挂在"正常退出"上**：硬杀/崩溃时后端会变孤儿，占着端口（本地模型场景还占
   着 6 GB 显存）。Tauri 版用 Win32 作业对象（`KILL_ON_JOB_CLOSE`）实测有效；换 Electron 后
   等价做法是**后端自己盯着父进程**（`ROLECARD_PARENT_PID` + 看门狗线程，父没了就自杀），
   这样这条保证与壳无关，两种壳都受益 —— 该做在后端，不该做在壳里。

**待办**：sidecar 自包含打包（PyInstaller onedir + 随包 `dist/`，安装包 200–500 MB）排在 D
的收尾，不打断桌宠主线；B/S 的"下载壳安装包"入口按已定方案由后端托管、**有产物才显示**。

**打包后必须复验的一条（用户 2026-09-20 拍定"记下来，等 sidecar 打包出来再验"）**：开发态实测
"硬杀壳 → 后端 1 秒内消失"，但 `core/parent_watch.py` **没有**打印它那句日志 —— 说明当时兜住的
是 Electron/Chromium 侧的进程管理，**不是**我们写的那道。这层照顾在打包形态是否还在，属于
未证明；复验判据是"强杀壳主进程（真实 Windows PID，`/F` 不带 `/T`）后 ≤3 秒端口释放，且后端
日志里出现 `[parent-watch] 父进程 … 已退出`"。若进程还在，就是孤儿回归，要查打包态的父链
（启动器多一层进程时 `ROLECARD_PARENT_PID` 指的是谁）。验完把结论回写到本节与 `开发流程.md`
的壳一节 —— 那两处现在写的都是"未证明是谁干的"。

> **2026-09-20 已验完，见下面 §11.4**：打包态父链没有多出一层（后端的父进程就是壳主进程），
> 我们那层看门狗**在冻结态单独实测有效**；而"强杀壳"这条路上先动手的仍是 Electron。

### 11.3 D②-3 原生桥（2026-09-20 落地，全部真机验过）

**桥面刻意做小**：`preload/bridge.ts` 只暴露 `backendUrl` / `backendReachable` / `openSession` /
`notify` / `onRequestOpenThread`（"我挂好监听了"的回执）。**没有通用 IPC 转发器** —— 有了
`invoke(channel, ...args)` 那种口子，上面这些限制就只是一句空话。

**"关窗口"的语义定在壳里**：控制台 `close` → `preventDefault` + `hide`（桌宠与后端继续活着），
唯一退出入口是托盘「退出」，它走 `before-quit` 回收**自己 spawn 的**那个后端。
`window-all-closed → quit` 保留为兜底，不是用户路径。

**通知的判定在前端、弹在壳**：与 §7 那条更正是一对 —— 后端调度器不知道"用户看过哪些"，那份
状态只在页面里；所以"这条算不算新未读"写在桌宠页（可测），壳只是拍 toast 的手。首次快照只立
基线，避免开机/重连把积压当新消息轰炸。

**实测清单**（`shell/` 起真窗，非 mock）：托盘与两扇窗创建无异常；桌宠拖到新位置后
`%APPDATA%\rolecard-shell\window-state.json` 记下 `(706,210)`；把该文件手工写成越界坐标再启动
→ 主窗从 `(-5000,-5000)` 夹回 `(0,0)`，且 `move` 事件把夹完的位置写回（一次启动同时验"还原/
夹取/保存"三段）；点控制台 ✕ → 窗口从列表消失而进程仍活（桌宠还在）；再跑一个实例 → 主实例
把控制台带回前台，第二个实例自己退出且**没碰**端口上那个不属于它的后端。

**当时有意推迟**（现已全部做完，见 §11.5）：开机自启与全局热键推到打包态（dev 下
`setLoginItemSettings` 会往登录项里写一条指向 `node_modules/electron` 的假启动项，热键绑定
是个还没定的产品选择）；原生目录对话框当时未做 —— `TaskDirectoryProvider` 从来不存在，
别再当"已预留"。

### 11.4 D②-4 sidecar 自包含打包（2026-09-20 落地，产物实机跑通）

**做法**：`packaging/rolecard-backend.spec`（PyInstaller **onedir**）+ `scripts/build_sidecar.py`
+ `shell/electron-builder.yml`（`extraResources` 把那份后端塞进 `resources/rolecard-backend/`）。
选 onedir 不选 onefile：onefile 每次启动都要自解压几百 MB，冷启动几秒起，而且"解压再执行"
正是杀毒软件最爱报的行为。

**实测体积（本机）**：随包后端 **219 MB**（含 chromadb/onnxruntime/tokenizers；**不含 Paddle**
—— 本地 OCR 按设计不进包，打包态的表现是"本地 OCR 不可用"，云端 OCR 不受影响）；解包版
**592 MB**；**NSIS 安装包 181 MB**。⇒ 当初"200–500 MB"的预估落在下沿，形态 A 的代价主要是
首次下载，不是运行时。

**踩到的一次假成功**（形状值得记住）：第一次构建 **exit 0**、exe 也起来了，但 uvicorn 报
`Could not import module "rolecard_agent.api.main"` —— 本项目是 src-layout 且不 `pip install -e`，
`collect_submodules("rolecard_agent")` 在打包进程里**安静地返回空**。修法是 spec 里显式
`sys.path.insert(0, "<repo>/src")`。**"构建成功"不等于"产物能跑"**：打包链路的验收判据必须是
跑那个 exe，不是看 PyInstaller 的退出码。

**打包态的路径策略**（`core/paths.py` 新增 `bundle_root()` / `user_data_root()` /
`dotenv_path()` / `path_from_config()`）：随包只读资源在 `_MEIPASS`（含 `frontend/dist`），
用户数据在 `%LOCALAPPDATA%\rolecard-agent`，`.env` 在安装目录之外。理由都是硬的：安装目录
可能不可写，而且升级是整目录替换。开发态一字未变 —— `tests/unit/test_paths.py` 钉住两种形态，
其中一条专门钉"相对路径按仓库根解析"（换基准会让用户"没改过配置"却凭空丢库）。

**进程归属两层各自实测（把 §11.2 那条待验收口）**：
① 绕开壳单独测随包 exe：真父进程 `os._exit` 后 ≤10 秒后端自己走，日志出现
`[parent-watch] 父进程 NNN 已退出` ⇒ **我们那层在冻结态有效**；
② 强杀打包壳主进程（`/F` 不带 `/T`）：后端 4 秒内消失、端口释放，但 `backend.log` 里
**没有**那一行 ⇒ 先动手的仍是 Electron 的子进程管理（且壳一死，管道里未落盘的日志一起丢）。
父链在打包态**没有多出一层**（后端的父进程就是壳主进程，`ROLECARD_PARENT_PID` 指对了）。
合起来的诚实说法：Electron 那层通常先兜住，我们那层是被单独证明过的第二道 —— 换壳、或壳被
整树 `taskkill /T /F` 时只剩它，所以不能删。

**安装包托管给 B/S 用户下载**（`SHELL_RELEASE_DIR` + `GET /api/shell-release` +
`GET /api/shell-release/download`，界面在设置→通用 底部一张卡）：判据是**目录里到底有没有
`rolecard-agent-*.exe`**，不是配置开没开 —— 部署方忘了拷产物时，界面连入口都不渲染，
不留一个点了没反应的死按钮。下载走 `FileResponse` 而不是再 mount 一个静态目录（SPA 挂在 `/`，
多挂一个就要和它抢匹配顺序）；文件名只由服务端列目录得到 ⇒ 没有路径拼接，也就没有穿越。

### 11.5 D②-6 收尾三件：原生目录对话框 / 开机自启 / 全局热键（2026-09-20）

**原生目录对话框**：桥加 `pickDirectory()`，**零参数** —— 路径是用户在系统对话框里挑的，
页面从头到尾不给路径，所以这条不构成"网页能指定任意路径"的新口子。界面侧
`NativeDirPickerButton` 在**没有壳时整个不出现**（B/S 继续用内置的目录树抽屉），挑完只填进
草稿，仍要按「保存」才生效：授权范围不该被一次点击顺手改掉。
`TaskDirectoryProvider` 那层抽象**没有补**，因为它不该存在 —— 选择器归壳、契约归后端，
两边各就各位就是完整的（§7 那条已按此改口）。

**开机自启**：托盘多一条「开机自启」勾选，**只在打包态出现**（dev 下 `setLoginItemSettings`
写进登录项的是 `node_modules/electron/dist/electron.exe` —— 一条指向依赖目录、卸载也带不走
的假启动项）。同理不给一个"看得见但永远无效"的条目：开发态整条不渲染。
自启带起来的这次启动带 `--autostart`，控制台**不显示**、只放桌宠 —— 开机自启的语义是
"宠物在桌面上待着"，不是"再弹一扇窗盖住用户正在做的事"。

**全局热键**：`Ctrl+Alt+R` 唤起/收起控制台（正开着就收回去）。注册失败（键被别的程序占了）
只 warn 一句，不影响启动；退出时 `unregisterAll`。**刻意不做**"热键让角色开口"那类触发：
那是能改变主机状态的动作，而 operator 鉴权（P0-3）还没有 —— 一条全局热键等于给"任何拿到
这台电脑的人"一个免登录的入口。

桥面到今天是九个方法，仍然**没有通用 IPC 转发器**，且新增的四个（起停 Ollama 三件 +
选目录一件）一律零参数。

**安装/卸载实跑（2026-09-20，本机 per-user）**：`rolecard-agent-0.1.0-x64.exe /S` 装进
`%LOCALAPPDATA%\Programs\rolecard-agent` 并建了开始菜单快捷方式；装完直接跑，**起的确实是包内
那个后端**（进程可执行路径 = `…\resources\rolecard-backend\rolecard-backend.exe`），控制台
200、托盘与热键都没告警。带 `--autostart` 再起一次：窗口列表里**只有桌宠、没有控制台** ——
开机自启的语义按预期成立。静默卸载把文件与快捷方式都清掉了，只剩一个空目录（NSIS 常态）。

**卸载故意不删用户数据**（`%LOCALAPPDATA%\rolecard-agent` 里是 sqlite/chroma/uploads，
`%APPDATA%\rolecard-agent` 里是壳的窗口状态与日志）：卸载一个应用不该顺手销毁别人的对话、
知识库和医疗记录。要清理由用户自己来。

仍未实跑的一条：**真的按键触发全局热键**（当时用户正在打游戏，没往系统里注键）。
`globalShortcut.register` 返回成功（失败会 warn，日志里没有），所以缺的只是"按下之后控制台
真的出来"这一步的人肉确认。
