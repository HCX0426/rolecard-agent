# 数据与隐私：存在哪、怎么备份、怎么搬走

> 面向：装机版用户。本产品是**本地为底**：对话、记忆、知识库全部在你自己的磁盘上，
> 没有任何遥测后端；出网只发生在你主动配的模型后端与"检查更新"两件事上。

## 数据根五件套（都在 `%LOCALAPPDATA%\rolecard-agent`）

| 目录/文件 | 是什么 |
| --- | --- |
| `sqlite\app.db` | 一切结构化数据：对话、记忆、角色卡、审计台账、token 账本 |
| `chroma\` | 知识库的向量索引（你上传的文档的分块检索用） |
| `uploads\` | 你上传过的原件（体检报告 PDF/图片等） |
| `pets\` | 桌宠形象包 |
| `elysia_lore\` 等演示目录 | 随包演示素材（可删，删了演示知识没了） |

升级前程序会把**整个数据根**快照到 `%LOCALAPPDATA%\rolecard-agent-update-backups\`
（保留最近 2 份）——这是"升级失败怎么还原"的原料。

## 备份：一条命令

装着 python 的机器上：

```
python scripts/tools/backup_data_root.py --dest 想放哪
```

得到一个 zip，里面是整根（sqlite 用快照方式拷，开着程序也不坏）。**注意：zip 里含
模型 API key**（存在 sqlite 里，明文是设计决定）——备份包别进网盘/聊天工具。

## 还原 / 换机

- 目标机器装好同版本（或更新版本）的 rolecard-agent，**先别启动**（或托盘退出）。
- `python scripts/tools/backup_data_root.py --restore <zip> --into <空的临时目录>`，
  再把临时目录里的内容原样拷回新机的数据根。启动后一切照旧。
- 升级失败的还原是**目录对目录**（不是 zip）：拿 `rolecard-agent-update-backups\` 里
  那份快照拷回去即可，详见《更新机制与OCR随包》"升级失败怎么还原"。

## 双机同步（如果两台都装了）

设置→资料里有双机互推（角色卡/会话/记忆/主动开口四类，带对账与冲突裁决）。**注意范围**：
健康档案原件、上传文件、知识库向量**不在同步范围**——换机请以"备份 zip"为主，同步为辅。

## 角色卡与记忆

- 角色卡可以导出成 SillyTavern V2 JSON 分享给朋友。**记忆默认不随卡走**；导出时显式
  选"带记忆导出"才会带上置顶且未失效的那几条——借卡的人拿不到她的其他记忆。
- 记忆存在 sqlite 的 `role_memory_item` 表里，四层（长期/自记/会话/项目），记忆页签
  里能看到和改的，就是注入进对话的全部。

## 图片出机吗

- 本地 OCR（报告图片的文字识别）随安装包走，图片不出机。
- 只有当你主动配置了**云端 OCR**（默认关）时，图片才会发给你自己配的那个云端服务。

## 一句话总结

你的数据根目录就是你的全部状态；拷走它=搬走她。备份脚本认它、升级备份护它、卸载不动它。
