# 常见问题与故障排查

> 面向：装机版用户。三条最快的自救路径：①看这一页的对应条目；②设置页导出诊断包；
③把 `backend.log` 最后几行贴给维护者。

## 回答很慢（尤其是本地模型）

- 本地模型（Ollama）的"思考"是真花时间：首字可能 10 秒以上。对话页消息行可以展开
  **思考过程**——那段时间花在哪儿它自己会讲。
- 云端后端通常首字 1~3 秒。慢的期望管理：换云端后端对比一次，就知道慢在模型不在网络。
- 首次对话/换模型后第一问会更慢（模型预热），第二问起是真实速度。

## 模型连不上 / 回答里写着"降级"

- 设置→模型里点"测试"看具体错误。常见三种：base_url 写错（路径少了 `/v1` 或多了）；
  key 无效（只写不回读，需要重新填一遍）；本机 Ollama 没起（`ollama serve` 或托盘）。
- 配了回退链时，主后端挂了会自动用下一个，并在回答上注明——这不是 bug，是设计。
- "本地"两个字在本仓有两个意思，别混：**模型跑在哪**（本机/云端）与**部署形态**
（单机桌面 / 公网自托管）是两条独立的轴。

## 更新相关

- **检查更新**在托盘菜单。三档（开机检查 / 下载 / 自动安装）默认只开第一档。
- 升级前程序会自动把数据根快照到 `%LOCALAPPDATA%\rolecard-agent-update-backups\`
（保留最近 2 份）。升级失败要还原：先装回旧版安装包，再把快照目录里的内容拷回数据根。
  详见《更新机制与OCR随包》设计稿的"升级失败怎么还原"一节。
- 装完新版桌面图标没变/版本没变：托盘退出旧实例再开一次（自动安装在退出时进行）。

## 桌宠不见了 / 压在任务栏上

- 先看托盘菜单里桌宠是否被关了；唤出后拖一下——她被顶出屏幕外时拉回来即可（面板在
  DOM 里，只是位置出界）。
- 桌宠窗口透不进点击：桌宠窗有"感应区"，把鼠标移到形象正上再点。

## 端口 8000 被占 / 后端起不来

- 随包后端默认监听 8000。别的程序占了它：换端口用环境变量 `ROLECARD_API_PORT`
  （壳会把它同时作为 `RUN_API_PORT` 传给后端——只改一边就是"后端起在 8000、壳在探
  另一个口"那种谁都没错却连不上的事故）。
- 反复起不来：`backend.log` 的最后 20 行几乎是唯一有用的证据；连同诊断包一起发。

## 401 / 403

- **401**：这是部署形态的轴——单机桌面版默认不开鉴权；如果你在公网/局域网部署了实例，
  凭据走 HTTP Basic（管理员发的那个）。
- **403 "本机服务只认本机来源"**：你用非回环地址访问了一台开了本机来源护栏的实例。
  用 `http://127.0.0.1:8000` 访问本机服务。

## 记忆相关的"她忘了/她记错了"

- 记忆页签是**管理视图**：能看到的每一条都是她每轮真的会被注入的（同库同检索，没有
  第二套）。她记错了就直接在页签里改/作废那条，不用提示词去"纠正"她。
- 记忆分四层（长期/自记/会话/项目），页签里按层分块；"自记"是她自己写的，内容最像
  日记，也最值得人工抽查。

## 一次性收集全部现场

- 设置页 → 诊断 → 导出：得到一个 zip（版本/构建/环境变量名单/错误签名/最近日志/库健康）。
  报 bug 带上它，比截图有用得多。
