### A. 技术选型
- 为什么用 LangGraph 而不是 LangChain 的 AgentExecutor / create_agent？

- 为什么用 Ollama 而不是直接调 API？企业里会怎么替换？
- 本地模型的选型踩过什么坑？
  **答（2026-09-17 终版）**：踩了一个完整来回。最初纯推断选了 `qwen2.5:7b`，部署时因为
  "Ollama 里拉的是 vl 版"顺手改成 `qwen2.5vl:7b`，理由听起来很对——vl 是文本版超集，
  对话/抽取/图片直读三合一，8GB 显存单模型常驻。**但官方 vl 模板的工具调用是坏的**：
  `bind_tools` 直接 400 "does not support tools"，而带工具的档案管理员是对话主路径。
  这个缺陷藏了两天才被评测暴露——单测全绿测不到它，因为测试铁律不碰真模型。
  **教训有两层**：换模型的验收必须包含一条 bind_tools 探针；"理论超集"不能替代真实请求。
  中间版：对话 = `qwen2.5:7b`（tools ✓ 实测 200），vl = 第二后端（图片直读/备用抽取），
  两个 7B 不同时驻留 8GB 显存，Ollama 自动换载 2~5 秒。
  **2026-09-17 终版：换成 `qwen3-vl:8b` 一行多用**（ModelScope GGUF 导入 Ollama 的
  **非官方混合模板**，chat + tools + vision 三者齐全）——一个后端行同时承担对话、识图、
  思考与 OCR，`local_vl` 退役；还踩过"模型页删一行、UI 不生效"的后端复活坑
  （effective_settings 会重新并入 env 后端），本次一并修掉。
  **追问彩蛋（踩坑）**：`provider=ollama` 的 base_url 不能带 `/v1`——langchain-ollama 走
  Ollama 原生端点（拼 `/api/chat`），带 `/v1` 会 404 page not found；`/v1` 是
  `provider=openai`（OpenAI 兼容端点）用的。端点风格由 provider 决定，这个错配我实测踩过。

### D. 安全与合规
- 你怎么保证模型不给出医疗诊断？
- 提示词约束可靠吗？如果用户诱导它呢？
- 病历数据上传到 LangSmith 云端，合规上你怎么解释？
- AI 自动提取的指标可能出错，你做了什么？
  **答（2026-09-15 已实现）**：三层校验 + 第二模型交叉 + 人工确认。① schema 约束抽取——强类型
  JSON，缺失必须是 null，不许编；② 确定性校验——数值/日期/单位/量级这些零成本就能挡掉一大半；
  ③ **原文锚定**——每个抽出的值必须带原文片段且能在原文里找到，找不到判为疑似幻觉直接拒收
  （这层挡掉的最多）；④ **第二模型交叉验证**——换一个 provider 的后端独立再抽一遍逐字段比对
  （行业称 LLM-as-verifier，Unstract 的 LLMChallenge 就是这个）；只有一个后端时降级为同模型
  复查，并**如实标注为弱校对**。最后：**只有双方一致的项才入库**，其余进「待确认」由人裁决；
  一律 `is_verified=0`，回答时原样保留【未经人工校验】标记。

### E. 工程化
- 分层之后层与层之间怎么通信？为什么不让 Agent 层直接写 SQL？
- 结构化数据和向量库的数据一致性怎么保证？（**这题很容易被问倒，提前想好**）
  **答（2026-09-15 已实现）**：先纠正前提——两边不是"要保持一致"，而是**同源、不同形态、
  单向可追溯**。同一份上传产出两条路：原文切块进向量库（知识库更贴原文，是原文的检索副本），
  AI 抽取的字段进结构化表（有损重建，形态完全不同）。"一致"靠三件事：① **可追溯**——每条
  抽取值带 `raw_text` 原文片段，且必须能在原文中找到（原文锚定校验，找不到判幻觉拒收）；
  ② **只写双方一致的项**——第二模型交叉验证后不一致的进待确认，绝不静默取一个；③
  **人工可覆盖**——修正后 `is_verified=1`，此时数据**故意**与原文不一致（原文可能印错、
  单位不同），人比原文权威。所以我的系统不承诺两边逐字一致，承诺的是"结构化数据里的每个值
  都能被原文证实，且能看出哪些还没被人工核实"。
- 怎么定位一次"模型答错了"的请求？LangSmith 里你看哪些字段？
  （注：2026-09-17 已删除 langsmith 依赖，可观测改走自研本地 Tracer + 审计表；若被追问就说
  "我评估过 LangSmith，自用场景下数据不出本机的本地 Tracer + 审计表更贴合隐私叙事"）
- 联网搜索你做在哪一层？怎么防止提示注入把搜索变成攻击面？
  **答（2026-09-17 已实现）**：联网是两个内核工具 `web_search` / `web_fetch`。三层防护：
  ① **总闸** `WEB_SEARCH_ENABLED=false` 两个工具一律返回可读的关闭说明；② **域名白名单**
  `WEB_ALLOWED_DOMAINS` 只管 `web_fetch` 的抓取目标（子域匹配，空=不限）；③ **SSRF 边界**
  `_host_is_public` 只允许公网 http/https，拒绝回环/私网，且**逐跳校验重定向**（P1-3 修过
  302 到 127.0.0.1 的绕过）。结果与正文都有字数截断、来源标注，工具只读（幂等不重试）。
  搜索后端 `web_search_backend=auto`：有 `TAVILY_API_KEY` 走云端，否则本地 ddgs（国内网络
  境外源会超时，这是已知限制，所以把 Tavily 云端通路搭好就绪）。人工校核可去 `.env` 注释。
- 运行环境配置你们怎么管理的？改配置要重启吗？
  **答（2026-09-17 已实现）**：分两类。**模型后端 / 服务引用**是数据库事实面的在线配置
  （模型页/服务页签，保存即热重建图）；**其余 env 配置**分可编辑/只读两半——可编辑子集
  （联网/OCR/检索/超时/思考）走「运行环境」页签保存即热生效（DB 覆盖 env，清空回落，校验
  失败整体拒绝不落半套）；只读项（认证/观测/路径）随进程构建，改了需要重启。刻意不开放
  全部在线编辑的原因：认证与观测属于进程构建期概念，在线改了也无法安全生效。
- 工具一直重试会不会烧钱？你做了哪些上限？
  **答**：`AGENT_MAX_STEPS=25`（LangGraph recursion_limit，默认是 10007，不设会无限循环）；
  工具执行 `TOOL_TIMEOUT_SECONDS` 兜底；重试只对显式声明 `idempotent=True` 的只读工具开放；
  回退链 ≤2。这三层把"模型抽风→数千次计费调用"的路径卡死了。
- consensus 多模型比对是什么？为什么做它？
  **答**：`compare_model_answers` 内核工具——把同一问题并行发给默认后端 + 回退链（≤3 去重），
  聚合出"一致 / 分歧 / 缺席"结论。初衷是给用户一个"多模型交叉确认靠不靠谱"的能力
  （与抽取的 LLM-as-verifier 同思路）；代价是 N 倍 token，所以显式声明非幂等、不重试。
