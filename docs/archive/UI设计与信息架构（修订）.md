## 二、缺口清单（按优先级）

### P0 · 功能缺失（"功能没做完"，用户明确要的）
1. **领域数据不能新增** —— 无 create 端点 + 无 UI 入口。当前只能上传文件或跑 seed 脚本。
   → 补 `POST /api/records/report`（新建报告 + 首行指标）与 `POST /api/records/index`（追加指标），
     数据页给「＋ 新增」。
2. **知识库无法在界面重建/清空作用域** —— `reset_scope` 未暴露。
   → 补 `DELETE /api/knowledge/{scope}`（写审计），知识库页给「重建」按钮 + 二次确认。
3. **角色 exemplars 未进表单** —— US-8 的「范例装配」能力后端已有、界面没有。
   → 角色表单加「范例（few-shot）」多行编辑（JSON 数组或分隔文本）。
4. **上传结果不反馈** —— 响应已有 `status`/`parsed`，前端只显示"已登记"，且文案还写着
   「解析在 v2.2 接入」（**已过时**）。用户根本不知道文件到底读没读进去。
   → 上传后按 `status` 显示三态：`indexed`（已入检索，含分块数）/ `pending`（未解析或 OCR 未配）/
     `已完成解析但无文本（扫描件）`。

### P1 · 信息架构与体验缺陷
5. **插件 / 数据 / 知识库三件事混在一个页签** —— 用户已明确吐槽。真正的问题是**"数据"没有自己的位置**。
6. 对话页快捷问题是写死的两条；空态引导只有一行灰字。
7. 工具调用回显是原始文本（`tool_result` 截断 120 字），无结构化展示（参数/结果/耗时）。
8. 状态提示统一塞在输入框上方一行 `status` 文本，无 toast/自动消失，多条会互相覆盖。
9. 无「停止生成」，长回答只能干等。

### P2 · 打磨与 v2.3 范围
10. **无响应式/移动端**：固定三栏（`w-52` 导航 + `w-64` 会话栏 + 主区），窄屏直接挤爆。
11. 无深色模式；无 skeleton/loading 占位；无错误边界（renders 出错白屏）。
12. 组件复用度低：按钮/卡片/表格/开关样式在 4 个页面各手写一遍 → v2.3「组件库」正是解这个。
13. 可访问性：仅开关有 `role="switch"`/`aria-checked`；其余交互元素缺 aria/键盘可达。

## 三、信息架构（IA）修订

**现状问题**：顶层只有 对话 / 角色卡 / 插件 / 设置。**「数据」与「知识库」都没有独立位置**——
数据被塞进插件详情，知识库被塞进设置。用户自然地困惑"插件页到底是 MCP 还是 RAG？数据归谁？"。

**建议 IA（把三件容易混淆的事拆成三个各自的位置）**：

```
对话          数据            知识库           角色卡        插件          设置
(会话/聊天)   (领域数据管理)   (RAG 库与检索)   (人设/权限)   (能力开关)   (系统)
             └ 按领域分组      ├ 作用域/来源     ├ 白名单      ├ 启停       ├ 通用
               health 域       ├ 分块/嵌入器     ├ 作用域      ├ 工具清单   ├ 模型
               ├ 报告列表      ├ 检索延迟        ├ 范例 ★新增   └ 如何新增   └ 审计
               ├ ＋新增 ★新增  ├ 上传入口
               ├ 修正/删除     └ 重建 ★新增
               └ 筛选/搜索
```

- **数据**：领域数据的唯一归属地，按域分组；未来新增领域插件自动出现一个分组。
- **知识库**：RAG 是**内核能力**，独立成页（含上传入口 + 检索延迟 + 重建），与插件彻底分开。
- **插件**：只做能力开关（领域插件启停 + 工具清单 + 如何新增），**不再含数据**。
- **设置**：只留 通用 / 模型 / 审计。

> 变化：从 4 个顶层页签 → 6 个；代价是导航变长，收益是**三个高频概念各归其位**，
> 直接消灭"插件页到底是啥"的困惑。

## 四、建议实施顺序

| 阶段 | 内容 | 理由 |
| --- | --- | --- |
| **S1 功能补全（P0）** | 数据新增（后端 + UI）· 知识库重建 · exemplars 入表单 · 上传结果三态反馈 | 用户要求"先把功能做完"；这 4 项是"能力缺一块"，不做完谈不上完整 |
| **S2 IA 重构（P1）** | 拆出「数据」「知识库」两个顶层页；插件页去数据化；审计加筛选 | 直接解决用户吐槽；纯前端改动，风险低 |
| **S3 体验打磨（P1/P2）** | 停止生成 · 工具调用结构化 · toast 化状态提示 · 空态引导 | 提升"友好度" |
| **S4 v2.3 工程化（P2）** | 抽组件库（Button/Card/Table/Switch/Tag）· 响应式（抽屉式导航）· 深色模式 | 原 v2.3 范围；S1~S3 的样式先手写，S4 统一收口 |

**建议**：S1 → S2 一起做（都直接回应用户两个诉求："功能做完" + "IA 别乱"），S3/S4 随后。

## 五、明确不做（沿用既有取舍）

- 多租户登录（v1 单用户演示）。
- 移动端**原生 App**：只做响应式 Web（v2.3）。
