# 设计对标：本项目的决策 ↔ 业界实践

> 生成日期：2026-09-15
> **诚实前提**：这份对照是**事后映射**，不是设计时逐仓照抄。设计过程依据的是三条——项目硬约束
> （本地优先 / 8GB 显存 / 可演示 / 时间紧）、通用工程原则（显式优于隐式、fail-closed、可插拔）、
> 以及业界成熟模式。所以下面每条的对应关系应理解为**"理念同源、做法简化"**，面试被追问
> "你读了哪个仓库的哪段代码"时要如实说：是模式对齐，不是代码级参考。
>
> 用法：面试被问"为什么这么设计"时，不要只说"我觉得这样好"，要说
> **"这是 X 模式的简化版，我因为 Y 约束砍掉了 Z"** —— 有对标、有取舍，才是工程判断。

## 一、内核与编排

| 本项目的设计 | 业界对应 | 判断 | 面试一句话 |
|---|---|---|---|
| 状态图 `model → (tools → model)*` + SQLite Checkpointer | **Temporal / Cadence** 的持久化工作流；LangGraph 本身受 Pregel 的 superstep 模型启发 | ✅ 对齐（简化版：无 signal / 无定时） | "会话状态落盘、进程重启可恢复，等价于持久化工作流的 event history，只是规模小两个数量级" |
| System prompt **每轮现场拼装、不入 checkpoint** | **Claude / OpenAI** 的 system 每请求传递；配置与状态分离 | ✅ 对齐 | "prompt 是配置不是状态——入历史会导致改了人设却对旧会话生效" |
| 无独立 guard 节点，审核在 `call_model` 内部 | **NeMo Guardrails / Guardrails AI** 的 output rail | ⚖️ 刻意取舍 | "独立节点意味着它是一条**边**，而边会被后来的重构绕过去；放在唯一跟模型说话的地方，是构造上保证" |
| 工具失败三分类 `offline / denied / failed` | **HTTP 语义分层** + 纵深防御 | ✅ 对齐且更细 | "插件停用 ≠ 角色无权 ≠ 执行出错，三者给用户的说法必须不同，否则排查全靠猜" |
| `tool_epoch` 版本号 + 漂移检测 | **乐观锁 / K8s resourceVersion** | ✅ 对齐 | "会话里记录的工具版本与当前不一致时上报一次，让"历史里的工具已下线"变成可解释事件" |

## 二、权限与多租户

| 本项目的设计 | 业界对应 | 判断 | 面试一句话 |
|---|---|---|---|
| 两阶段过滤：先按启用插件、再按角色白名单，最后 `bind_tools` | **K8s RBAC**（Role + RoleBinding 两级）、**AWS IAM** 的 policy 叠加 | ✅ 对齐 | "模型从来看不到它无权调用的工具——权限是可见性，不是调用时拒绝" |
| 知识作用域：**角色只声明、内核掌库**；未授权拒绝而非空结果 | **Weaviate multi-tenancy**、LlamaIndex 的 node filter | ✅ 对齐 | "若每个角色自带向量库就是 N×M 份索引，删漏一处永久残留；角色只声明，库归内核" |
| `switch_role` / 插件启停**不给模型** | 最小权限 + 防自我授权（**OWASP LLM Top 10** 的 excessive agency） | ✅ 对齐 | "让模型移动自己的权限边界等于自我授权，所以它是管理侧动作，不是工具" |
| `user_id` 列全表就位、但 v1 硬编码单用户 | 多租户 schema 预留 | ⚖️ v1 取舍 | "接真实登录是数据替换，不是改表——这是我刻意留的口" |

## 三、数据与一致性

| 本项目的设计 | 业界对应 | 判断 | 面试一句话 |
|---|---|---|---|
| 向量库（原文检索副本）+ 结构化表（有损重建）"同源不同形态、单向可追溯" | **CQRS 的读模型** | ✅ 对齐且表述更准 | "我承诺的不是两边逐字一致，而是：结构化里每个值都能被原文证实，且看得出哪些没人工核实" |
| 原文锚定 grounding（抽取值必须能在原文找到） | **RAGAS 的 faithfulness**、LlamaIndex CitationQueryEngine | ✅ 对齐 | "这一层挡掉的幻觉最多，且零成本" |
| 第二模型交叉验证（不同 provider 独立再抽一遍） | **Unstract 的 LLMChallenge**；LLM-as-verifier | ✅ 对齐 | "只有一个后端时降级为同模型复查，并**如实标注为弱校对**——假的安全感比不做更危险" |
| `file_hash` 幂等 + `ingestion_task` 状态机 | **Stripe idempotency key**；Saga + 补偿 | ✅ 对齐（简化） | "重复上传复用同一任务；解析失败会标记 failed，不会永远停在 pending" |
| 无 DB 迁移工具（改表要重建库） | **Alembic / Flyway** | ❌ 该补（v1 刻意） | "v1 不做迁移是刻意取舍，文档里写明了；生产要引 Alembic" |

## 四、模型接入与降级

| 本项目的设计 | 业界对应 | 判断 | 面试一句话 |
|---|---|---|---|
| 多 provider 同构（Ollama 与云端只差 base_url）+ 可插拔后端 | **LiteLLM / OpenRouter** 的 provider 抽象 | ✅ 对齐（自实现子集） | "本地模型和云端 API 在代码里是同一个 provider，部署形态只差一份配置" |
| 回退链 ≤ 2 | **Hystrix fallback** | ⚖️ 刻意比业界更保守 | "链越长越难定位，还会掩盖'降级后答案变差了'——所以硬性封顶 2" |
| 模型调用超时（2026-09-15 补齐） | 任何生产调用的标配 | ✅ 已补 | "没有超时时，挂起的本地模型让回退链永远触发不了——主模型既不返回也不失败" |
| 重排 / OCR / 工具失败一律降级 + 留痕 | **graceful degradation** | ✅ 对齐 | "增强类能力不能变成可用性故障；降级必须留痕，不然以为它一直在工作" |

## 五、安全与可观测

| 本项目的设计 | 业界对应 | 判断 | 面试一句话 |
|---|---|---|---|
| 双层防护：prompt 软约束 + guard 硬 gate，guard 自身异常也拦截 | **defense in depth**；OWASP LLM 的输入/输出双 rail | ✅ 对齐 | "提示词不是安全边界，它只是抬高成本；硬 gate 才是不变量，且 fail-closed" |
| 可观测门面（可切后端 + 默认脱敏 + tracer 永不抛异常） | **OpenTelemetry** 的 API/SDK 分离 | ✅ 对齐 | "观测挂了不能拖垮请求；脱敏放在 tracer 里而不是调用点——靠人记得调用，迟早漏一次" |
| 审计 `actor / action / target / detail` | **AWS CloudTrail** 事件模型 | ✅ 对齐（当前 actor 写死） | ⚠️ "actor 目前是硬编码 operator —— 接了认证才能写真实身份，这是已知缺口" |
| AI 抽取一律 `is_verified=0` + 标记拼进工具返回文本 | 医疗 AI 的 **human-in-the-loop**；数据溯源 | ✅ 对齐 | "手填也不等于已核实；标记必须拼在工具返回里，不能指望模型自己加" |

## 六、工程实践（超出常规的部分）

| 本项目的设计 | 业界对应 | 判断 | 面试一句话 |
|---|---|---|---|
| `check_consistency.py`——文档 ↔ 代码 23 项**机器校验** | **《Building Evolutionary Architectures》的 fitness function**；Java 侧对应 **ArchUnit** | ⭐ 超出常规 | "架构约束如果只写在文档里就会腐坏；我把它写成 CI 里的断言" |
| `core/` 内不出现 `health` 字样（机器校验分层） | 同上（架构适应度函数） | ⭐ 超出常规 | "分层不是目录命名，是可被断言的不变量" |
| 测试全离线、注入脚本化模型、**不测 LLM 本身** | 测试替身 / VCR 录制回放；**OpenAI Evals / RAGAS** 的评测思路 | ✅ 对齐 | "模型是外部依赖，'回答得好不好'用评测集度量，不写成单测——这个区分很多人搞反" |
| OCR 强制独立 venv / 子进程 | 进程级依赖隔离 | ✅ 对齐 | "paddle 的 numpy/onnxruntime 与 chromadb 的会打架，所以隔离在独立进程，且数据不出本机" |
| 依赖按范围拆 5 份 + `dependency parity` 断言 | Python extras 惯例 | ✅ 对齐 | "v1 内核不装 OCR 栈，否则第一天就拉进 paddle 全家桶" |

| 缺口 | 业界标配 | 何时必须补 |
