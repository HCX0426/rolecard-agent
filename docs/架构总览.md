## 1. 一句话定位与目标形态

**角色卡 = 人格 + 权限 + 工具 + 记忆的运行单元**；用户拥有"属于自己的角色"——它能接触
你的电脑（受控）、按事件主动找你、通过开放生态扩能，最终成为一个桌宠。这是区别于通用
对话助手（豆包等）的结构性差异点。

**目标形态：一套后端，双壳。**

| 壳 | 形态 | 能力边界 |
|---|---|---|
| **B/S** | 浏览器控制台（现状，已全功能） | 全功能，但无桌面驻留；主动开口只能"积压可查 + 轮询红点"（浏览器不给后台推送，如实降级；系统通知属 C/S 侧，接缝已做在壳那侧，见 §11.2） |
| **C/S** | 桌宠壳（里程碑 D，**Electron**；Tauri 骨架已撤下，理由见架构审计 §11.2） | 壳只负责三件事：**窗口**、**本地后端的进程生命周期**、**原生能力桥**（已落：托盘/置顶/透明窗/位置记忆/单实例/系统通知/开机自启/全局热键/原生目录对话框；桥面 **19 个方法**（2026-09-25 数正；原先写"九个"只算了桌宠那组）**只收会话 id、不收路径与命令**，且**没有通用 IPC 转发器**，见审计 §11.3）。界面**不在壳里再存一份** —— 窗口先落壳自带的本地着陆页，探活后跳后端托管的那份，两壳渲染同一个 dist |

单后端 = FastAPI + LangGraph 内核（`src/rolecard_agent/`）；前端 `frontend/`（React + TS）
构建产物 `dist` 由后端静态托管。两壳复用同一后端，桌面集成项仅在 C/S 生效。

### 1.1 「本地 / 云端」是两条互不相干的轴（问的人九成在问另一条）

| 轴 | 两档 | 在哪儿定 | 现在的真实状态 |
|---|---|---|---|
| **运行形态**：服务与数据在哪儿 | 纯本机（壳 + 随包后端，绑 127.0.0.1）↔ **公网部署**（服务器 + 浏览器访问） | `RUN_API_HOST` + `AUTH_MODE` + `Dockerfile` | 纯本机是**唯一真跑过**的那档；公网档**代码齐备但从未实跑**，欠的三件见 §4「尚未关闭」 |
| **模型后端**：这一次推理找谁算 | 本地 Ollama ↔ 云端 API（硅基流动等） | 设置→模型页（`model_provider` 一层一把 key + 失败回退链） | **两档都已实现**，而且本机现在对话默认走云端（库里 siliconflow 已配 key） |

两条轴可以任意组合：公网部署也可以全部用本地 Ollama，纯本机也可以全部用云端 API。
把"用云端模型"听成"部署到公网"（或反过来）是这条命名最常见的事故，所以写死在这里。

**"为什么没有登录页"也是这两条轴的混淆**。三个各自成立的事实叠在一起造成了这个观感：
① 现在跑的是 `AUTH_MODE=off`（`.env` 里没有 `AUTH_*` 项，单机零配置那一档）；
② 登录走 HTTP Basic 的**浏览器原生 401 弹框**，前端零代码，所以本来就不会长出"一个登录页"；
③ 认证判定里**本机来源永远放行**（`access.allowed` 第一条短路），所以即便开着 `on`，
从 127.0.0.1 进去也照样不需要凭据 —— 桌面壳与本机界面走的正是 127.0.0.1。
2026-09-25 实测（`AUTH_MODE=on` + 副本库起在本机 8124，不碰真库）：无凭据 `GET /api/sessions`
= **401 + `WWW-Authenticate: Basic`**、带使用者凭据 = 200、`/api/health` = 200（豁免）、
错 key = 401；非回环来源 + 使用者凭据打管理面 = **403**，同样来源换操作员凭据 = 放行。
**登录这条路径是通的**，它只是在这台机器上被故意关着。真正没做的是**数据不分**，见 §4.1。

## 2. 技术栈（当前）

**后端**（Python 3.13，`src/rolecard_agent/`）
- API：FastAPI + uvicorn；同步端点走线程池，对话 SSE 走专属线程池避免阻塞事件循环。
- 编排：LangGraph + LangChain（成对锁版本）；两节点循环（model↔tools）+ SQLite Checkpointer；`AGENT_MAX_STEPS` 上限防工具循环无界。
- 模型接入：`init_chat_model` 多后端同构（本地 Ollama + 任意 OpenAI 兼容云），回退链 ≤2，超时按客户端风格传参（本地后端 `base_url` 端点风格由 provider 决定）。
- 持久化：SQLite（WAL + FK + busy_timeout，`ThreadLocalConnection` 按线程分发 + 库代际防残留事务）；裸 sqlite3 + `.sql` schema，无 ORM，加列走幂等 `_migrate`。
- 向量检索：Chroma（一个作用域一个集合）+ 可插拔嵌入器（有 key 走 SiliconFlow bge-m3，无 key 走 hash 离线兜底）；索引身份 = 摄入任务 id（非文件名），删除连向量一起清。
- 文档摄取：pypdf + 标准库 zipfile/ElementTree（OOXML，禁 DOCTYPE 防 XXE/bomb）+ 可插拔 OCR（Paddle 在独立 venv 子进程，数据不出本机；云端 OCR 只能在「服务」页显式引用模型页的凭据行启用，绝不默认外发图片）。
- 配置：Pydantic v2 + 自研 `Settings.from_env`；`pyproject.toml` 单一依赖事实源，`requirements*.txt` 按范围拆分。
- 可观测：自研 Tracer 门面（JSON lines，键控脱敏 + 轮转）+ `audit_log` 表（只记路径/字节数/退出码，不记内容）。langsmith/langfuse 预留字段解析保留、依赖已删。
- 质量工具：pytest（**全离线**，LLM 注入脚本替身）+ 覆盖率阈值 85% · ruff · mypy · **自研 check_consistency**（文档↔代码断言）· 真机冒烟 `smoke_check.py`。

**前端**（`frontend/`，React 18 + TypeScript + Tailwind v4）
- Vite 构建 + `tsc --noEmit`；`dist` 有意入库（clone 后无 node 也能演示）。
- **自研 Hash 路由**（不用 react-router），6 页签全 `React.lazy` 分包。
- 深色模式（Tailwind v4 `@custom-variant dark`）+ 响应式（off-canvas 抽屉）；组件库 `components/ui/`。
- 测试：vitest（前端契约 + 组件行为，node 环境 mock fetch）。

**运行外部依赖**：Ollama（便携版）+ 本地多模态模型（一行多用：对话 + tools + 识图 + 思考）；
云端备用硅基流动；web_search 后端可选（Tavily key / ddgs / off）；反向图搜 `image_search`
可选（SauceNAO key，识别动漫/插画角色来源，未配 key 则该工具返回可读的未配置提示、不外发）。

## 3. 模块地图（后端模块 ↔ 功能，含到 C 的全部能力）

| 模块 | 职责 |
|---|---|
| `core/bootstrap.py` | **装配根**：建库/播种 → 服务实例化 → 知识库 + 注册表（由宿主注入的域接线）→ 图 → 热重建；`Runtime` 是可变量的**唯一持有者**，不起 HTTP 也能装配出可对话内核（C/S 复用，见 §7） |
| `core/identity.py` | v1 单用户演示身份的常量与播种（`DEFAULT_USER_ID` / `seed_demo_identity`）—— 内核概念，不归任何域、也不在 api 层重复定义 |
| `api/main.py` | **HTTP 壳**：绑定地址护栏、注入宿主侧域接线、`build_runtime(...)`、路由/中间件（库代际 + 认证）/静态托管/ASGI 生命周期 |
| `api/deps.py` | AppContext（`Runtime` 的读穿视图，端点写法不变）、get_context/get_actor 依赖、错误映射 |
| `api/auth.py` | Basic + X-API-Key 双凭证；三档 `AUTH_MODE`；`client_ip` 只认 TCP 对端（可信反代 CIDR）；fail-closed |
| `api/access.py` | **路由访问分级**（public / user / operator 一张清单，`api/main.py` 的认证中间件消费它）：**默认最严** —— 没在清单里表态的端点一律算操作员面，想让某条更宽松必须写一行。运行时收益是"`AUTH_EXEMPT_PATHS` 配宽了也拿不到管理端点"；清单本身是产品边界的说明书，也是下一步（角色）唯一的挂点。配对用例枚举运行时路由，**清单里写死一条就红** |
| `api/routers/` | 端点组：roles / sessions / records / domains / console / settings / services / **workspace** / **reachouts** / **approvals** / mcp / **local_service**（本地推理服务状态与显存释放，仅回环）/ **shell_release**（桌面壳安装包的托管下载：只报"有没有产物"，文件名由服务端列目录得到） |
| `api/chat.py` | **SSE 投送层**：`core/turn.py` 的事件帧成 Server-Sent Event（事件名取自事件类自带的 `sse_type`，无第二份清单）+ 专属有界线程池桥。`/api/prompt/enhance` 在 sessions 路由 |
| `core/turn.py` | **一轮对话的编排（宿主无关）**：跑图 → `Iterator[TurnEvent]`（Start/Thinking/Token/ToolCall/ToolResult/MessageReplace/ContextTrimmed/Error/End）。流式 fail-closed 审核（`StreamingGuard` + `WINDOW` 回扣）、已提交文本与已投送文本的对账、失败翻译成人话——**全在这里，不在 HTTP 层**。桌宠壳直接消费它，不必吃 SSE。另外它在**事件出口那一处**顺手维护「在飞正文登记」（`core/thread_locks.py`）：投送到哪儿就登记到哪儿，守卫扣住的那 `WINDOW` 个字符不进登记，一轮收手（成功 / 失败 / 被停 / 没人要了）就清 —— 另一个读者据此把「她正在说的那半句」镜像出来 —— 读它有两路：`GET /api/session/{tid}/turn` 只查这份登记（一次字典查找，**不做 `get_state`**，所以界面敢 0.8 秒问一次），`GET /api/session/{tid}/messages` 顺带带出同一个字段并给出 `total`（贵，兜住"已经落地的写入"）。两路是分工不是重复，理由与实测那 12 秒的账见架构审计 R26-38 |
| `core/graph.py` + `nodes.py` | 内核图、prompt 现拼、输出审核、工具三分类失败、历史裁剪（`CONTEXT_MAX_CHARS`，截断点不落 ToolMessage）、思考模型注入 |
| `core/guard.py` | 输出侧硬 gate（fail-closed，异常也拦）——安全第二层 |
| `core/text.py` | `text_of()`：消息 → 纯文本的**全项目唯一实现**（分块列表按空格连接，绝不产出 Python repr）。唯一性由 check_consistency 的 `single text extractor` 断言机器校验（P1-8）。配套 `core/markers.py`：【未经人工校验】/【AI 多模型比对·未经人工校验】标记常量（§5 第 5 条） |
| `core/plugins.py` + `tools/registry.py` | 插件启停（`tool_epoch`）、工具注册与两阶段过滤（bind_tools 阶段生效）、幂等重试开关 |
| `core/ingestion.py` | intake 台账（file_hash 幂等、状态机 pending→parsed→indexed/failed）、上传流式哈希 |
| `core/model_settings.py` / `runtime_settings.py` | 模型后端 CRUD（key 只写不回读）+ 热重建；运行环境在线覆盖（校验整体拒绝、空值回落 env） |
| `core/workspace.py` | **A** 任务目录解析与热切、受路径边界约束的只读树浏览（`resolve_task_dir`） |
| `core/reachout.py` | **B/C** 主动开口调度器：两级授权 + 三层抑制 + 关系驱动五类触发源（file_event/affection/time_pattern/recall/**open_thread**/timer，first-hit-wins）。⚠️ **"五类都在代码里"不等于"五类都轮得到"**：这条 `or` 链是排他的，而 `affinity` 每次成功开口 +0.2 且封顶 5.0（同一次开口还把衰减的钟归零）⇒ 触顶之后 `affection` 永久命中，后面三档一起读不到。09-25 修：`role_card.affinity_enabled` 补上第四把 per-role 开关（默认开 = 行为不变）、回忆档加 24 小时冷却（`role_proactive_state.recall_at`）、第五由头的素材从"她还没接住那截"改成"最近这一窗"（`proactive_recent_window`）。取证与实测读数见 [`架构审计（2026-09-26 轮）.md`](架构审计（2026-09-26 轮）.md) 的 `R26-23`/`R26-03`。+ 收件箱。**开口不只进收件箱**：宿主注入的 `deliver` 会把同一句落进"该角色的主动会话"（`proactive_thread_id(role_id)`，确定性 id），于是用户点得进历史、也能回话，角色下一次**对话**也看得到自己说过什么（注意：下一次**主动开口**过去是看不到的 —— 那是单轮无状态生成，直到加了下面①才两边都成立）。**生成时的上下文只有人设+记忆+任务指令**，所以两条口径写死在这里：① 带**该角色最近几条原文**并要求别重复（否则每次都是从零现编，实测连发几条同义话）；①′ 带**那条主动会话里还没了结的一截** —— 两刀互补、只看"最后说话的是谁"：最后说的是他 ⇒ "有几句你还没接"（`unanswered_lines`），是她 ⇒ "你说过这几句而他没回"（`unreplied_lines`，09-26 补的另一半，缺它她就会装作刚才那句不存在、转头另起话题）；② **记忆为空时指令不再提"长期记忆"**，recall 档整段换成"不假装记得往事"——指着一个空槽要它"提起以前答应的事"就是让模型捏造 |

### 4.1 规划中（2026-09-25 记下，未开工）：本地为底、登录换身份

用户描述的目标形态：**不登录就用本机那份数据；登录则把服务器上属于我的那份拉下来；退出登录后
本机那份再装载回来。**

把它写成可判定的形式，最关键的一条取舍是：**这是"换身份"，不是"做同步"。**

- 本机与云端各是**一份完整数据集**，界面同一时刻只呈现活动身份那一份。
- 双向同步要求冲突合并规则（同一句改述在两台机器上各改一次算谁的），成本比这条计划的收益高一个
  量级 —— 先不做。也**不要顺手做成**"每次写都发一份到服务器"：那会在第一个断网时刻变成静默丢数据，
  而那正是本项目最贵的一类故障（它改的不是缓存，是"她记得什么"）。
- 明确还开着的一半：**下行**（登录时取回）用户说清了；**上行**（什么时候把本机这份送上去、
  自动还是手动点一次）没说，属实现前必须拍的第一个决定。默认取最保守的那种：
  **只在界面上有一个"上传本机数据到账号"的显式按钮**，不自动上传。

**前置（硬依赖，不是可以并行的另一件事）**：`DEFAULT_USER_ID` 按 AST 只数**用法**是 **20 处**
（口径：`ast.Name` 的 Load 上下文，不含 5 处 import、也不含 1 处常量定义；旧版这里写"22 处"、
09-25 复算成"21 处" —— 那个 21 正是**把 `core/identity.py:17` 的定义那一行当成了用法**。
四个数现在一次算清并落在 `scripts/baseline.py` 的 `hardcoded_identity`：api 层按行 22｜整个
`src/` 按行 26｜api 层用法 18｜整个 `src/` 用法 20，见本轮台账 `R26-28` 与 `架构审计.md` §12.19）
—— `records.py` 10 / `domains.py` 4 / `sessions.py` 3 / `core/identity.py` 1（播种兜底，
本来就该是常量）/ `api/main.py:118` 那个 `current_user=lambda: DEFAULT_USER_ID` / `core/bootstrap.py` 1
（主动会话的归属）。这 20 处不改，登录后拿到的仍然是 `local-user` 那一份 —— 所以上表里
"[长期] 多人身份隔离"**就是这条计划的第一步**，不是它的替代品。

**但那 20 处不是主要成本，原先写在下面的那句"表结构一行都不用动"才是错的**：只有已经有
`user_id` 的四张表不用动（`session_thread` / `ingestion_task` / `domain_data` / `medical_report`，
它们的 19 条 `WHERE user_id = ?` 早就参数化好了，改起来是接一根线）。**09-27 把对面那一族数清了**：
本仓 SQL 声明的 21 张表里带 `user_id` 的只有那 4 张（另有 `app_user` 自己是主体、`tenant` 用
`tenant_id`），**其余 15 张一概没有归属维度** —— `role_card`、`role_memory`、`role_memory_item`、
`agent_reachout`、`role_proactive_state`、`plugin`、`kernel_meta`、`mcp_server`、`command_approval`、
`audit_log`（有 `actor` 一列，但它不是 `user_id`、join 不回 `app_user`）、`medical_index`
（只靠 `report_id` 挂在报告下面，身份是**间接**继承的）、`model_backend`、`model_provider`、
`service_endpoint`、`token_usage_day`，再加上 langgraph 的 `checkpoints` / `writes`。
对这一族，换身份要先补归属维度，那是**迁移**，不是接线。
（另一处"看着像有、其实没有"的过滤：`api/deps.py:49` 的 `get_thread` SELECT 了 `user_id`
却**不比对调用者**，任何 thread_id 都解析得开。）

**作用域要说清（这一条最容易漏）**：活动身份切换要盖住的不止 SQLite 行。一个身份的数据现在散在
`session_thread` / `role_memory*` / `role_card` / `agent_reachout` / `medical_*` / `token_usage_day`
**+ 检查点 `checkpoints`（LangGraph 的历史）+ 文件侧的 `UPLOAD_DIR` 与 chroma 目录**。
只切 SQLite 会得到"记忆没了、向量库还在"的半吊子状态 —— 那种状态比不切更糟，因为它看起来像数据损坏。

**2026-09-27 把这条改了一半**（用户：「key 就得跟着身份走呗」—— 形态定成"使用者接自己的
api key，我们这边不提供推理"）。原先的写法是：**刻意不按身份隔离** api_key、后端选择与失败
回退链、运行环境覆盖，理由是"那是设备级配置，登录不该让主人重填一遍 key"。现在切成两刀，
切法不是"配置 vs 数据"，而是**这次调用谁付钱**：

- **跟人走**：`model_provider`（api_key 与 base_url 就长在这一张表上），以及挂在它下面的
  `model_backend` 那份列表 —— 后者的归属**由 provider 推导**，不另加一列（两处真相早晚会
  各说一套）。换到一个从没填过 key 的身份就该让他填自己的：他要花的是自己的钱。
- **跟设备走**：这台机器有没有 Ollama（`local_service` 那一族探测）、运行环境覆盖、MCP 服务器
  配置、插件启停。这些问的是"这台机器能干什么"，换个人不会变。

原那句"登录不该让主人重填一遍 key"**仍然成立**，只是兑现方式换了：由"本机那份身份本来就带着
自己的 provider 行"来保证，而不是靠"所有人共用一把 key"。
安全前提顺手量过：api_key 在这套接口里**本来就是只写不读**（`api/routers/settings.py` 明写
"api_key 永不回明文 —— 只有掩码预览"，实现在 `model_settings.mask_key`）—— 所以"key 跟人走"
没有顺手开出一条读别人 key 的路；反过来，哪天要回显 key，必须**先按身份过滤再谈**。

**动手之前必须先拍的两件事**：
1. **服务器谁来运维。** 现有的分发决定是"使用者的笔记本永远不是公网服务器"（架构审计 §11.2），
   所以"服务器上那份数据"要么我们自己运维（成本 + 合规 + 谁负责备份与恢复），
   要么这条计划先只覆盖"我自己两个账号之间换"这一小块。
2. **健康档案与记忆上云要单独征求同意。** 2026-09-24 那条同意覆盖的是"云端**推理**可以读健康数据"，
   不等于"我们的服务器可以**留存**它"。在使用者那边这是两个问题，**不能拿一张同意书用两次**。

**第三件（09-27 补上去，用户问出来的）：「上行」撞上云端已有数据时是什么语义。**
本节原话是"界面上一个显式按钮把本机数据传到账号，不自动上传"——那说的是**什么时候传**，
没说**对面不是空库时怎么传**。而只要本机与云端各跑过一段，第二次上行就不是拷贝而是合并。
三条语义，代价各不相同（**尚未拍**，是实现前第一个要拍的；我推荐 B）：

- **A. 整份替换**：云端必须为空才推，非空就明写"会覆盖 N 条会话、M 条记忆"再二次确认。
  最省，但**会丢**——云端那侧的新条目直接没了。丢的是"她记得什么"，本项目最贵的一类故障。
- **B. 只追加（推荐）**：推"云端还没有的"，重复的**让它并存**，不做同义判定。
  不丢东西，代价是用户会看见两条相似记忆。这不是偷懒：09-24 的实测已经定过调 ——
  字面相似度不能安全地自动合并（Jaccard 0.43 会把"住在上海/住在苏州"并成一条），
  所以自动合并在技术上本来就不可信。B 只是把裁决权明确留给人和「整理记忆」按钮。
- **C. 真合并**：逐条冲突规则 + 界面裁决。就是本节上面否掉的那个"比收益高一个量级"的成本。

**不管选哪条，现在都得先埋两样**（否则以后只剩 A 能做，而 A 会丢数据）：

1. **`role_memory_item` 要有一个跨机器稳定的 `uid`。** 现在它的主键是本机 `AUTOINCREMENT`
   的整数 ⇒ 两台机器各自会**长出相同 id 的不同条目**，任何"追加/去重/重放"都会串成别人的。
   （09-27 已随 M2b 加上。）
2. **向量库不搬，只搬行。** chroma 里的向量是某个 embedding 后端算出来的，两台的后端一旦
   不同，向量之间不可比，合并出来的索引检索质量是随机的 —— 所以云端那份索引必须**重建**
   （现成的路：`KnowledgeBase.enforce_rebuild`）。顺带一条同族的键冲突事实：会话线程 id 是
   `s_<12 hex>`（uuid，天然可比），但**主动线程是 `s_proactive_<role_id>`**、`role_memory` 的桶
   也按 `role_id` 键 —— 内置卡两台机器同名，这些键会撞。这不是 bug，是"换身份=换一份完整
   数据集"的必然结果，但它决定了上行时哪些表能直接追加、哪些要 remap。

还有一条与 A/B/C 无关的前提：**健康档案与记忆上云要单独征求同意**（上面第 2 件），
不能拿"云端推理可以读健康数据"那张同意书用两次。
**09-27 开工，且上面第 1 件有了起步答案**：先**不买服务器** —— 拿本机起第二个后端实例
（独立数据根 + `RUN_API_PORT` + `AUTH_MODE=on`）当"云端"那一头。它是**脚手架不是上线形态**：
数据根分开就天然是本节说的"两份完整数据集，同一时刻只呈现活动那份"，所以 M1~M6 全都能真的
跑通并验；但它**验不到**公网攻击面、TLS、真实往返延迟，也验不到跨机器的物理隔离（同一台机器
就是同一个信任域，见 §1.1 与架构审计 §12.19 那条诚实边界）。分发决定"使用者的笔记本永远不是
公网服务器"没被这条松动 —— 它跑的是自己的两份数据。

  `app.state.ctx` —— 那是另一族"把请求级的东西放在进程级的对象上"的错法，同 §4.1 那条

  投递、图里的域工具）压根没有"这次请求"可问。所以先立**实例级身份**：`IDENTITY_USER_ID` →

  （两份完整数据集），所以"换身份 = 换一份数据集"**刻意不做成运行期可改项**：改了要重启，
  半换状态（界面是 A 的会话、后台调度替 B 冒话）比不换更糟。

## 5. 关键架构决策与不变式（历轮沉淀，改动前必读）

这些是被机器校验或反复强调的**硬约束**，不是风格偏好：

1. **`core/` 领域中性**：内核不得出现任何域的专有名词 —— 域目录名（health 等）**以及各域
   自己声明的表名**（`check_core_no_domain_token` 机器校验，表名从 `domains/*/schema.sql`
   推导，新增域自动跟上；注释与 SQL 注释一并算）。只盯 "health" 一个字的旧版曾放过
   `core/ingestion.py` 里一句 `UPDATE medical_report …`（架构审计报告 P1-1，已改为由域服务
   `create_report(ingestion_task_id=…)` 在插入时一起写）。
   用户/租户是内核概念（已从 `domains/health` 上移到 `core`）。
2. **权限三重过滤、bind 阶段生效**：白名单在 `bind_tools` 阶段裁剪，未授权工具对模型
   **完全不可见**（不是调用时拦截）；插件停用递增 `tool_epoch`，跨版本恢复会话回答"能力已下线"
   而非抛异常。
3. **guard fail-closed**：输出侧硬 gate，异常路径也拦；`switch_role` 等不得交 LLM 自主调用（防自我授权）。
4. **System Prompt 不落 messages 历史**；全局安全规则代码固化 + 后置。多模态轮次（本轮模型可见
   历史含图片）另注入「图像接地」段，排在人设/记忆/范例之后、安全规则之前：**事实以图为准，
   角色只负责解读不捏造**——先如实看清图（含逐字转录文字），人设决定「怎么看怎么讲」而非「图里
   有什么」，不认识的东西走 `web_search` 查证、查不到就承认不知道（防人设/检索资料盖过真实像素）。
   含图会话切到不支持视觉的模型时，由 `core/turn.py::model_error_detail` 翻成可操作提示（切回视觉模型 /
   新开不含图会话），不再吞成笼统的"模型调用失败"。
5. **AI 数据一律带【未经人工校验】标记**，标记拼进工具返回文本（不能让 LLM"记得说"）。
   常量在 `core/markers.py`（`UNVERIFIED_MARKER` 单条数据 / `AI_TEXT_MARKER` 整段模型产物），
   覆盖三处产出：域工具返回文本、AI 抽取写库的 provenance note、`compare_model_answers`
   的聚合结果（第一行）。
6. **审计只记路径/字节数/退出码，不记内容**；密钥只写不回读、永不出明文（运行环境视图掩码）。
7. **主动不绕过任何授权**：主动开口的动作与用户动作走同一套权限/审计/gate。
8. **per-role 隔离铁律**：主动开口的全部状态（触发配置/关系数值/回忆索引/校准/抑制）按
   `role_id` 隔离；记忆按角色取，回忆触发只查该角色自己的记忆；**唯一全局的是用户级护栏**
   （静默时段 / 未读堆积上限）。多角色 = 各自独立找用户聊，**角色间不互聊**。
9. **主动开口抑制与豁免**：三层抑制 = 间隔档（锚点是她**最后一次说话**，主动开口与在会话里
   回答都算，09-26）/ 静默时段（23:00–08:00）/ 未读堆积上限；
   `file_event` 触发**只豁免间隔档一次**，静默与未读是用户级护栏**不放松**。
10. **配置双源热切**：`Settings` 字段 + `from_env` 映射 + `RUNTIME_FIELDS` FieldSpec +
    settings runtime 视图组 + `.env.example` 契约五处必须同步（check_consistency 前缀元组含新
    env 前缀才放行）。运行环境在线改的字段保存即 `rebuild_runtime` 热生效。
    **例外：「用哪个 OCR / 嵌入 / 重排后端」不是配置项** —— 它只有「服务」页一个事实面
    （端点序 + 引用的模型页凭据）。这两族 env/在线开关曾存在过，但生产上从不被读
    （`seed_once` 恒播种一条启用的内置行 ⇒ 工厂里的 env 分支不可达），"改了没生效"的开关
    比没有开关更糟，已随架构审计报告 P1-5 收口删除。
11. **改数据契约走变更记录**：加列走幂等 `_migrate`；公开签名不破坏。**搬层/重建表允许**
    （2026-09-21 模型配置拆成 `model_provider` + `model_backend` 两层就是这一条），但要同时满足
    三件事：① 读侧形状不变（服务层用 JOIN/派生补齐被删的列，内核与消费方一行不改）；
    ② **搬完配置不许变小**（模型行、凭据、默认与回退顺序一个都不能少 —— 变多是可接受的
    宽松化，变少是丢用户的东西）；③ 拿本机演示库的**副本**跑一遍迁移并逐行对照，结果写进
    设计稿（不是"新库测过了"就算完）。旧列一律在迁移里删掉而不是"留着但不用"：一个没人读
    的列就是下一个假接缝。表/列名不改是默认姿势，不是禁令 —— 上面三条才是。
12. **模型能力标在后端、换模型对所有角色统一生效**：`model_backend` 带 `supports_vision`
    （能否收图）与 `supports_tools`（工具调用是否可用）。`call_model` 每轮按
    **当前模型**的能力自适应——`supports_tools=false` 就不绑工具（这条是**后端硬生效**）。
    ⚠️→✅ `supports_vision` 现在消费在两处：渲染徽标，以及**调用前拦截的一半证据**（P1-2
    已落地，2026-09-20）：只有"该行声明 false"**且**"Ollama `/api/show` 的 capabilities
    实测不含 vision"同时成立才拒这一轮，探测问不到 / 云端探不了 / 声明 true 一律放行，
    供应商 400 的翻译路径作为兜底保留。**仍然不** disabled 发图按钮 —— 判定只在一处（后端），
    界面复制一份就是第二个事实面。口径是用户选的"只拦确定的否"（误杀一个能看图的模型，
    比多花一次 400 往返严重）。文档以前写"决定发图按钮"是超前描述，已按现状收回。
    这样"切到某个云端 VLM"
    对任意角色都能用，不必为绕模型缺陷去建特殊角色（用户 2026-09-19：能力是模型的属性）。
13. **轮次事件名是跨语言线协议**：内核侧唯一声明处是 `core/turn.py` 的 `EVENT_TYPES`
    （每个事件类自带 `sse_type`，帧化直接读它，不存在第二份字符串清单），前端侧是
    `api.ts` 的 `ChatEvent` 联合。两者由 `tests/unit/test_frontend_contract.py` 做双向差分
    —— 改一边不会让另一边编译失败，症状只是"那一类东西从此不显示"。
14. **一轮对话的编排不属于 HTTP 层**：跑图、流式审核、文本对账、失败翻译全在 `core/turn.py`，
    投送方式（SSE / 桌宠原生事件 / 脚本直取）是宿主的事。
15. **记忆有上界，且退役不物理删**：每桶 active 条数有上限（超出即退役最弱的）、注入按字符预算
    **整条**截断（半条事实会被当完整事实用）；自动退役只写 `invalidated_at` / `superseded_by`
    （可撤销、可查、整理错了能回滚），**只有用户明确删除才物理删**。命中计数只涨在真进了
    prompt 的那几条上——它是退役排序里"频次"那一半的唯一来源，所以必须长在注入路径上。
16. **端点必须表态，默认最严**：`api/access.py` 那张清单是"哪些端点能影响主机"的唯一答案；
    没登记的路由自动按 operator 处理，想让某条**更宽松**必须写一行。配的用例枚举运行时路由，
    清单里出现死条目即红（降级悄悄失效比没降级更糟）。
17. **用哪台后端：会话 > 角色 > 全局优先级，而全局那份始终是兜底的那条链**。角色卡上的
    `model_name` 是"这个角色归谁接"，它赢过「服务」页那串顺序里的第一档；留空就是完全跟着
    全局走（解析器连名字都不点，由运行时按 `model_default` 定）。**但换 primary 不换池子**：
    角色挑了靠后那台时，降级链仍是 `[全局默认, *回退档]` 去掉它自己 —— 操作员排第一那台是
    最被信任的备胎，把它从链上抹掉等于"角色选了个冷门后端，连兜底都没了"（这条 09-25 之前
    就是那样错的）。用量账记的是**实际接话那台**（`Settings.backend_name`，声明的已被删掉
    就落回默认），不是角色卡上写的那台：记成 NULL 会让"没设置"那些轮次在按后端分组的页上
    凭空消失，而角色级选择用得越多，那个洞越像 bug。

## 6. 安全模型总纲（贯穿所有里程碑）

- **fail-closed 贯穿**：认证、guard、工具白名单、路径边界、审批默认（run_command 默认手动批准）。
- **端点按"能影响什么"分级**（`api/access.py`）：public / user / **operator**，**默认最严**——没在
  清单里表态的端点自动算操作员面。判定顺序是三条短路，2026-09-25 逐条量过（真值表见架构审计 §12.19）：
  **本机来源永远放行** → 已声明 `operator:` 凭据时只认操作员族 → 一条都没声明则整套分族休眠
  （否则"AUTH_MODE=on + 只有一条 `alice:pw`"的老配置会把主人锁在自己的设置页外）。
  第二条正是"我从 127.0.0.1 测不出分族"的原因，别把它当失效。`off` 档不启用分级（语义就是本机
  单人使用，且非回环绑定已被启动护栏拒绝）。用户自己日常用的（对话/会话/自己的数据/角色卡/
  记忆）都在 user，**不需要登录**。**默认最严**这半句是专门用来堵"`AUTH_EXEMPT_PATHS` 配宽了一点
  就让管理端点免凭据可达"的 —— 漏写一行是收紧而不是放开。
- **路径边界**：任务目录外读写一律拒绝（`_resolve_within`）；run_command cwd 必落任务目录内。
- **联网边界**：联网总闸 + 域名白名单 + web_fetch 逐跳 SSRF 校验；未配 key 不外发。
  `image_search`（SauceNAO 反向图搜）同受联网总闸管，未配 `SAUCENAO_API_KEY` 时返回可读提示、
  **绝不静默上传**用户图片（与云端 OCR 同一"图片外发需显式配置"义务）。
- **审批共用确认 UI**：命令审批（B/S 确认卡，C/S 系统弹窗）；批准一次跑 N 遍被结构禁止（回放）。
  **批准还要持有凭据**：每条待批由读侧下发一次性 `decide_token`（30 分钟过期、决定后清空），
  `decide` 缺 / 错 / 过期 = 403。它不是登录（单机形态本来就不登录），而是"这一条你确实看到过"
  —— 于是"猜自增 id 就批准"和浏览器里的跨源盲 POST 都不成立（读不到响应就拿不到令牌）。
- **不做 Agent 自扩权，但允许 operator 主动接入**：红线是"运行中的 LLM Agent 自己启用/安装
  能力"——绝不允许（启停/接入从不暴露为 LLM 工具，见 `domains/registry.py`）。**用户在设置里
  主动接入 MCP server 是合法的 operator 动作**：`/api/mcp/servers` CRUD（仅 http 传输；URL 由
  operator 主动填故本机/内网/公网均可——"仅公网"的 SSRF 边界只用于模型给的 URL，如 web_fetch；
  headers 只写不回读掩码；全程审计；启停热重载；**添加即自动测、连不上仍保存但标红**）。
  env `MCP_SERVERS` 与运行时 `mcp_server` 表并存合并（表覆盖同 id）。**MCP 是可选扩展层**
  （与 OCR/RAG 同层）：需 `pip install -r requirements-mcp.txt`，未装时接入/测试给可操作提示。
  插件同理：启停是 operator 动作，不做 LLM 自助安装。
- **数据保护**：LangSmith/云端可观测默认关闭；健康数据不外发除非显式配置。
