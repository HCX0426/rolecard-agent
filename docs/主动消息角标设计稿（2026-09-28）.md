## 1. 要解的问题：她"主动说的"和"在回答"长得一模一样

主动开口那句会落进 `s_proactive_<role>` 这条会话（09-19 那个决定），于是那条线里
**混着两种助手消息**：她主动冒出来的那句，和她回答你的话。`R26-40` 的修法
（`buildTurns` 走 `splitSegments`）已经让两种消息**在结构上分开**了 —— 主动那句自成一段、
`turn.user === null`，所以它那行小字里没有「耗时」（一小时后冒的话不会被算成"答了 62 分钟"），
也没有「重新生成」（没有可重跑的提问）。

但这两处差别是**减法**：用户看到的是"一段光秃秃的她的话 + 一个复制"，读不出
"这是她主动找我说的话"。而"她主动找我"恰恰是这个产品要卖的那件事 —— 它不该只能靠
"这行怎么少了两个字"来推断。

## 2. 一张图：今天

```
┌ 爱莉希雅 · 主动找你 ────────────────────────────────────────┐
│                                                              │
│  今天腰还酸吗？                                     13:33     │ ← 她主动说的
│  复制                                                        │
│                                                              │
│                                    ┌────────────────┐        │
│                                    │ 好多了，你呢    │ 13:35  │ ← 你回的
│                                    └────────────────┘        │
│                                                              │
│  那就好。我今天在阳台看到一只橘猫，趴在那儿晒了半小时  13:35  │ ← 她在答
│  耗时 3 秒  复制  重新生成                                    │
└──────────────────────────────────────────────────────────────┘
```

两段的**质感完全一样**（都是左侧正文），差别只在第三行的按钮多少。

## 3. 决策点：角标画成什么样（三选一）

**A · 小字行加一枚徽章**（推荐）

```
│  今天腰还酸吗？                                     13:33     │
│  [她主动说的]  复制                                          │
```

- 改一处：那行小字（`ChatPage.tsx` 里 `turn.answer` 的小字行）前面插一个 `<span>`。
- 不动布局、不动字号、不新增容器 —— 这一句本来一天也只出现几次，不该抢戏。
- 与已有的徽标语言一致（模型页的「视觉 / 工具」徽章、`ProcessPanel` 的小字）。

**B · 左侧一条竖线 + 极淡底色**

```
│  ┃ 今天腰还酸吗？                                   13:33     │
│  ┃  复制                                                     │
```

- 视觉上区分最强，但**与"她"的既有样式冲突**：她的回答是**没有气泡**的裸正文，
  加底色等于给她造了第二种容器形态 —— 而"气泡属于用户、裸文本属于她"是当前一眼可辨的约定。

**C · 上方独立一行说明**

```
│  爱莉希雅 · 主动找你                                         │
│  今天腰还酸吗？                                     13:33     │
```

- 最清楚，也最重：每段多一行，一段放着两三条这样的消息时会把对话撑得很散。
- 而且它会与**桌宠那条镜像提示**（「正在生成 · 不是这一扇窗发的」）形成第二种"顶部小字"，
  两种格式并存 = 下次想加第三种时没有先例可依。

**倾向 A**：文案短、改动最小、不引入新的容器语义。

## 4. 判据：哪一段算"她主动说的"

**`turn.user === null`** —— 就是 `buildTurns` 已经算出来的那个事实（`splitSegments` 切出来的
"没有用户消息跟着的那一段"）。**不新增字段、不问后端**。

为什么不问后端要一个 `is_proactive` 标记：那会给同一件事造第二个事实面。而这条判据的
**正确性边界**恰好已经论证过：

- 删除粒度是**整轮**（`expandSelection` 按 `groupTurns` 扩展），所以不会出现"提问被删掉、
  留下一条孤零零的回答"从而被误判成主动开口；
- 一条会话的**首条消息**若是助手（主动会话正是这样），`groupTurns` 会让它自成一轮 ⇒ 判据成立；
- 它同时是"耗时栏不出现"的判据 —— 一处判据管两件事，不会漂。

## 5. 决策点：桌宠那份面板跟不跟

| 选项 | 代价 | 说明 |
|---|---|---|
| **暂不跟**（推荐） | 桌宠那侧仍只有"她的话"，没有标签 | 桌宠面板画的是**原始消息列表**（没有"轮/段"的概念），要判"这条是不是主动说的"得另写一条判据（"上一条不是用户消息"）—— 那是一份与 `splitSegments` 平行、会各自漂的规则 |
| 跟（复用同一判据） | 多一处渲染 + 一条判据的两份实现 | 一致性更好；代价是上面那条 |

这一稿只做控制台。桌宠那侧若要做，**第一步应该是把"段"这个概念也搬过去**，而不是在那儿
另写一条"上一条是谁"的判据 —— 那属于 `R26-45` 记的"桌宠缺状态出口"那条已知尾巴。

## 6. 不做什么

- **不新增后端字段**（判据在前端已有）；
- **不改 `groupTurns` / `splitSegments`**（它们同时是删除粒度与耗时口径，改一处动三处）；
- **不给它做开关**（一个一天出现几次的徽章，开关的维护成本高于它本身的噪音）；
- **不动收件箱抽屉与桌宠气泡**（那是"她哪天找过我"的账，与"这句话是不是主动说的"不是同一件事）。
