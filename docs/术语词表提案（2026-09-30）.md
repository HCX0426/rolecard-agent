## 1 · 病灶一句话

三个词混指本身不是问题，**问题是其中一处把人指去一个改不到的页面**：关于页写着「修改默认后端
请前往「模型」页签」（`frontend/src/pages/SettingsPage.tsx:1116`），而"对话默认谁算、失败依次
回退谁"的真正写入口在**服务页签**（`src/rolecard_agent/api/routers/settings.py:197` 的注释自己
就写着「编辑入口已统一到「服务」页签」）。症状是"我照它说的改了，可对话还是没变"，而这恰好是
本项目最忌讳的那类**看起来有入口、其实是死按钮**。

其余的混指都属于"要多看一眼才懂"，不致命，但它们让每一句提示都必须写得比本来更长。

## 2 · 事实面只有三层（词表必须钉在这个上面，而不是钉在"读起来顺"上）

| 层 | 表与字段 | 唯一的写入口 | 现在界面上叫什么 |
|---|---|---|---|
| L1 凭据 | `model_provider`（id / provider / base_url / api_key）—— `core/schema.sql:258-269`，api_key 那列的注释就是"凭据唯一源" | 模型页签的抽屉 | 「厂商」「供应商」，偶尔被叫成"后端" |
| L2 模型行 | `model_backend`（name / provider_id / model / num_ctx / supports_* / 惩罚三档）—— `core/schema.sql:273-286`；**这张表上没有 api_key、没有 base_url、没有 provider、也没有 usage** | 模型页签 | 「后端」「模型」两词都压在这张表上 |
| L3 用途序 | `service_endpoint`（category = chat / ocr / embedding / rerank，ref_backend / sort_order / enabled）—— `core/schema.sql:412-423` | 服务页签（`PUT /api/services/{key}`，`ServicesPanel.tsx:115`） | 「服务」「优先级」；**「默认」和「回退链」的真正的家在这里** |
| L4 进程 | 那个 FastAPI 进程本身（随包后端 / 地址 / 端口） | 桌宠与设置页的状态格 | 「后端」「服务」—— **与前三个都不是同一层** |

L4 是这张表存在的真正理由：只要"后端"同时指"L2 那一行"和"这台机器上跑着的那个程序"，
任何一句带"后端"的提示都要读者自己猜是哪一层。

## 3 · 建议的词表（推荐档）

| 词 | 只指 | 从此不再指 |
|---|---|---|
| **模型** | L2 那一行（能被选来对话的那个东西） | 厂商、凭据、进程 |
| **厂商** | L1 那一组（一把 key + 端点） | 模型、后端 |
| **密钥** | L1.api_key | —— 只有模型页出现"编辑"，别处只出现"引用" |
| **优先级** | L3 的序 | —— 页面名保留「服务」，正文一律写"对话优先级 / 嵌入优先级" |
| **默认 / 依次回退** | L3 里 category=chat 的第 1 位 / 其后 | "模型页里那个默认徽章"（那只是 L3 的镜像） |
| **本机程序** | L4 | 「随包后端」「服务地址」这类既像 L2 又像 L3 的说法 |

一句判据可以用来自查：**一个句子里出现两个"后端"而它们不同层，就是没写完的句子。**

## 5 · 刻意不建议动的三处

1. **`.env.example` 的 `MODEL_BACKENDS`**：env 的形状本来就是一段 JSON 里带 key
   （`core/config.py` 里那段合并逻辑至今如此），和拆层后的库形状天然不同。改这个词会连带动契约名，
   收益只是"读起来一致"。做法：只在注释里加一句「这里的『后端』= 模型页那一行 + 它引用的厂商」。
2. **URL 段**：`/api/settings/models`（L2）与 `routers/services.py:140/154/568` 里那个
   `"key": "models"`（L3 的 chat 序）**同名不同表**。这条不是"词用得不好"，是两个资源共用了
   一个标识；改 URL 是破坏性的（外部脚本、桌面壳、文档链接都指着它）。做法：加注释点名，不改名。
3. **「通道」**：只出现在传输义（`frontend/src/api.ts:42`、`lib/stream.ts:150`、`lib/sync.ts:4`），
   没有冲突，不进取度表 —— 词表越长越没人遵守。

## 6 · 需要你拍的三件事

1. 第 3 节那张词表认不认，尤其**「服务」这个词要不要继续当页面名**（它同时也是 L3 的口语义）。
2. **L4 叫什么** —— 我推荐「本机程序」，备选「本地服务」「后台程序」。
3. **一次改十处，还是只改第 1 处 + 第 10 处文档订正**（其余按手感逐步收敛）。我的推荐是后者起手：
   第 1 处一行字就能消掉"改了没生效"这一类投诉的入口，而第 2-9 处要连着改前端按文案写的断言，
   值得单独一次提交慢慢核。
