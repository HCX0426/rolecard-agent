## 一、硬件评估

| 项目 | 实测值 | 最低要求 | 判定 |
| --- | --- | --- | --- |
| GPU 显存 | **8 GB**（RTX 5060 Laptop，7899 MiB 空闲） | ≥ 6 GB（Q4 量化 7B 模型） | ✅ **满足** |
| 内存 | **15.2 GB** | ≥ 8 GB（模型加载 + 系统 + 项目） | ✅ **满足** |
| CPU | AMD Ryzen 9 8945HX（16C/32T） | ≥ 4 核（CPU 推理兜底） | ✅ 富余 |
| 磁盘 C: | **141.9 GB 空闲** | ≥ 10 GB（Ollama + 模型文件） | ✅ 富余 |
| 操作系统 | Windows 11 | Windows 10+ | ✅ |
| Ollama | **已安装**（`qwen2.5vl:7b` 已拉取） | — | ✅ 完成 |

**结论：硬件完全满足部署条件，部署已完成。** 8GB 显存跑 Q4 量化的 7B 级多模态模型是甜点位。

> 8GB VRAM 的限制：模型权重（Q4 ~4.5GB）+ 视觉编码器（~1-2GB）+ KV cache（随对话长度增长）
> ≈ 6.5-7.5GB，刚好占满。**不能同时加载两个 7B 模型** —— 这正是默认模型选
> `qwen2.5vl:7b` 的原因：一个模型覆盖对话 / 抽取 / 图片直读，无需切换。

## 二、多模态模型推荐

| 模型 | Q4 体积 | VRAM 占用 | 中文 OCR | 文档理解 | 推荐度 |
| --- | --- | --- | --- | --- | --- |
| **qwen2.5vl:7b** | ~4.5 GB | ~6-7 GB | **最强** | **强**（图表/报告/Agent） | ⭐ **首选** |
| **minicpm-v** | ~3-4 GB | ~4-5 GB | 强 | 中 | ⭐ 备选（显存紧张时） |
| **gemma3:4b** | ~2.5 GB | ~3-4 GB | 中 | 中 | 备选（最轻量） |
| llama3.2-vision:11b | ~6-8 GB | ~8 GB（边缘） | 中 | 强 | ❌ 8GB 勉强，不推荐 |
| llava:7b | ~4.5 GB | ~5-6 GB | 弱 | 中 | ❌ 中文场景不推荐 |
| moondream | ~1.7 GB | ~2 GB | 弱 | 弱 | ❌ 太小，不适合报告 |

**推荐方案：`qwen2.5vl:7b`（Q4_K_M 量化）**

理由：
- **中文 OCR 最强**（健康报告全是中文，这是核心需求）
- **文档理解最好**（图表/表格/报告结构化理解）
- **与你现有的 qwen2.5:7b 同家族**——风格一致、切换自然
- Q4 量化后 ~4.5GB，8GB VRAM 剩余空间足够放视觉编码器 + KV cache
- Agent / 工具调用支持成熟（项目的抽取管线可直接对接）

## 三、部署步骤

```bash
# 1. 安装 Ollama（默认装到 C:\Users\<你>\AppData 或 D:\Software\Ollama）
irm https://ollama.com/install.ps1 | iex

# 2. 拉取多模态模型（~4.5GB，需等待下载）
ollama pull qwen2.5vl:7b

# 3. 验证
ollama list
ollama run qwen2.5vl:7b "你好"
```

模型文件默认存到 `C:\Users\<你>\.ollama\models`。如需改到 D 盘，安装前运行：
```cmd
OllamaSetup.exe /DIR=D:\Software\Ollama
```

## 五、注意事项

1. **单一模型常驻（已定的部署形态）**：默认模型就是 `qwen2.5vl:7b`，对话与抽取共用一个
   常驻模型，没有"切换模型挤出显存"的问题。若另行配置文本版 `qwen2.5:7b`，两个 7B 不能
   同时加载，Ollama 会自动卸载/加载（~2-5 秒切换开销）。
2. **端点风格由 provider 决定**：`provider=ollama` 的 `base_url` 不带 `/v1`
   （langchain-ollama 拼 `/api/chat`）；带 `/v1` 会得到 Ollama 的
   `404 page not found`（实测踩过，见 `技术评审与决策.md` §8.2）。
3. **嵌入器 key**：`SILICONFLOW_API_KEY` 留空时嵌入器走 hash 离线兜底（RAG 可用但语义
   相似度弱）；配了 key 走 bge-m3。`make_embedder` 会从 DB 后端配置兜底取 key。
4. **上下文长度**：Ollama 默认 4K 上下文。抽取时报告全文可能超过 4K，建议在
   Ollama Settings 里调到 16K。
5. **首次加载慢**：Q4 模型首次从磁盘加载到 GPU 需 5-15 秒，之后 Ollama 缓存加载 ~2 秒。
6. **抽取的模型切换与降级**：`EXTRACT_BACKEND=auto` 优先选本地 ollama（本地优先）。
   Ollama 没跑时如实降级：只有 DB 里的云端后端可用则自动切云端；都没有则返回
   502/`skipped=no_model`，**失败也写审计**（`extract_report_failed`）。
