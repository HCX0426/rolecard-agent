## 二、多模态模型选型结论（2026-09-17 修订）

| 模型 | Q4 体积 | VRAM 占用 | 工具调用 | 中文 OCR | 结论 |
| --- | --- | --- | --- | --- | --- |
| **qwen3-vl:8b**（ModelScope GGUF） | ~6 GB | ~7-8 GB | ✅ tools + thinking + vision 齐全 | **强**（报告/图表） | ⭐ **现用** |
| ~~qwen2.5vl:7b~~ | ~4.5 GB | ~6-7 GB | ❌ **官方 vl 模板不支持 tools**（bind_tools 400） | 强 | 已退役（2026-09-17） |
| gemma3:4b、llama3.2-vision:11b 等 | — | — | — | — | 备选/不推荐，见下 |

**为什么是 qwen3-vl:8b**：
- **工具调用可用**：这是对话主路径（档案管理员带工具）。qwen2.5vl:7b 官方模板的
  `bind_tools` 直接 400，曾是被评测抓出的部署级缺陷。
- **一行多用**：对话 + 识图 + 思考 + OCR 全由同一个常驻模型承担，"两个模型换载"问题不存在。
- **8GB 显存放得下**：Q4 量化 8B 略紧但仍可跑（Ollama 自动管理 KV cache）。

> ModelScope 导入说明：本项目的 qwen3-vl 不是 Ollama 官方库的混合版模板，而是从 ModelScope
> 仓库拉取 GGUF 导入（`ollama create` 自定义 Modelfile），故能同时具备
> chat + tools + vision 能力。直接用官方 `ollama pull qwen3-vl:8b` 可能拿到模板功能不完整的
> 版本 —— 这是 README 里反复提醒"见下方说明"的原因。

## 三、部署步骤（2026-09-17 修订）

```bash
# 1. Ollama 已装（D:\code\Ollama，便携版；服务需手动启动）
D:\code\Ollama\ollama.exe serve

# 2. 拉取/导入全能力 qwen3-vl（ModelScope GGUF → ollama create），模型名 qwen3-vl:8b
# 3. 验证
ollama list          # 应含 qwen3-vl:8b
ollama run qwen3-vl:8b "你好"   # 文本
```

模型文件默认存 `D:\code\Ollama\models`（`OLLAMA_MODELS` 指向，已写入本机环境）。

## 五、注意事项（2026-09-17 修订）

1. **单模型常驻（已定的部署形态）**：全项目只用一个 `qwen3-vl:8b` 后端行（对话 + OCR 共用）。
   模型页若有多个后端，按行各自可被引用；OCR 的 `_CAPABILITY_DEFAULT_MODEL["ocr"]=None`
   语义是"该类别无能力默认 → 引用时用后端自己的模型"（一行多用，2026-09-17 落地）。
2. **端点风格由 provider 决定**：`provider=ollama` 的 `base_url` 不带 `/v1`
   （langchain-ollama 拼 `/api/chat`）；带 `/v1` 会得到 Ollama 的 `404 page not found`
   （实测踩过，见 `archive/技术评审与决策.md` §8.2）。
3. **嵌入器 key**：`SILICONFLOW_API_KEY` 留空时嵌入器走 hash 离线兜底（RAG 可用但语义
   相似度弱）；配了 key 走 bge-m3。`make_embedder` 会从 DB 后端配置兜底取 key。
4. **思考模式**：`MODEL_THINKING_MODELS` 名单内模型以 `reasoning=True` 调用（**默认名单是
   空的**，qwen3-vl:8b 要自己写进去才看得见思考）；对不在名单的模型传 reasoning=True 会
   400（名单本身就是安全护栏）。**这一档只决定"看不看得见"，不决定"想不想"**：09-26 实测
   不列名时它照样想（一次回话 366~3809 token 而可见正文几十个字、首字 11.6~141 s），
   `think:false` 与提示里写 `/no_think` 都关不掉 —— 想省时间只能换非思考模型，
   想让她"看起来在打字"就把模型列进名单（拆账见 09-26 轮审计 `R26-29`）。
5. **上下文窗口**：`num_ctx` 可在线为每行后端配置六档（对话页「上下文」按钮），
   Ollama 默认常为 2048 tokens，比模型自带的 32k 小得多。**但"按需调大"在这台 8 GB 的机器上
   有实测上限**：09-26 把生成长度钉死只挪窗口，4096 档 17.2~17.9 tok/s、8192 档 15.5~20.4
   tok/s，而 8192 那一档 `/api/ps` 读到 `size 6.85 GB > size_vram 5.80 GB` —— 多出来的
   1 GB KV 已经在显存外了，**换不来速率**（拆账见 09-26 轮审计 `R26-29`）。
6. **首次加载慢**：Q8/Q4 模型首次从磁盘加载到 GPU 需 5-15 秒，之后 Ollama 缓存加载 ~2 秒。
7. **抽取的模型切换与降级**：`EXTRACT_BACKEND=auto` 优先选本地 ollama（本地优先）。
   Ollama 没跑时如实降级：只有 DB 里的云端后端可用则自动切云端；都没有则返回
   502/`skipped=no_model`，**失败也写审计**（`extract_report_failed`）。
