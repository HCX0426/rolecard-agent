# 开发流程（活文档 · 设计先行）

> 存在的理由（用户 2026-09-18：「没有先设计后端、再设计界面功能、再实现、最后后端对照前端吗？
> 有时候界面不合理还得我说」）：把"设计先行 + 实现后对照回写"固化成可执行的四步，让界面在
> **写码前**就摆出来，而不是事后补救。

---

## 一个功能/能力的标准四步

顺序不可颠倒：**后端设计 → 界面设计 → 实现 → 对照回写**。

### ① 后端设计（先定契约，不写码）
产出落到 `架构总览.md`（模块地图加/改一行）：
- **数据契约**：新增表/列？→ 列名不改、加列走幂等 `_migrate`（铁律，见架构总览 §5）；
- **接口契约**：端点路径、入参/返回字段、错误码（堆栈只进日志不进返回值）；
- **不变式**：这个能力受哪几条硬约束（fail-closed / 路径边界 / 权限三重过滤 / 审计只记路径不记内容 / per-role 隔离 / 配置双源热切五处同步…）。
- 若要加配置项：一次点齐 `Settings` 字段 + `from_env` + `RUNTIME_FIELDS` + settings runtime 视图组 + `.env.example`（check_consistency 会卡前缀）。

**出口**：契约与不变式白纸黑字，能对着它评审，不用猜。

### ② 界面设计（写码前把界面摆出来 —— 治"界面不合理得你说"的那一步）
产出落到 `前端设计.md` 的 **能力↔界面覆盖矩阵**，为该能力**先加一行**并写清：
- **落在哪个页签/面板**（对话/数据/知识库/角色卡/插件/设置/审批/主动）；
- **用户能看到什么、能操作什么**（只读？可编辑？有哪些控件？）；
- **状态**：加载中 / 空态 / 错误 / 成功反馈（toast 三态等）；
- **是否刻意不做 UI**（如 MCP：配置驱动、不给运行时自扩权入口）——"不做"也要在矩阵里写明理由。

**出口**：这一行 + 一句线框级描述（哪块区域、放什么）经确认，再进实现。避免"后端做完了才想界面长啥样"。

### ③ 实现
- 后端：按 ① 的契约写，配 **单元测试（全离线，LLM 注入脚本替身）**；guard/权限/fail-closed 不图省事绕过。
- 前端：按 ② 的矩阵行写；数据只从 `api.ts` 出；复用 `components/ui/`；深色/响应式跟基线。
- **小步跑快反馈**：改哪个模块就先只跑对应测试文件（≈2s）；提交前再走门禁（见下）。

### ④ 对照回写（实现完必须做，否则文档又过期）
- 把 `前端设计.md` 矩阵那行从"设计中"改成最终状态（✅ / ⚙️ / ⬜）；有后端↔前端分歧就**当场修或记进 §6 小缺口**；
- 更新 `架构总览.md`：模块地图、里程碑状态表（A–D / M 线）、关键决策/不变式（若引入新的）、待办清单；
- 触及需求/验收 → 同步 `需求与验收标准.md` 的用户故事与追溯矩阵；
- 改了 `.env`/字段 → 跑 `check_consistency`。

**出口**：设计文档描述与代码现状一致（文档可信是它不被跳过的前提）。

## 门禁：别每次都跑全量（慢在真机冒烟 + 覆盖率二跑）

| 场景 | 命令 | 约时 | 覆盖 |
|---|---|---|---|
| 迭代中小改（默认） | `python scripts/gate.py --fast` | ≈1.5 分钟（实测 83.8s） | ruff + mypy + 单测(-x) + 一致性 |
| 相关改动即时反馈 | `pytest tests/unit/test_<模块>.py` | ≈2 秒 | 单模块 |
| 提交 / 发布前 | `python scripts/gate.py` | ≈4 分钟（离线冒烟实测 10s）；跑真机 UI 段再 +≈10 分钟 | + 覆盖率≥85% + 前端 test/build + 冒烟 14 项 |
| 真模型验收（不进门禁） | `pytest -m live` 或 `scripts/run_eval.py` | 分钟级、随模型版本波动 | 真 8B 抽取 / 评测基线 |

> 计时口径（2026-09-19 实测校正，此前那组数字是 2026-09-18 的旧值）：单测占 fast 层 88%；
> **pytest-xdist 并行反而更慢**（各用例自起临时 chroma/sqlite，
> 建库开销吃掉并行收益）——别往并行优化，要快就只跑相关测试文件。
> 真模型/真机用例一律带 `live` 标记，`addopts` 里的 `-m 'not live'` 把它们整条挡在门禁外；
> 冒烟的浏览器那段用 `SMOKE_SKIP_UI=1` 显式跳过（提交前至少跑一次完整冒烟）。

## 提交

- **Conventional Commits**：`feat` / `fix` / `docs` / `test` / `refactor` / `chore`（scope 可选，如 `feat(reachout):`）。
- 一个可 bisect 的提交只做一件事：功能与它自己的测试/文档回写同提交；纯工具/环境修复独立提交。
- **不提交** `.env`、真实数据、任何密钥；演示数据全部虚构。
- 提交前工作区自查（`git status`），确认没有意外的敏感文件或无关大块改动混入。

---

## 一页速查

```
后端设计 → 界面设计(填矩阵) → 实现(+离线单测) → 对照回写(矩阵/总览/需求一致)
   ↑ 契约+不变式落到 架构总览   ↑ 可见/可控/状态落到 前端设计矩阵
gate.py --fast 日常 · 全量提交前 · 只跑相关测试文件求快
```
