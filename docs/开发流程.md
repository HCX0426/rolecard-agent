# 开发流程（活文档 · 设计先行）

> 存在的理由（用户 2026-09-18：「没有先设计后端、再设计界面功能、再实现、最后后端对照前端吗？
> 有时候界面不合理还得我说」）：把"设计先行 + 实现后对照回写"固化成可执行的四步，让界面在
> **写码前**就摆出来，而不是事后补救。

---

## 一个功能/能力的标准四步

顺序不可颠倒：**后端设计 → 界面设计 → 实现 → 对照回写**。

### ① 后端设计（先定契约，不写码）
产出落到 `架构总览.md`（模块地图加/改一行）：
- **数据契约**：新增表/列？→ 列名不改、加列走幂等 `_migrate`（铁律，见架构总览 §5）；
- **接口契约**：端点路径、入参/返回字段、错误码（堆栈只进日志不进返回值）；
- **不变式**：这个能力受哪几条硬约束（fail-closed / 路径边界 / 权限三重过滤 / 审计只记路径不记内容 / per-role 隔离 / 配置双源热切五处同步…）。
- 若要加配置项：一次点齐 `Settings` 字段 + `from_env` + `RUNTIME_FIELDS` + settings runtime 视图组 + `.env.example`（check_consistency 会卡前缀）。

**出口**：契约与不变式白纸黑字，能对着它评审，不用猜。

### ② 界面设计（写码前把界面摆出来 —— 治"界面不合理得你说"的那一步）
产出落到 `前端设计.md` 的 **能力↔界面覆盖矩阵**，为该能力**先加一行**并写清：
- **落在哪个页签/面板**（对话/数据/知识库/角色卡/插件/设置/审批/主动）；
- **用户能看到什么、能操作什么**（只读？可编辑？有哪些控件？）；
- **状态**：加载中 / 空态 / 错误 / 成功反馈（toast 三态等）；
- **是否刻意不做 UI**（如 MCP：配置驱动、不给运行时自扩权入口）——"不做"也要在矩阵里写明理由。

**出口**：这一行 + 一句线框级描述（哪块区域、放什么）经确认，再进实现。避免"后端做完了才想界面长啥样"。

### ③ 实现
- 后端：按 ① 的契约写，配 **单元测试（全离线，LLM 注入脚本替身）**；guard/权限/fail-closed 不图省事绕过。
- 前端：按 ② 的矩阵行写；数据只从 `api.ts` 出；复用 `components/ui/`；深色/响应式跟基线。
- **小步跑快反馈**：改哪个模块就先只跑对应测试文件（≈2s）；提交前再走门禁（见下）。

### ④ 对照回写（实现完必须做，否则文档又过期）
- 把 `前端设计.md` 矩阵那行从"设计中"改成最终状态（✅ / ⚙️ / ⬜）；有后端↔前端分歧就**当场修或记进 §6 小缺口**；
- 更新 `架构总览.md`：模块地图、里程碑状态表（A–D / M 线）、关键决策/不变式（若引入新的）、待办清单；
- 触及需求/验收 → 同步 `需求与验收标准.md` 的用户故事与追溯矩阵；
- 改了 `.env`/字段 → 跑 `check_consistency`。

**出口**：设计文档描述与代码现状一致（文档可信是它不被跳过的前提）。

## 门禁：别每次都跑全量（慢在真机冒烟 + 覆盖率二跑）

| 场景 | 命令 | 约时 | 覆盖 |
|---|---|---|---|
| 迭代中小改（默认） | `python scripts/gate.py --fast` | ≈1.5 分钟（实测 83.8s） | ruff + mypy + 单测(-x) + 一致性 |
| 相关改动即时反馈 | `pytest tests/unit/test_<模块>.py` | ≈2 秒 | 单模块 |
| 提交 / 发布前 | `python scripts/gate.py` | ≈4 分钟（离线冒烟实测 10s）；跑真机 UI 段再 +≈10 分钟 | + 覆盖率≥85% + 前端 test/build + 冒烟 14 项 |
| 真模型验收（不进门禁） | `pytest -m live` 或 `scripts/run_eval.py` | 分钟级、随模型版本波动 | 真 8B 抽取 / 评测基线 |

> 计时口径（2026-09-19 实测校正，此前那组数字是 2026-09-18 的旧值）：单测占 fast 层 88%；
> **pytest-xdist 并行反而更慢**（各用例自起临时 chroma/sqlite，
> 建库开销吃掉并行收益）——别往并行优化，要快就只跑相关测试文件。
> 真模型/真机用例一律带 `live` 标记，`addopts` 里的 `-m 'not live'` 把它们整条挡在门禁外；
> 冒烟的浏览器那段用 `SMOKE_SKIP_UI=1` 显式跳过（提交前至少跑一次完整冒烟）。

### 节奏：每项局部检查，每阶段一次全套（2026-09-19 定）

一轮整改里每项都跑一次全套，实测成本是 6×88s ≈ 9 分钟；而多数失败其实是秒级就能暴露的
（import 顺序、类型、某条测试的语义）。所以：

- **每个提交前**（局部，约 10s）：`ruff` + `mypy` + **只跑受影响的那几个测试文件**
  （`.venv\Scripts\python.exe -m pytest tests/unit/test_x.py tests/test_y_api.py`）。
  绿了才提交 —— 提交保持自洽可 bisect，见下一节。
- **每个大阶段结束时**（一次）：`gate.py --fast`。这一层负责抓到"局部检查看不见的跨项串扰"
  （改了配置契约影响别的模块、装配根挪了位置、检查器自身被改坏）。
- **补一次全量的判定条件**（满足任一）：删改公开 env 配置项 / API 形状、动前端渲染的数据面、
  改装配根或进程生命周期、发布/打 tag 前。否则阶段末的 `--fast` 就是终点。
- 阶段末失败时**按提交二分定位**，不要回头整片重改；也别把"每项一次全套"当成保险 ——
  重复的慢检查不等于更可靠，它只是让人不敢改。

## 桌宠壳（`shell/`，Electron）怎么跑（2026-09-20 起）

```
cd shell && npm install          # 首次要设 ELECTRON_MIRROR，否则二进制从 GitHub 拉常卡
npx electron/install.js          # 若上面只装了 wrapper 没下二进制（369 MB），补这一刀
npm run dev                      # = tsc + electron .；关桌宠窗用 ROLECARD_PET=0
```

壳侧的环境变量约定（与壳技术无关，都不是 Python 的 `Settings` 契约）：

| 变量 | 作用 | 缺省 |
|---|---|---|
| `ROLECARD_PYTHON` / `ROLECARD_API_SCRIPT` | 开发态用仓库 `.venv` + `scripts/run_api.py` 起后端 | 由仓库根推 |
| `ROLECARD_BACKEND_CMD` | 打包形态：整条后端启动命令（优先级最高） | 未设 |
| `ROLECARD_API_PORT` / `ROLECARD_BACKEND_URL` | 连哪个端口 / 控制台地址（壳必须把它**同时作为 `RUN_API_PORT` 传给子进程**，否则"后端起在 8000、壳在探 8011"这种谁都没错却连不上的事故会重演） | 127.0.0.1:8000 |
| `ROLECARD_PET` | `0` = 不开桌宠窗 | 开 |
| `ROLECARD_OLLAMA_BIN` | 壳起停本地推理服务时用哪个可执行文件（D③-b）。不设则按 `%LOCALAPPDATA%\Programs\Ollama` → `Program Files(x86)\Ollama` → PATH 依次找。**装在非默认位置又没进 PATH 的（本机就是 `D:\code\Ollama`）必须设这一项** | 自动发现 |
| `ROLECARD_OLLAMA_URL` | 壳判断"端口上有没有人在跑"的地址（只用来决定要不要再起一个；"在不在跑"由后端的 `/api/local-service` 说） | `http://127.0.0.1:11434` |
| `ROLECARD_PARENT_PID` | 后端看门狗：父进程没了就自杀（壳注入） | — |

**Electron 侧实测（两扇真窗 + 真进程）**：

- 透明成立：`transparent` + `backgroundColor:#00000000` + `hasShadow:false` 三者齐，截屏幕
  区域可证 IDE 内容从透明区透出。**按窗口截图永远看不出来**（不合成下层窗口）。
- 无边框拖拽**不再需要壳的能力**：`-webkit-app-region: drag` 由 Chromium 处理，后端托管的
  页面直接能用（Tauri 那边"远程源拿不到注入 → 拖不动"的坑在这里不存在）。
- 着陆页是 `file://` 页面，**自己跨源 fetch 后端只会拿到恒假信号** → 探活必须问主进程
  （`shell:backend-reachable`），端口与判据只有一处定义。
- 硬杀壳（`taskkill /F` 不带 `/T`）后，后端在 1 秒内消失，但**没打印看门狗日志** ——
  带走它的是 Chromium 侧的进程管理（作业对象），不是 `core/parent_watch.py`。看门狗作为
  第二道保险保留（打包形态或非 Chromium 壳就没有这层照顾），其机制由
  `tests/unit/test_parent_watch.py` 用真父子进程闭环证明。
- 验证进程一律用真实 Windows PID：git-bash 的 `$!` 是它自己的编号，杀不到东西。
- **关控制台 = 收起**（`close` 里 `preventDefault` + `hide`），唯一退出入口是托盘「退出」；
  单实例锁让"再跑一次 `npx electron .`"变成"把控制台带回前台"。这两条都可以不靠托盘验证：
  点 ✕ 后用 `list_windows` 看窗口消失而进程仍活，再起第二个实例看窗口回来。
- 窗口位置存在 `%APPDATA%\rolecard-shell\window-state.json`。**不用点桌面也能验全三段**：
  把这个文件手工写成越界坐标（如 `{"main":{"x":-5000,"y":-5000,…}}`）再启动 → 窗口被夹回
  当前工作区，且 `move` 事件会把夹完的位置写回文件 —— 还原、夹取、保存一次跑完。
- 桌宠那扇窗要 `page-title-updated` + `preventDefault`：不然着陆页/控制台的 `<title>` 会把它
  在窗口列表里也叫"控制台"，看窗口名字排查时会找错东西。
- **锁屏时合成输入进不去**（`foregroundStatus: blocked_before_pointer_input`，窗口也不会被
  置前）—— 那是环境问题不是拖拽坏了，让用户解锁再继续。

### 安装包怎么打（D②-4，2026-09-20 实测）

```
cd frontend && npm run build                      # ① 界面：dist 是后端静态托管的，必须先有
cd .. && .venv\Scripts\python.exe scripts\build_sidecar.py   # ② 后端 → build/sidecar/（≈2 分钟）
cd shell && npm run package:dir                   # ③ 解包版（不装进系统，用来验打包态）
cd shell && npm run package                       # ④ NSIS 安装包 → shell/release/
```

`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 对 ③④ 同样要设（builder 自己会去
下 electron 的 zip）。国内还要 `ELECTRON_BUILDER_BINARIES_MIRROR`（nsis / winCodeSign）。

实测数字（本机，2026-09-20）：随包后端 **219 MB**（onedir，含 chromadb/onnxruntime，不含
Paddle —— OCR 按设计不进包），解包版 **592 MB**，安装包见 §11.4。

**spec 里那一行 `sys.path.insert(0, "<repo>/src")` 不能删**：src-layout + 不 `pip install -e`
时 `rolecard_agent` 对打包进程不可导入，`collect_submodules` 会**安静地返回空**，产物起来
就报 `Could not import module "rolecard_agent.api.main"` —— 构建 exit 0、运行才炸。

**打包态数据落在哪**（`core/paths.py` 的两个根）：随包资源 `_MEIPASS`（含 `frontend/dist`），
用户数据 `%LOCALAPPDATA%\rolecard-agent`，`.env` 在 `%LOCALAPPDATA%\rolecard-agent.env`。
开发态一字不变（仓库 `data/`、仓库根 `.env`）。壳自己的状态与日志在 `%APPDATA%\rolecard-agent`
（`productName` 决定，dev 与打包同一份）。

**后端的日志现在有两个去处**：壳的终端（开发态看得见）+ `%APPDATA%\<app>\backend.log`
（每次启动覆盖）。打包态只有后者，而"进程归属"这类保证的判据就是日志里那一行 —— 没有
落盘日志，那条保证根本无法验证。

### 进程归属：两层各自实测过谁在兜（2026-09-20，打包态）

- **随包 exe + 真父进程死亡**（绕开壳单独测）：父 `os._exit` 后 ≤10 秒后端自己走，日志里
  确实出现 `[parent-watch] 父进程 NNN 已退出` —— 这一层是**我们的**，且**在冻结态成立**。
- **强杀打包壳主进程**（`taskkill /F` 不带 `/T`）：后端 4 秒内消失、端口释放，但
  `backend.log` 里**没有**那一行 —— 先动手的是 Electron 对子进程的管理（另外：壳一死，
  管道里没落盘的日志也会一起丢）。
- 结论：开发态与打包态都是"Electron 那层通常先兜住，我们那层是第二道且被单独证明过"。
  非 Electron 壳（或壳被整树 `taskkill /T /F`）时只剩我们那层，所以它不能删。

## 提交

- **Conventional Commits**：`feat` / `fix` / `docs` / `test` / `refactor` / `chore`（scope 可选，如 `feat(reachout):`）。
- 一个可 bisect 的提交只做一件事：功能与它自己的测试/文档回写同提交；纯工具/环境修复独立提交。
- **不提交** `.env`、真实数据、任何密钥；演示数据全部虚构。
- 提交前工作区自查（`git status`），确认没有意外的敏感文件或无关大块改动混入。

## 一页速查

```
后端设计 → 界面设计(填矩阵) → 实现(+离线单测) → 对照回写(矩阵/总览/需求一致)
   ↑ 契约+不变式落到 架构总览   ↑ 可见/可控/状态落到 前端设计矩阵
每项：ruff+mypy+相关测试文件(~10s) → 提交；每阶段：gate.py --fast 一次；
公开契约/前端数据面/装配根有变 → 阶段末再补一次全量
```
