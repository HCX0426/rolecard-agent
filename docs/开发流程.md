## 全景：一个功能的一生

```
想法 ─→ ① 需求行(US-x + 验收口径) ─→ ② 后端设计(契约/不变式→架构总览)
     ─→ ③ 界面设计(矩阵行→前端设计) ─→ ④ TODO(一条=一个可独立验证的行为)
     ─→ ⑤ 先写红测试 ─→ ⑥ 实现到绿 ─→ ⑦ 局部检查(≈2s)
     ─→ ⑧ 提交(Conventional Commits + dist 同提交) ─→ ⑨ 阶段末 gate --fast(≈84s)
     ─→ ⑩ push → CI 四臂并行(门禁/前端/镜像/Windows 分片×4)
     ─→ ⑪ 满足触发条件 → gate 全量(≈4min) ─→ ⑫ 打包链①②②′④ + 三层自证
     ─→ ⑬ bump 版本 → tag v* → Release(镜像 ghcr + 安装包)
     ─→ ⑭ 用户机上：双日志 / health / 自动更新(latest.yml)
     ─→ ⑮ 每晚：真机体检 + 评测；每周：锁刷新；常驻：Renovate / 审计 / 密钥扫描
     任何一环的发现 ─→ 回写文档与台账 ─→ 回到 ①
```

白话版：**先把要什么写成能验收的字，再把接口和界面在写码前摆出来，然后小步实现（测试先行、
改哪跑哪、每步秒级反馈），阶段末过一次快档门禁，push 后让 CI 四臂在云端复核；要发布时走
打包链、三层自证、打 tag 出 Release；装出去之后靠日志、health 和夜间体检知道它活得怎么样；
依赖、漏洞、文档一致性由机器人每周维护。** 全程任何环节发现的事实（bug、偏差、教训）都要
落回文档/台账 —— 这是四步流的第④步，也是本仓唯一不可跳的环节。

## 环境与常用命令

### 三层环境，各管一段

| 环境 | 用途 | Python | 何时需要 |
|---|---|---|---|
| `.venv` | 主服务（M1~M4 全部） | 3.13 | **现在** |
| `.venv-ocr` | RapidOCR 独立环境 | 3.13 | v2.2 |
| 容器 | 部署 | — | v2.4 |

**为什么 OCR 必须单独一个环境**：OCR 引擎会拉入 `opencv`（本机实测 113 MB）、`onnxruntime`
与一批二进制依赖，装进主环境会显著拖慢每次依赖解析，并让主服务的升级被它锁住。它本来就该是
独立进程。（2026-10-02 换后端时订正：从前这里写的是"`paddleocr` 会拉 `paddlex`…与主环境的
numpy 版本主张冲突"——那条**被迫**的理由在 RapidOCR 上已不成立。现行完整口径以
`requirements/requirements-ocr.txt` 开头那一段为准，别在两处各写一套。）

### 常用命令速查

| 场景 | 命令 |
|---|---|
| 装环境（一次性） | `python -m venv .venv` → `.venv\Scripts\python.exe -m pip install -U pip` → `.venv\Scripts\python.exe -m pip install -r requirements/requirements.lock` → `.venv\Scripts\python.exe scripts\init_db.py` → `git config core.hooksPath .githooks`（启用提交钩子） |
| 起后端（开发态） | `.venv\Scripts\python.exe scripts\run_api.py` |
| 起前端 | `cd frontend && npm run dev`（Vite 热更新） |
| 起壳（Electron） | `cd shell && npm run dev`（首次装依赖见下文壳那节） |
| 只跑某模块测试 | `.venv\Scripts\python.exe -m pytest tests/unit/test_xxx.py`（≈2s） |
| 快档门禁 | `.venv\Scripts\python.exe scripts\gate.py --fast` |
| 全量门禁 | `.venv\Scripts\python.exe scripts\gate.py` |
| 一致性单查 | `.venv\Scripts\python.exe scripts\check_consistency.py`（判据单独落盘读退出码，别与管道串联 —— `CONTRIBUTING.md` §2 有两次事故） |
| 打包 | 见下文「安装包怎么打」（四步链，顺序是硬依赖） |
| 发布 | 见下文「版本线与发布」 |

### 依赖的单一事实来源（镜像管"要什么"，锁管"装什么"）

- **`pyproject.toml` 是唯一事实来源**（`dependencies` + extras：`api` / `rag` / `cloud` / `dev`）。
  `requirements*.txt` 是 pip 安装镜像，按范围拆开（`-api` 接入层 / `-rag` 向量检索 / `-cloud`
  云端 provider / `-dev` 开发工具 / `-ocr` 独立环境）；`scripts/check_consistency.py` 断言
  extras 与镜像逐条一致。
- **锁文件**：`requirements/requirements.lock`（运行时五族 + dev，CI / README / 打包臂用）与
  `requirements/requirements-runtime.lock`（纯运行时，install.bat / Dockerfile 用）由
  pip-compile 从镜像产出。改了镜像**必须重新 compile** 刷新锁；刷新后若头部被本机 pip 配置
  写进 `--index-url`/`--trusted-host`，删掉再提交。锁与镜像的覆盖关系钉在
  `check_consistency.py` 的 `LOCK_SURFACES`。
- **安装器可以不同，锁必须同一把**（2026-10-10 拍板）：CI 四臂用 `uv pip install` 提速
  （本机对照实测冷装 pip 303.9s vs uv 27.8s，约 11×，包集零差异）；本地开发路径
  （README / install.bat / Dockerfile / 你自己的 `.venv`）仍用 pip。锁的契约是"pip 装得上"，
  安装器不是契约面。

### 数据库有迁移，别再写"删库重建"

现行机制两层（`R102-30` 起的口径，全文见 `CONTRIBUTING.md` §8.5）：

1. **列级迁移全部声明驱动**：`storage/db.py::reconcile_columns` 按 `core/schema.sql` 与
   `domains/*/schema.sql` 的声明补列（核心表与域表都覆盖），bootstrap 在跑 DDL 前后各调一次。
   加列通常**只改 schema 声明一处**，不用手写 ALTER。
2. `_migrate` 只管"补列器补不了"的形状迁移（整表重建与搬层各带前置 DROP 与显式事务）。
   仍然要三处一起改的只剩 `model_settings.py::migrate_to_provider_layers` 那份内联 DDL
   —— 分叉由断言 `shape migration DDL` 看住。"从老形状库跑 bootstrap 再比列集合"的测试在
   `tests/integration/test_legacy_schema_upgrade.py`。

### 国内网络与不要做的事

OCR 那一份会拉 `onnxruntime` 与 `opencv` 两个大轮子（合计 150 MB 级），直连 PyPI 慢到像卡死：

```powershell
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

- ❌ 不要把 OCR 依赖装进 `.venv`；❌ 不要把 `.venv` 当部署产物（部署走容器）；
- ❌ 不要在两处维护依赖清单；❌ 不要绕过锁安装（CI / 镜像 / 打包臂只从锁装）。

## 一个功能/能力的标准四步

顺序不可颠倒：**后端设计 → 界面设计 → 实现 → 对照回写**。

### ① 后端设计（先定契约，不写码）

产出落到 `docs/架构总览.md`（模块地图加/改一行）：

- **数据契约**：新增表/列？→ 列名不改、加列走幂等 `_migrate`（铁律，见架构总览 §5）；
- **接口契约**：端点路径、入参/返回字段、错误码（堆栈只进日志不进返回值；统一错误结构
  在 `CONTRIBUTING.md` §5）；
- **不变式**：这个能力受哪几条硬约束（fail-closed / 路径边界 / 权限三重过滤 / 审计只记路径
  不记内容 / per-role 隔离 / 配置双源热切五处同步…）。
- 若要加配置项：一次点齐 `Settings` 字段 + `from_env` + `RUNTIME_FIELDS` + settings runtime
  视图组 + `.env.example`（check_consistency 会卡前缀）。

**出口**：契约与不变式白纸黑字，能对着它评审，不用猜。

### ② 界面设计（写码前把界面摆出来）

产出落到 `docs/前端设计.md` 的**能力↔界面覆盖矩阵**，为该能力**先加一行**并写清：

- 落在哪个页签/面板；用户能看到什么、能操作什么（只读？可编辑？）；
- 四态：加载中 / 空态 / 错误 / 成功反馈；**是否刻意不做 UI**（"不做"也要写理由）。

**出口**：这一行 + 线框级描述经确认再进实现。

### ③ 实现（测试先行 + 小步快反馈）

- 后端按 ① 的契约写，配**单元测试（全离线，LLM 注入脚本替身）**；guard/权限/fail-closed
  不图省事绕过（铁律全文与 DoD 在 `CONTRIBUTING.md`，工作流四步在其 §2）。
- 前端按 ② 的矩阵行写；数据只从 api/ 出；复用组件库；深色/响应式跟基线。
- **编码内循环（分钟级）**：读目标文件 docstring（不变式在那）→ 先写/补测试（**在改动之前
  就是红的**）→ 实现到绿 → 只跑受影响测试文件（≈2s）→ ruff（顺手 autofix）→ 提交。
  铁律速览：不改公共签名；不动安全 prompt 与拼接顺序；不改表列名；不在 domains/ 定义
  user/tenant；不让 LLM 碰权限边界；堆栈只进日志；新依赖先改清单；不跨文件顺手重构；
  不提交密钥与真实数据；不删 TODO 却不实现。

### ④ 对照回写（实现完必须做，否则文档又过期）

- 矩阵那行改最终状态（✅ / ⚙️ / ⬜）；有后端↔前端分歧当场修或记进小缺口；
- 更新 `docs/架构总览.md`：模块地图、里程碑状态表、关键决策/不变式、待办清单；
- 触及需求/验收 → 同步 `docs/需求与验收标准.md` 的用户故事与追溯矩阵；
- 改了 `.env`/字段 → 跑 `check_consistency`；
- **扩任何一条尺子的受验面，两臂要在干净 worktree 里量一次**（`R28-47` 的教训：判据里混了
  gitignore 的东西，本机全绿、CI 红 10 处）。
- 设计稿搬 `docs/archive/` 的判据：结论已在某份活文档里有一份（台账例外：原地封存，`R26-19`）。

**出口**：设计文档与代码现状一致（文档可信是它不被跳过的前提）。

## 怎么加一个领域插件（开发者向）

1. 新建 `src/rolecard_agent/domains/<id>/` 包：`models.py` / `service.py` / `tools.py`，
   需要建表的再加 `schema.sql`；
2. 在包的 `__init__.py` 导出一份 `SPEC`（`DomainSpec`，含 `id` 与 `tool_factory`）——
   `DOMAINS` 由 `discover_specs()` 从目录自动派生（缺声明启动即报错）；
3. 重启服务：建表、插件行、工具注册自动完成；随包 schema 清单按目录现数，新域不必改 spec，
   但**要重打 sidecar** 才会进安装包；
4. 在角色卡页为需要的角色勾选新工具（白名单默认不含新工具）。

权限边界不变式：**不做界面动态安装**。RAG 检索是例外那一侧：内核能力，按角色作用域授权。

## 门禁：别每次都跑全量

| 场景 | 命令 | 约时 | 覆盖 |
|---|---|---|---|
| 迭代中小改（默认） | `python scripts/gate.py --fast` | ≈1.5 分钟（实测 83.8s） | ruff + mypy + 单测(-x) + 一致性 |
| **CI 每次 push/PR** | `python scripts/gate.py --ci` | ≈5.5 分钟（本机实测 320.5s） | 快层全部 + `baseline --check` + **依赖审计**（OSV 出网，新告警=红）；**覆盖率档不进 CI**（只在本机全量档与夜间臂）；跳过需要 node/浏览器/真机的步骤（各有专属 job） |
| 相关改动即时反馈 | `pytest tests/unit/test_<模块>.py` | ≈2 秒 | 单模块 |
| 提交 / 发布前 | `python scripts/gate.py` | ≈4 分钟（离线冒烟实测 10s） | + 覆盖率三档（覆盖率≥90% 全局；单文件地板与改动行门槛的数值住配置，见 pyproject）+ 前端 test/build + 冒烟 14 项 |
| 真模型验收（不进门禁） | `pytest -m live` 或 `scripts/tools/run_eval.py` | 分钟级、随模型波动 | 真 8B 抽取 / 评测基线 |

**红了怎么办**：看 gate 输出里红的那一步 → 红跑取证与偶发签名重试日志在 `build/` 下
（`scripts/pytest_with_evidence.py` 对已知 chroma 偶发自动重跑取证，屏幕标 FLAKY-RECORDED）
→ 修完只重跑该档。门禁读数分槽落盘（覆盖率家族进 `docs/gate-readings.json`，快档计数进
gitignore 的 scratch），**别把数字抄进散文**（README 有反向守卫断言）。

**节奏（2026-09-19 定）**：一轮整改里每项都跑全套，实测 6×88s ≈ 9 分钟纯浪费 —— 多数失败
秒级就能暴露。所以：**每个提交前**只跑局部（ruff + mypy + 受影响测试文件，≈10s）；**每个
大阶段末**跑一次 `--fast`（抓跨项串扰）；**全量只在**删改公开配置/API 形状、动前端数据面、
改装配根/进程生命周期、发布前跑。push 之后的 CI 是**异步门禁**：推完继续干活，不必等它。
阶段末失败按提交二分定位，不回头整片重改。pytest-xdist 在本机**反而更慢**（各用例自建临时
chroma/sqlite，建库开销吃掉并行收益）—— 要快就只跑相关文件（CI 的 Windows 分片是跨机并行，
不是 xdist）。

> 计时口径的完整注记（读数分槽、`-q` 累加的坑、runner 读数不回写等）原样住在
> `docs/gate-readings.json` 生成侧与 `scripts/gate.py` 注释里，此处不抄第二份。

### CI 四臂（`.github/workflows/ci.yml`，push main + PR 触发，并行）

| 臂 | 跑什么 | 守住什么 |
|---|---|---|
| 门禁 --ci | uv 装锁 → gate.py --ci（三层墙钟：步超时 / 进程内看门狗 / 外部 timeout，保证挂死必留红与日志） | 提交自洽：静态+单趟测试+一致性+审计+密钥扫描 |
| 前端 | 壳 typecheck + 升级清理判据 + `npm run build`（含 tsc）+ vitest；main 上 dist 漂移由 bot 自动重建回写，PR 上漂移=红 | 前端可构建、dist 与源码同步 |
| 镜像真跑 | docker build → compose 解析与必填变量护栏 → 裸容器拒绝启动 → 带鉴权起容器走真 API 往返（401/建会话/首页托管/存云端后端/非 root/HEALTHCHECK 真报 healthy） | 镜像这个交付物本身是活的 |
| Windows 分片×4 | 快档用例按路径哈希切 4 片跨机并行（`fail-fast: false` 保日志） | Windows 专属分支被机器接住 |

省时机制：`paths-ignore: docs/**` · concurrency 同 ref 只跑最新 · uv 装锁 · mypy 增量缓存 ·
手动档（full-gate 全量、windows-release 打安装包进 artifact）把最贵的检查放低频位。
CI 红了先看哪臂 → 哪步 → 该步日志末尾（多数步骤自带取证输出）；cancelled 的 job GitHub
不传日志，所以分片臂 fail-fast 关着。

## 桌宠壳（`shell/`，Electron）怎么跑

```
cd shell && npm install          # 首次要设 ELECTRON_MIRROR，否则二进制从 GitHub 拉常卡
npx electron/install.js          # 若上面只装了 wrapper 没下二进制（369 MB），补这一刀
npm run dev                      # = tsc + electron .；关桌宠窗用 ROLECARD_PET=0
```

壳侧环境变量（与壳技术无关，都不是 Python 的 `Settings` 契约）：

| 变量 | 作用 | 缺省 |
|---|---|---|
| `ROLECARD_PYTHON` / `ROLECARD_API_SCRIPT` | 开发态用仓库 `.venv` + `scripts/run_api.py` 起后端 | 由仓库根推 |
| `ROLECARD_BACKEND_CMD` | 打包形态：整条后端启动命令（优先级最高） | 未设 |
| `ROLECARD_API_PORT` / `ROLECARD_BACKEND_URL` | 连哪个端口 / 控制台地址（壳必须把它**同时作为 `RUN_API_PORT` 传给子进程**） | 127.0.0.1:8000 |
| `ROLECARD_PET` | `0` = 不开桌宠窗 | 开 |
| `ROLECARD_OLLAMA_BIN` / `ROLECARD_OLLAMA_URL` | 壳起停本地推理用哪个 exe / 判断端口上有没有人在跑 | 自动发现 / `http://127.0.0.1:11434` |
| `ROLECARD_PARENT_PID` | 后端看门狗：父进程没了就自杀（壳注入） | — |

实测要点：透明窗三件套（`transparent` + 透明底 + `hasShadow:false`）齐才成立，按窗口截图
看不出来（不合成下层窗口），要截屏幕区域；着陆页 `file://` 跨源 fetch 是恒假信号，探活必须
问主进程（`shell:backend-reachable`）；**关控制台 = 收起**（唯一退出入口是托盘「退出」），
单实例锁让再跑一次变成"带回前台"；窗口位置存 `%APPDATA%\rolecard-shell\window-state.json`，
手写越界坐标可验夹取三段；**锁屏时合成输入进不去**是环境问题不是拖拽坏了；**开机自启只在
打包态给**（dev 下会写一条指向依赖目录的假启动项）；全局热键 `Ctrl+Alt+R` = 唤起/收起；
原生目录对话框走 `pickDirectory()` 零参数（页面不给路径，不是"任意路径"的口子）。

## 安装包怎么打

```
cd frontend && npm run build                      # ① 界面：dist 是后端静态托管的，必须先有
cd .. && .venv\Scripts\python.exe scripts\build_sidecar.py   # ② 后端 → build/sidecar/（≈2 分钟）
.venv-ocr\Scripts\python.exe scripts\tools\build_ocr_worker.py  # ②′ 随包 OCR → build/ocrworker/
cd shell && npm run package:dir                   # ③ 解包版（不装进系统，用来验打包态）
cd shell && npm run package                       # ④ NSIS 安装包 → shell/release/
```

**这几步是"手工全跑一遍"的形状；`scripts/install_package.ps1` 实跑 ①②②′④**（差 ③：
`probe_package_artifact.py` 三层读的是 ③ 的产物，只跑脚本不打 ③，探针量的是上一包的解包物
—— 10-01 实测踩过）。`-SkipBuild` 只装现成那份（`build/sidecar` 缺席时 throw，不拿旧构建物
冒充新的）。

**② 吃 ① 的产物，吃进去就固化**：`frontend/dist` 被 PyInstaller 当数据收进随包后端 ——
改过任何前端文件，② 必须重跑，只重跑 ④ 会得到"构建成功、里面是旧界面"的包（09-29 被验货
哈希当场抓过：判据只看入口资源哈希，"构建退出码 0"从来不等于"产物是当前的"）。

**② 的两个守卫**：spec 里 `RUNTIME_PACKAGES` 逐条 `find_spec`，缺一族**拒绝出产物**（因为
`collect_submodules()` 对没装的包返回空列表且不报错 —— MCP 那两条曾被这样漏掉半年）；
`build_sidecar.py` 打包前把 git HEAD 与脏旗写进 `build/build_info.json`，spec 缺它拒绝出产物
—— `/api/health` 因此能自报 `build.sha`（脏旗带 pathspec，只问会进包的路径）。

**②′ 只能在 `.venv-ocr` 解释器里跑**：非该解释器直接拒绝出产物，打完还要过"渲染文字 →
认出来"的冒烟。打完一包必跑 `scripts\forensics\probe_package_artifact.py` 三层自证：
① 包内 dist 与仓库逐文件 sha256 → ② 包内后端 == 刚构建那份 → ③ 真起包内 exe 问
`/api/health` 的 build.sha 与 HEAD 对账（③ 才是"装的是哪一版"的答案）。

**打包机的解释器布局是硬前置**（10-02 实测）：conda 布局把原生件放 `Library\bin`、`DLLs\`
里一个都没有 —— ffi/sqlite3 一族**静默漏收**，构建 exit 0、起包才炸 `ImportError`。用
python.org 安装包或 uv 的 standalone CPython 就没这问题。spec 里 `sys.path.insert(0,
"<repo>/src")` 那行**不能删**：src 布局不 `pip install -e` 时 `collect_submodules` 会安静
返回空。

CI 有一条**手动触发**的发布链 job（ci.yml 勾 `build_windows`）：串 ①（用入库 dist）→ ② →
事后尺子 `check_bundle_parity.py` → 随包后端起一次答 health → ④ → 产物核对（点名
ocr-worker 与 backend 在包内 + latest.yml 在场）→ artifact。**它不装进 runner**：实装 +
起壳窗仍只在本机跑（`install_package.ps1` 六步：备份 → 关进程 → 静默装 → 两路哈希验货 →
起服务验健康 → 纯度尺子）。

### 静默安装与进程归属（实测要点）

- 静默安装只有一条命令能用：`powershell -NoProfile -Command "Start-Process -FilePath '<包路径>' -ArgumentList '/S' -Wait -PassThru"`。
  **别在 git-bash 里直接 `./包.exe /S`**：MSYS 把 `/S` 当 POSIX 路径转换掉，NSIS 弹出向导
  等人点（判据：进程的 `MainWindowTitle` 是"rolecard-agent 安装"）。静默模式下
  `runAfterFinish` 不生效，装完必须脚本自己启动。
- **别在 dev 服务还开着时验证安装包**：`Backend.ensure()` 是"端口有人应就直接连"（设计如此），
  装好的壳会安静连上 dev 后端 —— 看着"界面正常"，测的不是安装包。且**换后端=换库**：随包
  exe 读 `%LOCALAPPDATA%\rolecard-agent`，dev 读仓库 `data/`，来回"重启"会像删了数据。
  `install_package.ps1` 第 [5/6] 步自己会问"谁在答"（监听者 ExecutablePath 不在安装目录
  之下就 throw）。
- 卸载故意不动用户数据（对话/知识库/体检记录是要用户自己决定的事）。
- **进程归属两层**：Electron 的作业对象通常先兜住（壳死 4 秒内后端消失但日志无看门狗行）；
  `core/parent_watch.py` 是第二道且被单独证明过（父 `os._exit` 后 ≤10 秒后端自己走，冻结态
  成立）。验壳起停要给空端口且**两个 env 一起设**（`ROLECARD_OLLAMA_URL` 与 `OLLAMA_HOST`）。
- 后端日志两个去处：壳终端（开发态）+ `%APPDATA%\rolecard-agent\backend.log`（每次启动
  覆盖）；壳自己追加写 `shell.log`。"进程归属"这类保证的判据就是日志里那一行。

### P1b — 前端手写类型迁移（工具已就位，迁移暂缓）⬜

现状（2026-10-25）：后端契约自动化已完成（生成 + 接线 + 门禁漂移步），前端
`schema.gen.ts` 已由契约生成（typecheck 绿）。**手写类型迁移暂缓**，工具在
`frontend/scripts/check_handwritten_types.mjs`（按字段集匹配，保留前端原名）。

暂缓的原因：那 19 个可迁类型引出 **117 处 tsc 报错**，而 `npm run build` 含
`tsc --noEmit` ⇒ 挡住构建。117 处全是同一类：**"后端可能返回 null，而前端当必有"**
（生成类型是 `X | null`，手写是 `X`）—— 这是真实隐患，值得单独一批修，而不是混在
契约迁移里。

要做时：① 先修 117 处空值处理（每处一个 `?? 默认值` 或显式判空）；② 再跑
`node scripts/check_handwritten_types.mjs` 完成迁移；③ 迁移完**删掉被替换的手写
interface**（那才是"冗余清掉"）。未迁移的 40 余个手写类型要逐个看：生成物里没有对应
组件的（后端那些端点还没建模），先留在原地。
验收：`npm run build` 绿 + 前端类型与后端契约同源 + 手写 interface 数量显著下降。

### P3 — 测试套件本身提速（🟡 第一刀已落地 2026-10-25）🟡

"命令会失效"是机器能接住的那一半。
验收：登记的命令块被探针执行；故意改坏一条命令 → gate 红。

### 缓做 / 不做（有登记的取舍，不是遗漏）

| 项 | 判定 | 理由 |
|---|---|---|
| SBOM | 缓做 | 等真实分发诉求；pip-audit + 锁已覆盖大头。价值判断，非工作量 |
| Playwright 持续 E2E | 缓做 | smoke_check 14 项 + 截图冒烟已覆盖关键路径；某条用户路径反复手测时再自动化它 |
| branch protection 强制 | 不做 | 单人仓无强制对象；P12 的自审 PR 是自愿版 |
| staging 环境 | 不做 | 桌面应用结构性不适用（等价物：artifact → 本机验收 → Release） |
| 变异测试 | 不做 | 慢且只解决"审验证"问题的一半 |
| 实时监控/告警全托管（Prometheus/Sentry 类） | 缓做 | 需服务端；P2 是它在本产品形态下的最小可行等价物 |
