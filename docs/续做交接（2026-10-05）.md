- **设计落定**：`inline_generation: bool = False` 测试缝（True = 回旧的同步形状，存量用例
  全传它）；生成/投递重活 `_generate_and_deliver`；恒建单 worker `ThreadPoolExecutor` +
  per-role `_queued` 队位（**入队前记账**、`add_done_callback` 归还 —— 取消路径也触发）；
  `stop()` 用 `shutdown(wait=False, cancel_futures=True)`（排队中的取消、在跑的自己收尾）。
- **本轮实测过的坑**（复发概率高）：
  - 测试 `_drain` 若用 `cancel_futures=True` 会把**还没轮到**的那笔直接吞掉 —— 槽位不还、
    行不落，红得还看不出是谁的错。收口用 `wait_idle()` 再 `shutdown(wait=True)`。
  - 池线程 `record_reachout`（commit）与 `mark_delivered` 之间那一行**正落在补投查询的窗口里**，
    不跳就是同一句进会话两遍 —— 补投必须跳过 `_queued` 内的角色。
  - `check_changes` 对挂起事件是**原样再报**：上一批在飞时下一拍不跳过它，同一批素材会被
    刚醒的角色跨拍重播。
  - 收尾挂任务自身的 `finally` 挡不住"被取消的任务永不执行" —— 槽位归还只能挂 done 回调。
  - 0xC0000005（use-after-close）的根子是**把同一条 sqlite 连接喂进跨线程写的调度器**：
    池线程必须先收干净再交还 fixture（`wait_idle` + `shutdown(wait=True)`）。
- **改 scheduler.py 注意**：PowerShell 改写会把 LF 换成 CRLF，`consistency` 当场红 ——
  改完注意行尾（ruff/门禁会替你抓住）。

## 二、每一轮的固定节奏（2026-10-07 起的新节奏，照抄）

一个条目 = 一笔修复提交。**读数分槽后节奏从六步缩成四步**（原来第 3/4/5 步那一整串
"刷 head → 再跑一趟 → 读数收尾提交"是 head 归属判据的流水线，判据已随"数字移出散文"
退役 —— 快档根本不写入库槽，工作树跑完是干净的）：

1. **修 + 回归测试 + `gate.py --fast` 绿**，才许提交。入库那份
   `docs/gate-readings.json` 不会再被快档弄脏（分槽），但 `git add -- docs` 前仍要
   `git status` 核对 —— 混进别的东西照样是脏提交。
2. 更新两份账本：快照第五节该条 → ✅ + commit 哈希（放你这笔提交的**最终**哈希，
   amend 过就要用 amend 后的）；交接第四节同步状态。
   **代码注释/字符串里不许出现裸编号**（`P2-3` 这种写法）—— `audit citations` 尺子会红
   （dangling），改用语义措辞（"身份显式化那一格"）。
3. `gate.py --fast`（验证账本改动）→ 账本**单独一笔** docs 提交。
4. 末了跑一次 `scripts/check_consistency.py` 确认全绿 —— 这之后**不必**再跑 gate
   把 head 刷上来：head 住在 gitignore 的 scratch 里，跟提交没有归属关系了。

**动了用例数**什么都不用改 —— README 不抄数，scratch 里的读数下一趟绿跑自动刷新。
**只有全量档**（覆盖率步真跑，src 有改动时）会把入库那份的覆盖率家族刷出新值：
那时 `docs/gate-readings.json` **单独一笔** `chore(读数收尾)` 提交（说明改了哪些数），
随后再跑一趟 `check_consistency.py`（coverage threshold 尺子拿新读数复核阈值）。
