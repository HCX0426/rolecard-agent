## 二、每一轮的固定节奏（照抄，别省步骤）

一个条目 = 一笔修复提交，然后走完这六步：

1. **修 + 回归测试 + `gate.py --fast` 绿**，才许提交。`docs/gate-readings.json`
   **不要混进修复提交**（`git add -- docs` 会把它捎上 —— 提交前 `git status` 核对，
   不对就 `git restore --staged docs/gate-readings.json`）。
2. 更新两份账本：快照第五节该条 → ✅ + commit 哈希（放你这笔提交的**最终**哈希，
   amend 过就要用 amend 后的）；交接第四节同步状态。
   **代码注释/字符串里不许出现裸编号**（`P2-3` 这种写法）—— `audit citations` 尺子会红
   （dangling），改用语义措辞（"身份显式化那一格"）。
3. `gate.py --fast`（验证账本改动 + 刷新读数）→ 账本**单独一笔** docs 提交。
4. 再跑一趟 `gate.py --fast`（把 `readings.head` 刷到 docs 提交上）。
5. `docs/gate-readings.json` **单独一笔** `chore(读数收尾)` 提交（说明改了哪些数）。
6. 末了跑一次 `scripts/check_consistency.py` 确认 60+ 断言全绿 —— **不要再跑 gate**，
   会把刚刷的 head 又动掉。

**动了用例数**（±N）就在第 1 步同一提交里改 README 首屏那个数（否则第 3 步的
"README 数字收尾"当场红）；前端数与覆盖率由全量档（或快档的前端臂，见 P3-16 那格）刷新，
README 要跟着它们的读数走，不许手写一个新数。

## 四、实际踩过的坑（按复发概率排）

1. **读数/README 归属链**：head ≠ HEAD → 红；README 与读数不同步 → 红；读数混进
   非收尾提交 → 下一趟被覆盖 → 归属红。就是第二节那六步的由来，顺序不可换。
2. **裸编号 + 审计索引**：代码里的 `P2-x`/`Rxx-xx` 无对应档 → dangling；改了
   `架构总览.md` 要 `scripts/build_audit_index.py` 重建并**核对行数没变**（防"重建吸收坏
   token"的假绿）。
3. **改路径/搬家的两分法**：living 引用照改；historical（"从前/2026-10-0X 实测"）**保留
   旧名**并注"（后迁 X）" —— 把历史改成假话没有尺子会红。完整先例在 P2-19 第一刀与
   `4f35a8c`（sync 迁移）的提交说明里。
4. **先测量再动手**：临时探针 / AST 清单 / grep 现场量完再改，用完删干净
   （P2-3 量过 18 次 fallback 全是 by-design；P2-3 收拢前靠登记尺自证"未登记臂为空"）。
5. **测试计数与提交信息**：提交信息里引用的测试名、哈希要**贴实际**（amend 过的哈希、
   写错的函数名都发生过，发现即 amend）。
6. **别硬上的三件**（要么先拿口径，要么单独立项）：
   - P2-19 第二刀 `11434` 单源：`localhost` vs `127.0.0.1` 是**主机不同不是排版**，
     且 `shell/main/ollama.ts` 是跨语言独立事实面（尺子扫 .ts）；
   - 批次 3 的 P1-7/P1-9 与 P2-12 同一条路；P1-8 完整版 = v2.5「消息出 checkpoint」
     立项（2-3 周，单独带全量对减用例）—— 按快照批次 3 那行的依赖顺序走；
   - P2-1 的 Runtime ≤150 在"门面收掉 + Assembler"，core ≤30 要先解决"被两侧共用的
     主动开口零件"（`open_threads`/`anti_repeat`/`file_watch`/`proactive_state` 得先定形状）。
7. **门禁快档 >120s 会自动转后台**：等 job 输出（`job_output`）别空转；一轮里跑两三趟
   gate 是常态（第 3/4/5 步各一趟）。
8. **新尺子/新用例第一次红，先分辨"设计还是缺陷"再动判据**：升级演练第一版写
   "逐字节相等"当场红 —— 实弹量出的两处（列顺序：SQLite `ALTER ADD COLUMN` 只能追加；
   旧列遗留："升级不删列"是既定取向）都是**设计**，但修法不是放行：把边界写进代码
   （`LEGACY_EXTRA_COLUMNS` 点名名单，名单外的遗留列**同样红**），让"下次多出一种没被
   决定过的遗留"仍然抓得住。放行判据 = 把尺子拆了。
