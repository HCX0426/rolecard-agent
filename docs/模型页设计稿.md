# 模型页设计稿（界面优先 · 已拍板 A/B/C）

> 关联：`docs/模型接入设计稿.md`（结构与边界，含 §2.1 落地偏差）、`docs/前端设计.md` §3（页签）与
> "不可用控件三档"。这一稿只管**界面与交互**；结构（provider/model 两层、usage 派生）在那份稿的 §2。
> 规则：你点头后才动代码；每批单独提交，文档回写同提交。
> **A/B/C 已定（2026-09-20）**：A 分组卡片 / B 添加抽屉 / C 测视觉默认不勾选。
> 批次①（后端两层）已落地，见 §5 与 §6.1；界面这版是批次② 的施工依据。

## 0. 设计目标（按你说的"美观优先"落成可检查的四条）

1. **一屏能读懂"我有哪些凭据、每个凭据下有哪些模型、谁在用"** —— 现在的平铺 12 列表格做不到。
2. **添加模型是一条有反馈的流水线**：选供应商 → 选模型 → 测连 → 成功才进列表。不出现"存了个跑不通的行"。
3. **能力位是看得见的三态**，不是两个勾选框：能看/不能看/没测过，一眼区分，且"没测过"给出口。
4. **所有不可用状态都带一句"怎么恢复"**（走 `ui/Button` 的 `disabledHint`，见前端设计的三档口径）。

## 1. 布局（设置 → 模型）

```
┌ 本地推理服务 ──────────────────────────────────────────── 〔状态灯 · 地址〕
│ 在跑 · qwen3-vl:8b 5.4GB（常驻）      [预热/常驻] [释放显存]  [停止服务]
└──────────────────────────────────────────────────────────────────

 供应商与模型            〔+ 添加模型〕                     ⟳ 重新探测

┌ SiliconFlow ────────────────── api.siliconflow.cn/v1 · key 已存 ****2f ┐
│ ✓ DeepSeek-V4-Flash        [对话·默认] [工具 ✓] [视觉 ✗]      [⋯]      │
│ ✓ Qwen3-VL-30B-A3B         [对话] [视觉 ✓] [工具 ✗]           [⋋]      │
│ ─ 这个供应商还用于：嵌入、OCR                       〔在服务页调整〕    │
└──────────────────────────────────────────────────────────────────────────
┌ Ollama（本机）────────────── localhost:11434 ───────────────────────────┐
│ ✓ qwen3-vl:8b            [对话] [视觉 ✓] [工具 ✓] [未驻留·首条会慢]  [⋯] │
│ ⚠ bge-m3                 [嵌入] 未探测到能力：连不上该模型        [⋯]  │
└──────────────────────────────────────────────────────────────────────────
```

要点：
- **卡片按供应商分组**，组头一次性显示 base_url 与 key 状态（"已存 `****2f` / 未配置"）——
  凭据在一个地方出现，这是拆层的界面收益。
- 模型行左侧一个**状态 glyph**：`✓` 探测可用 / `⚠` 有问题 / `○` 未测。
- 徽章是**三态**：`视觉 ✓` / `视觉 ✗` / `视觉 ?`。`?` 可点，点开就是那张能力探测的确认卡（见 §3）。
- **默认**是 chip（`[对话·默认]`）而不是 radio 按钮，避免"模型页能改默认"的旧歧义；改默认仍只在服务页。
- 组尾那行"这个供应商还用于：嵌入、OCR"是**只读回显**（`used_by` 派生自服务页），
  附带一个跳转动作，不在这儿编辑 —— 用途只有一个事实面。
- `…` 菜单：编辑名称 / 重命名模型 / 复制凭据到…（不做）/ 删除。**删除走 useConfirm**（已收口的原语）。

### 视觉规格（与现有设计系统一致，不引入新色板）

| 元素 | 规格 |
|---|---|
| 卡片 | `ui/Card`（`p-5`，`rounded-xl`，`border-slate-200 dark:border-slate-700`），组间距 `space-y-4` |
| 组头 | `text-sm font-medium` + `text-[11px] text-slate-400` 的 base_url/key 摘要；左侧 3px 状态色条（正常 emerald / 异常 amber / 未配 slate） |
| 模型行 | 行高 40px 基准，`divide-y`；hover 只改底色 `hover:bg-slate-50 dark:hover:bg-slate-800/60`，不位移 |
| 徽章 | `rounded px-1.5 py-0.5 text-[10px]`；`✓` emerald、`✗` slate（不是红——"不能看"是事实不是错误）、`?` sky |
| 深色态 | 每个色一次 `dark:`，**禁止相邻双写**（§5 清理过的那条纪律，门禁的 doc-links 不管这个，靠 review） |
| 动效 | 只有两处：添加成功后新行 120ms `opacity/translate-y` 进场；探测中 glyph 用 `animate-pulse`。不做页面级动画 |
| 响应式 | <768px 时徽章换行到第二行、`…` 菜单保持右上；组头不折叠（信息密度优先） |

## 2. 添加模型（新增，替代现在的"手填一行"）

点〔+ 添加模型〕→ 右侧抽屉（`ui/Modal` 的变体，480px），三步同屏、自上而下：

1. **供应商**：下拉，来自 `GET /api/settings/model-providers`；已存在的供应商置顶并标"沿用已存 key"。
2. **模型**：可搜索 combobox，条目来自 `GET /api/settings/models/catalog?provider=X`
   （OpenAI 兼容读 `/v1/models`，Ollama 读 `/api/tags`）。**拉不到或列表里没有**→ 允许手填，
   并显示一句"该供应商不提供模型列表（常见于中转站），请确认名称准确"。
3. **Key**：只有该供应商没有 key 时才出现；出现时说明"只存本机、不回显"。

底部一个〔测试连接〕按钮，状态机：`idle → testing → ok / failed(原因)`。
**只有 `ok` 之后〔加入〕才可用**（禁用 + `disabledHint="先测试通过才能加入"`）。
测试失败时把后端的 detail 原样显示，不自己编文案（与本页既有惯例一致）。

> 为什么值得做这么重：现在"加完就热重建"，配错的行会让下一轮对话静默走回退链 —— 用户看到的是
> "它突然变笨了"，查不到原因。测连门禁把错误压在添加那一刻。

## 3. 能力探测（`视觉 ?` 点开的确认卡）

```
探测 Qwen/Qwen3-VL-30B-A3B 的能力？
  · 会向 SiliconFlow 发 2 次请求（1 次工具调用测试，1 次最小生成）→ 消耗配额
  · 测「视觉」需要上传一张 16×16 的测试图片（图片会离开本机）
  [取消]  [只测工具（不上传图片）]  [全部测试]
```

三件事必须写清楚：**花几次调用、发不发出图片、多久**。默认高亮在"只测工具"，
"全部测试"是明确第二选择 —— 图片外发是我们的红线，不该被一次点击顺带做掉。
结果写回该行的能力位并刷新徽章；探测失败 → 徽章仍是 `?`，行尾挂原因（沿用后端 detail）。

## 4. 状态清单（每种都要有确定表现）

| 状态 | 表现 |
|---|---|
| 加载中 | 骨架卡（3 行占位），不显示空态文案，避免"你以为没配" |
| 一个供应商都没有 | 空态卡：一句解释 + 〔添加模型〕主按钮 + 「本地 Ollama 免配置」次按钮 |
| 供应商没 key | 组头状态条转 amber，行内徽章全 `?`，添加按钮可用但测连必然失败（错误来自后端） |
| 该行被服务页引用 | 组尾 `used_by` 回显；删除时确认框点名"服务页的嵌入用途会因此失去该后端"（避免删完出现空引用） |
| 探测中 | glyph `animate-pulse` + 按钮禁用（`disabledHint="正在探测…"`） |
| 热重建失败 | 顶部 `ui/Notice` 红色条，写"配置已保存但生效失败：<detail>"，并提供〔重试〕——绝不静默 |

## 5. 契约与数据（界面之下的最小改动）

- `GET /api/settings/models` 返回 `providers: [{name, provider, base_url, has_key, key_masked, models:[…]}]`
  （旧字段 `backends` 保留一版，前端切完再删——两壳共用一个 dist，同版本内不跨形态）。
- 模型行新增只读 `used_by: string[]`（派生自 `service_endpoint` 的引用），**不再有可写的 `usage`**。
- 新端点：`POST /api/settings/models/catalog`（原稿写的 `GET …?provider=` 落地时改了 —— 拉列表
  要带 key，而 key 不进 query string）、`POST /api/settings/models/probe`（目标 + 是否测视觉），
  以及逐条增删改三个（见 §6.2）。
- 迁移：现有 3 行按 `(provider, base_url)` 归并出 2 个供应商；`name` 保持模型行的键，
  所以 `session_thread.model_name` 与角色卡的 `model_name` **不断链**（这是本次唯一不能破的兼容点）。

### 6.1 批次① 落地记录（2026-09-21）与批次②③ 的硬前置

已落地（后端两层 + 迁移 + 派生，界面一行未改，门禁全绿 + 真机往返验证）：

| 契约 | 现在的实现 |
|---|---|
| `GET /api/settings/models` | 同时给 `providers`（新形状：组 → 模型行，key 只在组头）与 `backends`（旧形状，`usage` 已是派生只读值）。旧界面照跑 |
| `PUT /api/settings/models` | **过渡写入口**：仍收旧形状（每行带 provider/base_url/api_key/usage），内部按端点归并成组；`usage='chat'` 翻译成 chat 引用行。批次② 换界面后随旧界面一起删 |
| 对话默认与回退 | 事实面 = `service_endpoint` 里 category='chat' 的引用序（第 1 位 = 默认）。`kernel_meta` 的 `model_default`/`model_fallbacks` 已删（迁移搬进引用顺序） |
| 服务页 `PUT /api/services/models` | 改为 `save_chat_pool(order)`：序列**就是**"哪些模型用于对话"的定义，候选是模型页全部行 —— 不再要求"先当 chat 才能进列表" |
| 能力位 | 三态列（NULL=没测过），`providers` 视图里是 `true/false/null`，`backends` 视图里仍折叠成 bool |

**批次②/③ 必须补上的一件事**（拆层暴露出来的，不做就是功能洞）：新界面不再选用途，
所以「服务」页的模型推理那一节要给一个**"把某个模型加入对话"的入口**（候选 = 全部模型行，
按供应商分组显示），否则一个刚添加的模型 `used_by` 永远是空 —— 它哪都不能去。
（①-b 已把这条路兜住一半：`add_model` 会把新行放进对话序列尾部，所以"加完就能聊"仍然成立；
反方向"把某行从对话里摘掉 / 把只服务嵌入的行加回对话"仍需批次③ 的入口。）

### 6.2 批次①-b 落地的端点（批次② 的界面照这张表接线）

| 端点 | 请求 | 出参 / 语义 |
|---|---|---|
| `POST /api/settings/models/catalog` | `{provider_id}` 或 `{provider, base_url?, api_key?}` | `{models, reachable, detail}`。**POST 不是 GET**：拉列表要带 key，而 key 绝不进 query string（会留在访问/代理日志与浏览器历史里）。拉不到也回 200，界面据此退回手填 |
| `POST /api/settings/models/probe` | 同上 + `model, test_tools=false, test_vision=false` | `{reachable, model_listed, tools, vision, vision_source, calls_used, models, detail}`。**纯测量不落库**；两个 flag 对应确认卡的两个按钮（§3），`calls_used`/`vision_source` 就是卡片上那句"花几次调用、发不发图片"的数据源 |
| `POST /api/settings/models` | `{provider_id \| provider+base_url+api_key, model, name?, num_ctx?, supports_vision?, supports_tools?}` → 201 | 加**一行**（组不存在就顺手建）。`name` 缺省由 (供应商, 模型名) 生成、撞车加后缀。返回同一份读形状 + `added` |
| `DELETE /api/settings/models/{name}` → 204 | — | 删一行；组里没别的模型就连凭据一起删；删的是对话默认则下一位自动顶上。其他类别的引用行保持原样并呈现「失效」 |
| `PATCH /api/settings/models/{name}/capabilities` | `{supports_vision?, supports_tools?}`（值可为 `null`） | 写回探测结论。**只有出现在请求里的键才写**，`null` 是"这一项没测过"（→ 界面 `?`），不是"不支持" |

三条接线纪律：探测/添加都**不需要**在前端持有 key（给 `provider_id` 即可，凭据由服务端从组里取，
从不在网络上往返）；`test_vision` 的确认卡必须先把"图片会离开本机"写出来才允许点；
错误文案一律原样显示后端 `detail`，界面不自己编。

`GET /api/settings/models/catalog` 落地时会改成 **POST**（批次①-b）：拉模型列表要给 key，
而 key 绝不进 query string（会被访问日志与代理日志留下来）。

## 7. 要你拍的三点

- **A. 分组卡片 vs 手风琴**：我推荐分组卡片（全部展开、一屏读完）；手风琴更省高度但"谁可用"要点开才知道。
- **B. 添加流程是抽屉还是行内展开**：我推荐抽屉（三步有地方放状态与错误）；行内更轻但容易挤。
- **C. 测视觉默认不勾选**（要显式点"全部测试"才上传图片）：我强烈建议保持这个默认；
  如果你更省事、希望"一次探测全测完"，我就把默认改成全部、只保留一句提示。
